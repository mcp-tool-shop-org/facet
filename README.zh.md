该风格应用于**资源**，在纹理空间中——而不是针对每个视角进行绘制，然后将它们组合在一起。将一个具有夸张外形的粘土概念模型输入到流程中，它会返回一个纹理网格，该网格的颜色来自对*该*网格的风格化参考，所有参考无法看到的部分都将通过蒙版绘制和表面感知的膨胀来填充。

名称既指问题的一半，也指多边形，以及它们需要呈现的表面。

## 安装

该流程本身是一组本地脚本，您可以在输入路径时调用它们——克隆仓库并阅读[入门指南](https://mcp-tool-shop-org.github.io/facet/handbook/getting-started/)。

**两个服务器以软件包的形式提供**——记录索引，因此助手可以查询证据链，而不是读取它，以及**从 v0.4.0 版本开始，测量服务器**，因此两个相隔几个月测量的资源将通过一个代码路径进行处理。

```bash
npx @mcptoolshop/facet               # the record index; zero-prerequisite, no Python needed
pip install facet-mcp[measure-full]  # + the measurement tools and their instruments
```

`facet-mcp` 是针对记录的标准输入/输出 MCP 服务器（六个工具，其中四足验证工具是一个拒绝的健康表面），而 `facet-index` 是索引本身（`build` / `verify` / `q` / `claims`）。从检出目录内部运行其中一个；`--db` 指的是不同的索引。

### 测量服务器——v0.4.0 版本的新功能

`facet-measure` 回答了比较的**数值部分**，并且不会说明输出是否良好。每个有效负载都包含服务器版本、仪器的文件哈希值和一个配置哈希值，并且 `measure_report` **拒绝**跨不匹配进行比较——这是整个系统存在的目的。

通过运行一个**动词**而不是 `--help` 来进行验证——一个控制网格返回 786,432 个面，并在没有检出目录的机器上具有完整的身份包围。

**您获得的结果取决于一件事，那就是您的 Python 版本：**

| 您的 Python | `[measure-full]` 提供了 |
|---|---|
| **3.11 / 3.12** | **所有八个工具**——`open3d` 从 PyPI 安装 |
| **3.13** | 四个工具；`mesh_stats`、`mesh_topology`、`measure_report`、`anchor_check` |

`open3d` 0.19.0 是最新的*发布*版本，并发布了 cp38–cp312 轮子，**不包含 sdist**，因此在 3.13 上，PyPI 上没有任何内容可以安装。额外的文件将其包含在 `python_version < "3.13"` 之后，因此安装**成功**，并且四个几何工具会输出**`4` REFUSED**，表明它们需要什么——而不是整个安装失败。

**要在 Python 3.13 上获得所有八个工具**，Open3D 在其滚动开发通道上发布了当前的 cp313 轮子。在命令行中使用直接 URL 即可；它只是在已发布的软件包元数据中被禁止：

```bash
# Linux — stable filename, no build hash
pip install https://github.com/isl-org/Open3D/releases/download/main-devel/open3d-0.19.0-cp313-cp313-manylinux_2_35_x86_64.whl
```

⚠ **在 Windows 和 macOS 上，开发轮子的后缀是 `+<sha>`**（在撰写本文时为 `open3d-0.19.0+63e30be-cp313-cp313-win_amd64.whl`），并且名称会随着 `main` 的变化而变化——列出 [`main-devel` 发布](https://github.com/isl-org/Open3D/releases/tag/main-devel) 中的资源，并选择当前版本。**此构建是此流程的 open3d 依赖项所使用的数字进行测量的依据**，并且它是一个真正的可比性边界：身份包围记录了仪器的哈希值，而不是其依赖项——[E31](docs/experiments/E31-ruling.md)。

*在 v0.3.1 之前，该轮子包含两个 `.py` 文件，不包含任何测量仪器，因此安装的测量服务器没有任何内容可以调用。没有人注意到这一点，因为这个仓库就是检出目录：该工具在构建的地方工作，并且从未在其他地方使用过。*

⚠ **`pip install facet-mcp` 在每个已发布版本中都存在问题，直到 v0.3.0，并且在 v0.3.1 中已修复。** 该轮子将 `facet_index` 作为顶级模块进行安装，因此，直到包括 v0.3.0 在内，它都会根据 `<venv>/Lib` 解析记录的位置——该文件既不包含语料库也不包含索引——并且 `build`、`claims` 和 `q` 在没有 `--db` 的情况下都会失败。**在 v0.3.0 或更早版本中，请使用上面的 `npx` 二进制文件。**

从 v0.3.1 开始，根目录是通过**测试记录**来解析的，而不是通过假设它：从检出目录内部运行任一命令，它会找到它；从其他任何位置运行它，它会输出**`4` REFUSED**，并显示它尝试的两个目录和它查找的两个标记。`$FACET_INDEX_DB` 现在由这两个命令读取，并且它选择哪个*索引*，而不是哪个*语料库*。在从 `main` 构建并安装到干净的虚拟环境中时进行测量——[E24](docs/experiments/E24-ruling.md)。

*此代码块已更正两次。它首先读取 `pipx install facet-mcp # 或直接安装 Python 包 `, until v0.3.0's read-back ran a **verb** instead of `--help`。
然后它说该轮子“仅适用于 `q` 和 `claims`”——**`claims` 也不起作用**，E24 通过运行它发现了这一点。两次更正都在 [known-defects.md](docs/known-defects.md) 中，并附有其测量结果。*

**第五个对象处于循环中期，并且它是第一个以参考为基础进行构建的
（2026-08-17 → 2026-08-19）。** A1，“档案管理员”，是从一个包含其自身嵌入配方的参考开始的，而不是从一个粘土概念开始，此后每个阶段都以该参考为基础：在网格存在之前，规范在 **16/16 个表面** 上得到确认，在导演的审查下批准了网格，一个场景以 **像素级精确的方式三次** 复制了参考，一个包含 sha256 清单的八视图双环，以及两个命名的污染失败，每个失败都针对一种机制进行了测量，然后才进行任何更改。烘焙过程于 [2026-08-19](docs/experiments/E70-baked-look-report.md) 获得批准——**基于身份和服装，这就是该批准的全部范围。**

**然后，画笔打开，它只在孔中进行绘制。** 第一笔在 2026-08-19 绘制在偏航角 90 度：不变 ANDON 读数为 **0.014 lv，最大的热分量为 0 px**，在 472,318 px 的测试区域之外，并且 `commit` 绘制了 **3,585 个纹素**，填充了 **2,044,423 → 2,040,838** 的孔，之后重新验证了源图集的字节级一致性。在导演的缩放视图中，背心领口到肩部的浅色三角形变为深红色，缝线看起来像一件完整的服装。它没有创造出脸部，也没有转动头部，也没有绘制第二件背心。

**方法论结果比资产本身更重要。** 在整个过程中，ControlNet 强度从未被调整——每个修复都 **消除了一个原因**，而不是对某个原因施加压力。其中两个失败是顾问自身规范缺陷，在花费任何资源之前，由执行器席位和外部审查渠道捕获，并且两者都在记录中被命名，并附带了导致它们被驳回的测量结果。

**这是一个流水线，而不是一个单角色生成器。** 如果在八个命名的元素上与规范相矛盾，则提示将赢得 **8 次中的 8 次**——中位 ΔE 为 46.3，而五个保留的控制组为 6.2——同时，图像中的人物保持不变。结构由网格和控制来保持；命名的属性由提示来控制。

**投影问题于 2026-08-16 结束** ([E45](docs/experiments/E45-warp-and-aov-kickoff.md)–[E49](docs/experiments/E49-finish-and-cap-kickoff.md))。
这八个图像 **组成**：从每个视角的束中重建，使用边界 × 面向 × 可见性权重，图集首次通过了导演的接受标准——两次，在两个周期中——旁边是一个已发布的图集，其路径一直在破坏图像，而这些图像是大家一致认可的。执行此操作的链条位于 `tools/` (`emit_view_aovs`, `s3_composite`, `flow_estimate`, `s3_run`, `s3_sheet`, `atlas_from_aovs`, `twin_mesh_warp`)，主要通过一个外部审查渠道构建，该渠道的指定的校准声明一直保持 **二十次成功，一次失败**，并且每次都通过在此处运行它来验证，然后再信任构建。

**规范是数据，它控制着支出（2026-08-17）。** 身份规范命名了十七个元素；生成双胞胎的工作流程命名了十六个元素；配置文件默认值命名了六个元素。没有任何东西将它们连接起来，因此四个周期修复了在源处出现错误的图像下游的合成。规范现在是一个数据库，其键是 **表面**——一个元素列表无法显示缺少的内容，并且一个可为空的占位符会使孔成为一行——并且 `canon_gate` 在 **内部** 运行，即在生成器工具内部运行，在输出目录存在之前。如果一个生成器的提示没有涵盖已批准的规范，则该生成器将被拒绝，并且不会写入任何内容。

**它是一个路由器，并且是“失败安全”的。** 它将一个对象解析到其规范文件，从 **两个** 方向覆盖一个提示，并携带一个范围。**一个生成支出并且没有提供规范的工具不会安静地进行——它会拒绝。** 对于一个实际上没有规范的对象，其解决方法是基于人口普查的，并且不能由具有规范的对象使用：`--no-canon --subject GALLEON` 继续进行并宣布其存在；`--no-canon --subject W3` 被 **拒绝**，因为 W3 具有表面。这通过构造而不是通过约定来关闭复选框，这很重要，因为之前的形状——`if args.canon:`——允许已发布的 PowerShell 驱动程序在不发出任何声音的情况下通过关卡。

**第二个方向是检测到实际缺陷的方向。** 检查提示 *是否包含* 规范会发现一个提示过于简单。检查提示中的 *所有内容* 是否都是规范，会发现一个短语命名了角色没有的东西——并且有一个短语存在于实时默认值中：**`gold necklace`**，该存储库已经测量出该短语错误地命名了金腰带吊坠，*“并且该元素意外地幸存下来。”* 包含该短语的覆盖提示现在返回 `missing: 0` 并且仍然被拒绝，并命名了该短语。

```
canon_gate 1.0.0  census  (occupancy is not ratification)
subject      named   occupancy   ratified   prof_hit surfaces
W3              19       24/24      24/24       5/19 canon/w3.surfaces.json
GALLEON         13           -          -      11/13 NONE
DRAGON          11           -          -      10/11 NONE
LONGSWORD        5         5/5        5/5        4/5 canon/longsword.surfaces.json
E10-LAYER        1           -          -          - NONE
LOGO             0           -          -          - NONE
A1              10       16/16      16/16      10/10 canon/a1.surfaces.json
```

`prof_hit 5/19` 是一个 **故意留下的样本，并且是损坏的**：它是运行实际会使用的实时默认值，因此第一个 `--profile character.json` 应该会停止。修复该字符串会删除证据。

**并且有一个工作表，因为没有规范的四个对象不会自行完成。** 它会发出一个对象 *类型* 所暗示的每个表面——因此，在有人命名它之前，一个孔就是一个行——将 IDENTITY.md 转换为一个清单，将关节作为对来携带以进行确认，并保留每个视角的范围插槽。它在 **结构上无法填充占位符**，这是它所测试的属性：带有已分配表面的有毒短语不会被写入。生成规范是人类参考的过程；工作表只是使该过程变得廉价和完整。

**模型的边界是明确规定的，而不是通过探索来发现。** 它会检查两个方向上经过验证的规范短语，并限定范围。它**不会**检查释义或同义词——语义匹配会将模型置于边界内，而本仓库从原则上反对这样做——也不会检查单个视图的组成部分，直到声明了视图范围，也不会检查指定的材质是否着陆在*正确*的表面上。范围插槽存在，并且它们的表面列表为空：填充它们需要人工操作，就像填充人物一样。四个对象拥有一个 IDENTITY.md 文件，但没有表面 JSON 文件——这是因为没有完成，而不是因为在没有进行手动操作的情况下就生成了。

**衡量提示可以包含多少元素，并且它没有达到规范。** 文献资料对每个添加的提示元素都设定了一个成本，即元素是否会实际出现，并且这个范围远低于我们的范围，因此 Opus 团队询问，是否可以利用已经支付的资源来解决这个问题。**答案是否定的，原因在于结构——**语料库中的任何元素都不会在周围的计数发生变化时保持其短语不变，并且该元素有可能不存在。他们提供的是单方面的限制，即在一个摄像头上最多可以使用五个提示，并且这些提示的字节完全相同，遮罩和种子也相同：在一个包含 **10 → 17** 个元素的范围内，删除了所有在 10 时存在的内容，而当计数变为*零*时，身份发生变化，这导致了完整的校准间隔发生变化。**W3 的规范要求 19 个，而语料库从未达到这个数量**（[E55](docs/experiments/E55-density-vs-identity-report.md)）。工作室会打印出三个将被合并的数字——24 个提示表面、25 个必需的检查、19 个唯一的元素——因此，从不会将覆盖率计数与元素计数测量进行比较。

**第六个对象参与进来，以回答一个不同的问题，并返回了一个否定结果（2026-09-22）。** 为了测试在应用了*油漆*（姿势和道具）之后会发生什么，对 `ai-rpg-stage` 进行了一次重建，并且它能够干净地重建，然后**无法进行自动绑定。** 通过测量而不是通过论证，消除了四个可能的因素：未添加纹理的输入、组件数量、网格拓扑和姿势。**判别器尚未确定**，并且 [`canon/BASE-FIGURE.md`](canon/BASE-FIGURE.md) 包含了尝试过的内容的表格，但没有说明导致失败的原因——因为本仓库确实指出了一个原因，即手臂与躯干的分离，但在同一小时内，一个真实的 A 姿势证明了这一点，并且在*更大的*分离距离下失败，而一个通过的姿势则不然。

**最终的结果是一个尺寸约束和两个边界。** 通过这种方法进行的所有重建都会被归一化到**其最长轴上的 1.002**——在四个不相关的资源上进行测量，精确到小数点后三位——因此，一个道具网格根本没有真实的比例，并且以原样加载的加热护罩是一个 1.8 米高的门。道具的实际尺寸现在以毫米为单位声明一次，并存储在文件旁边，然后进行检查，而不是信任（`tools/prop_scale.py`，场景单位 **1.0 = 1.8 m**）。如果一个道具*接触*人物的一个顶点，则不会保留该道具，因此接触边界会报告最小距离**和一个接触区域**（`tools/verify/prop_contact.py`）——触发它的资源在 624,510 个点中接触了 97 个点，接触面积为 0.00072，显然没有被抓住。并且现在会读取自动绑定的结果，而不是假设：`tools/verify/rig_report.py` 命名关节，将网格作为一个*集合*而不是一个计数进行比较，并说明是否存在蒙皮。

**一只长着六根手指的手，通过了四个无法识别手的边界，并最终得到了一个可接受的结果。** 导演通过观察发现了它。规范条款 7——每只手有五根手指——存在是因为条款 2 导致了这种情况，并且现在手是他的缩放视图中的一个验收项目，而不是指标默默无语的事物。

## 该路径

```
  styled 2D concept ╌╌► clay prep ╌╌╮   ← CANDIDATE hop, walked once. Not a route
                                    ╎     stage. Everything below it is the route.
                                    ▼
form-exaggerated clay concept ──► image-to-3D ──► weld ──► density allocation
                                                             │
                    cull what no camera can see ◄────────────┘
                                 │
                                 ▼
       twins, generated from THIS mesh ──► project ──► brush the holes ──► fill
```

分阶段进行，并说明了每个阶段的原因：**[手册](docs/handbook/index.md)**。

**虚线跳跃是新的，并且故意不是实线。** 该路径的第一个框一直显示*粘土概念*，到目前为止，这里没有生成任何粘土——每个粘土都是手工制作的，并且在输入时进行了哈希处理。现在存在一个概念→粘土工具，并且它的第一个配对已经以完整尺寸进行了测试：姿势、手腕绑带、腰带吊坠和撕裂的下摆都已包含；鬃毛质量没有包含；在整个帧中测量的颜色泄漏为 **C\* p99.9 = 13.15**，背景为无缝的非彩色。**该配对无法显示的是网格是否会得到改进**，这是唯一能够促进其使用的因素，因此它仍然是一个候选对象，并且其证据已被记录：**[概念准备](docs/concept-prep.md)**。

## 是什么让它起作用

六个发现，每个发现都需要一次实验，并且每个发现都超出了产生它的对象的范围。[完整的版本，包括测量结果](docs/findings.md)。

- **先注重形状，再考虑风格。** 重建工具会将表面噪点解读为几何体。一个干净、雕塑感十足的粘土模型，其平面经过有意识的夸张处理，最终会呈现出比风格化的精灵图像更好的拓扑结构；风格化的孪生模型会同时生成，并作为颜色参考。
- **突出面部轮廓，塑造面部特征。** 将图像裁剪为半身像，会在头部增加 **3.1–4.5 倍** 的多边形数量，而且这种差异是结构性的——分离的眼睑、眉毛皱纹、建模的鼻孔——而不是更清晰的模糊效果。
- **孪生模型属于网格，而不是角色。** 在不同的网格中重复使用孪生模型，可以使覆盖率降低 **62% → 22.7%**，因为手臂会投射到模型旁边的空白区域。每次都要从即将进行纹理处理的网格中生成孪生模型。
- **身份属于提示词。** 提示词中未提及的规范元素会意外出现，并且会以同样的方式消失——当金色膝盖护甲最终仅通过损坏的 ControlNet 中的噪点出现在图像中时，我们对其进行了测量。
- **询问几何体，而不是阈值。** 将关键遮罩替换为精确的光线投射轮廓，可以将参考覆盖率提高 **28.4% → 39.1%** 的有效纹素——完全是累加的，没有扩散，不需要 GPU。角点中值关键技术在这里已经失败了 **四** 次，并已停止使用——一个绘制的渐变、一个灰色调的粘土渲染、一个扩散模型的灯光照亮的背景，以及一个扩散参考，其自身的角点跨度为 L\* 48.1–81.1。⚠ 该形状仍然包含在一个消费者产品中，即 `tools/verify/gate_mesh.py`，它会采样单个角点：在这里明确说明，而不是默默地进行。
- **剔除任何相机都无法看到的区域，从图集中剔除，而不是从网格中剔除。** 49% 的图集纹素从外部是不可见的；排除这些面可以使插值减少 **68%**。与其删除，不如排除，这样可以使失败变得不可能，而不是仅仅可以检测到。

## 尚未解决的问题

已命名并测量，放在首页而不是脚注中。[全部位于代码中](docs/known-defects.md)。

- **一些可见的表面贴图映射到图集空间，但没有任何烘焙过程会写入这些贴图**，渲染时会显示为图像未修改的默认黑色。Blender 的烘焙工具使用纹素中心采样，因此没有纹素中心的三角形区域会留空——它的开发者
[命名了这种机制，并在构建了所有这些数据之后两周合并了一个修复](https://projects.blender.org/blender/blender/pulls/161752)。这是一种属性，与单个对象无关，而是与流程有关：在一个资源上进行测量，**而在其他四个资源上未进行测量**。
- **刀片带在所有八个摄像机上占据 0.00% 的第一阶段参考**——在灰色背景上的钢材正好位于关键阈值上。联合处理可以修复 55.72%。
- **笔触接缝没有对齐。**一种来源边界的偏差是普通纹理变化的 **5.5 倍**；导演命名的区域的偏差是 **9.5 倍**。
- **扩散会从不相关的图集岛屿之间渗出**——74.9% 的扩散纹素从另一个岛屿获取颜色，与图 1.0 上的平均距离为 0.177。⚠ **这个比例是在图集纹素中，而不是关于摄像机所见的内容**：扩散占烘焙图集的 26.95%，占渲染图像像素的 **4.95%**，比例为 0.18。贴图存在于大型图表中，孔洞存在于小型图表中，因此扩散的纹素在屏幕空间中是廉价的。
- **⚑ 决定接受标准的缺陷是由贴图携带的，而不是由任何填充携带**——区域呈现出另一种材质的颜色，而没有任何斑点统计数据可以检测到。通过在三个空间中进行三次会话进行测量：**91.05% `reference` 携带，富集度为 0.99**，与基准率一致；在布料绿色中，同一类别的比例为 **68.46% `reference`**；在薄刀片上，表面自身的绘制纹素的比例为 **18.77%**，而与扩散填充的 **5.55%** 相比。填充正确地从其最近的绘制邻居处获取，而该邻居本身已经存在问题。混合本身是一种未记录的双频带分割
(`M + gaussian_blur_σ16(B − M)`)，它在相同的点上测量 **四个选项中最差** 的结果。
- **⚑ 绘制的面呈现出条带状，并且上述所有权发现应用于已接受的资源。**A1 的孪生面是一个连续的色调；烘焙被切割成垂直的、不同色调的条纹。`project_twins` 是 **胜者全得**——每个纹素由一个摄像机通过面对权重完全决定，而不是通过平均，并且该面由正面视图和两个 45° 象限看到，这些视图在接受环上对皮肤值的差异为 **R 13.0 / G 13.9 / B 18.3**。只要面部上的两个 UV 图表由不同的摄像机拥有，差异就会呈现为明显的阶跃，因此 **条带是岛屿边界，而不是污垢**——也不是灰色孔洞类别。**笔刷在结构上无法修复它**：`commit` 仅写入孔洞纹素，并且样式的纹素是冻结的。命名了两种补救措施，但都没有采用——让正面视图拥有整个头部条带，或者允许进行缝隙混合，**从而重写样式的皮肤**，而当前流程中的任何阶段都无法做到这一点。加权平均值已经累积在工具中，并且混合图集已经存在于磁盘上；没有人将其呈现在导演面前。**这存在于批准烘焙的表格中**，并且批准涵盖了身份和服装集——已接受的工件上的公开缺陷不是矛盾，但记录不应将批准视为涵盖了没有人评估的属性。
- **视图永远不会是独立的，这限制了所有混合修复。**对于每个缺陷斑块，**100% 的具有两个或多个贡献摄像机的面都位于 90° 范围内**（平均 45°），并且 21% 的缺陷面仅由一个摄像机看到。在接近相同的控制下，相邻视图会同时失败，因此摄影测量学中发布的多个视图的优势不能在此处直接应用。
- **此流程中的每次重建都是一个空心双层外壳**，壁厚约为两个体素。没有一个体素可以进行体积预测。
- **板材在未命名的材质边界处存在差异，而规范是关键**（2026-08-16）。内部双面到网格的扭曲，在所有八个视图中，与轮廓中值的 1.2–3.0 相比，平均值为 **3.5–11.1 像素**；导演圈出的每个残余区域——袖口、手、靴子顶部——都是材质连接，而生成提示中没有命名。⚠ **已于 2026-08-17 更正，并且更正结果更加明确。** 此处写道“记录的提示包含六个元素”——经过测量，它将两个不同的文件焊接在一起。生成孪生的工作流程命名了 **16 个中的 17 个**，仅缺少握持部分；*笔刷配置文件默认值* 命名了六个。两者都是正确的，并且该句子在其中做出了一个错误的声明。重要的是，握持、护手、护胫和手在 16 个短语的提示中出现 **零** 次——因为 **规范中根本不存在这些元素**。即使是完整的提示也无法命名一个从未指定的“手”。✅ **已于 2026-08-17 关闭**——表面列表已被遍历、填充，并且 **24/24 已通过验证**，并且门现在拒绝使用不包含该元素的提示。
- **5.65–5.57% 的有效纹素是任何平面环摄像机都无法看到的表面**——它们在每个视图中都未能通过深度门，没有投影路线可以绘制它们，并且已发布的流水线使用岛屿盲区填充来覆盖它们，从而产生了深色标记。它们需要一个策略（中性材质、笔刷或接受），而不是一个修复（[E49 报告](docs/experiments/E49-finish-and-cap-report.md)）。
- **已接受等级的表格上的平面彩色多边形**——导演的唯一公开类别。⚠ **填充通道假设已被证伪（2026-08-17）。**孤立填充的测量值低于其自身的基准率（0.27 倍），补丁位于 90–99% 的普通绘制纹素上，并且在从烘焙修复之前使用的图集构建的渲染中也存在相同的缺陷。相反，它被追溯到其来源：渲染视图的孪生版本在那里是干净的，并且 **不同的** 视图拥有 115 个缺陷像素中的 97 个，其面对权重为 0.68，而另一个为 0.60。角度补丁是一种 **散射伪像**，颜色是已经命名的表面上真实的跨视图差异——因此，“缺陷存在于孪生版本中”不能证明需要进行孪生版本再生。⚠ **并且此页提出的修复也已被证伪（2026-08-17）。** 它写道“*更喜欢目标视图的合成器是范围内的修复，并且成本为零。*”合成器已经存在，并且已经是默认设置；与从一条记录的运行中提取的静态图像上的平面分类器进行比较，首先选择目标视图会 **增加** 命名目标上的计数（38 → 40），并且会大幅增加其他两个视图上的计数（23 → 64，36 → 110），并且会变得 *更加* 连贯。机制：**形状是所有权，颜色不是。** 橄榄色是视图 6 绘制的表面，而视图 6 正确地绘制了该表面，因此在目标 6 上——其中首先选择目标意味着 *更喜欢视图 6*——该策略会最大化构成缺陷的颜色。**所有权策略无法修复正确归因的表面上的跨视图颜色差异**，这会使整个系列失效，而不是仅使其中一个分支失效（[E52](docs/experiments/E52-target-first-flats-ruling.md)）。剩下的只是一个绘制问题，并且需要进行一次生成。*已过时的文本，但保留以符合更正规则：“大小为单个三角形的孤立岛屿，从边界相邻的孪生样本中进行平面填充，并使用未侵蚀的轮廓。”*

- **一种不会自动绑定骨骼的重建方法，并且没有已知的歧视器。** 六个测试对象中的一个可以干净地重建，但无法进行自动绑定骨骼。未添加纹理的输入、组件数量、网格拓扑和姿势都通过测量进行消除——并且这个仓库中*确实*提到的原因，在同一小时内被证明是虚假的，因此表格中没有该项。对一个已存在的绑定骨骼进行操作，其结果是有可测量的上限，而不是一个修复方案：大约 20 度的手臂旋转仍然可以正常工作，大约 110 度会导致肩膀变形，并且刚性板绑定[无法修复](docs/tools.md)——所有三个尝试的修复方案都经过了测量，并且都失败了。
- **没有道具被安装和接受。** 尺寸约束和接触门存在，并且针对已知间距的合成网格进行了测试。目前还没有任何东西被放置在模型中，并且在导演的视角下进行了评估，在这一点发生之前，该门只是一个没有实际资产的工具。

## 这个仓库的运行方式

纪律性与流水线一样重要，并且它存在于此，原因如下：之前的流程进行了十次测试，每次都对自己的输出进行评估，并在下一次测试中将结论作为既定事实进行记录。该循环中的任何内容都无法进行验证。

- **先进行规范，后进行报告，最后进行评估**——并且设计实验的环节不会对自己的结果进行评分。七十二个实验都记录在[此处](docs/experiments/)。
- **修正会保留在相应的位置，与导致其被推翻的测量结果并列**，而不是以静默删除的方式进行。仅在最初的环节中，就有六个继承的声明被证明是虚假的，并且这六个声明仍然可以与替代它们的内容并列查看。
- **失败的结果会保留在仓库中，并附带其原因。** [`tools/superseded/`](docs/tools.md)
不是一个存档——任何人都可以运行这些工具，并观察它们以相同的方式失败。
- **负面结果就是完全的成功**，它会被报告并关闭，而不是调整到某个数值。
- **测试会与修改代码的代码提交相关联**——在两个测试人员手中，有 1376 个测试通过，并且有 1319 个经过路径限制的 CI 测试。
- **记录是可以查询的。** 对整个流程使用 SQLite + FTS5 索引进行验证，验证了四个方面。它发现评估计数与文本中描述的不同，通过对记录本身进行计数来确定。

## 信任和威胁模型

facet 完全在您自己的机器上运行——每个工具都是您在您键入的路径上调用的脚本，因此有意义的问题不是*此应用程序请求了哪些权限*，而是*这些脚本对您的机器做了什么*。通过测量来回答，并且每次扫描都可以重新运行；完整的策略在[SECURITY.md](SECURITY.md)中。

- **涉及的数据：**本地磁盘上的网格、纹理、图像和 JSON 文件，路径由您在命令行中提供。此外还有 `docs/index/facet.db`，它是*派生*出来的——它不包含任何原本不在该仓库中的文件，并且 `facet_index.py build` 会从头开始重新生成它。
- **未涉及的数据：**绝不涉及任何凭据。没有任何内容会读取、存储或传输令牌、密钥或密码，并且这些内容都不存在于文件中——已检查是否存在以提供程序为前缀的密钥、GitHub PAT、Slack 令牌、AWS 密钥 ID、私钥块、Bearer 令牌和内联 `api_key`/`password` 赋值，**零个匹配项**，没有可识别为凭据的文件。
- **没有遥测数据。**不收集，也不发送。由于没有任何内容需要选择退出，因此不存在选择退出的选项。
- **网络出口：**两个工具会打开一个套接字——`restylize_views.py` 和 `texpass_brush.py`——并且两者都会调用 ComfyUI HTTP API，地址为 `--host`，**默认 `127.0.0.1:8188`**。`tools/` 中的其他任何内容都不会进行网络调用。
- **权限：**普通用户。没有权限提升、没有服务安装、没有系统设置或注册表写入。

公开了三个关键点，而不是声称它们已被消除，因为仅列出保证的安全说明并不是一个威胁模型：**文件操作没有被沙箱化**（一个工具会在其参数指示的位置写入）；**许多工具和文档中都嵌入了绝对本地路径**——在 26 个文件中总共出现 114 次，这并不是秘密，而是一个机器布局的披露，也是大多数工具无法在其他地方未经修改运行的原因；并且**意外的故障会以未发布的脚本中的 Python 堆栈跟踪形式出现**，没有 `--debug` 门控。有意的停止是 `ANDON:` 消息，其中包含触发它们的测量结果。这就是研究工具的契约，[SHIP_GATE.md](SHIP_GATE.md) 准确地记录了何时它不再足够好——对于两个命令所执行的*安装*操作，在 0.2.0 版本中：`facet-index` 和 `facet-mcp` 返回 `0` 正常 / `1` 用户错误 / `2` 运行时错误——并且，自从 [E22](docs/experiments/E22-ruling.md) 之后，**对于触发的门控或失败的 `verify` 环节，返回 `4` 拒绝**，这意味着工具正在工作并告诉您不要继续，而不是运行时错误。所有这些都会以结构化的失败形式拒绝，并命名下一步操作，而不是堆栈跟踪 ([E21](docs/experiments/E21-cli-contract-report.md))。

**并且这两个命令中的门控不再可删除。**在执行安装操作时，每个 ANDON 都会触发 `raise`；一个简单的 `assert` 只是一个 `python -O` 会静默删除的声明，并且在 E22 之前，此仓库中的 87 个门控都可以通过环境变量删除。在相同的门控上，分别在四种解释器模式下进行了测量。
**并且，自从 [E23](docs/experiments/E23-route-gates-report.md) 之后，生成四个已接受资产的路径上的门控也不可删除**——它在十二个工具中拥有 **57 个站点**，转换为对从未执行过的文件的纯粹移动，现在每个站点都会在 `-O` 和 `PYTHONOPTIMIZE=1` 以及在正常解释器下拒绝。
**并且，自从 [E25](docs/experiments/E25-ruling.md) 之后，该类别已关闭。**它在 43 个文件中拥有 **133 个站点**——用于生成上述四个已接受资产的证据的测量工具，以相同的方式进行转换，使总数达到 `raise`，总数为 **278**。
在 `tools/` 下，仅剩 **一个**简单的 ANDON `assert`：
`superseded/texpass_thin_mask.py`，它**永远**不会被转换，因为这些工具被保留，以便任何人都可以运行它们并观察它们以相同的方式失败。该剩余部分通过名称固定在测试套件中，因此未来的扫描无法在不故意编辑测试的情况下将其删除。

**支持状态：**此仓库在一个平台上以开放方式进行开发，由一位主管和一对轮换的顾问和执行者组成。`main` 是唯一受支持的状态。没有发布渠道、没有回溯策略，也没有 SLA——取而代之的是记录：每个声明都与其生成代码相邻，并且 [docs/experiments](docs/experiments/) 包含每个声明的规范、报告和裁决。

## 要求

Blender 5.x，Python 3.11+，以及 `numpy`、`scipy`、`trimesh`、`open3d`、`Pillow`、`spandrel`、`torch`。仅需要本地 ComfyUI 安装才能使用修复画笔。
在 RTX 5090 上进行开发；VRAM 空间比原始速度更重要。

**两种解释器，并且这种划分是有意的。**套件、已部署的 MCP 工具以及所有测量都在使用携带 CI 引脚的环境下运行（3.12）。重建阶段在第二个解释器下运行，该解释器已固定为 **3.10**，因为 TRELLIS 轮子是为此构建的。如果某个工具无法导入，通常是因为它正在从另一个解释器中调用。

CI 在 **ubuntu-latest / Python 3.12** 上运行 hermetic 子集套件，并使用固定的安装（`.github/workflows/ci.yml`）；artifacts 层需要记录的树，地址为 `E:\AI\training`，这些树不在 git 中，因此 CI 会按设计选择不使用它们。
在本地，`python -m pytest` 运行所有 **1376** 个测试，而 `python -m pytest -m "not artifacts"` 运行 CI 复制的 **1319** 个测试。

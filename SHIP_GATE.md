## B. Error Handling

- [x] `[all]` Errors follow the Structured Error Shape: `code`, `message`, `hint`, `cause?`, `retryable?` (2026-08-08, **re-answered at the extraction**) — the old SKIP said this "lands with the extracted MCP tools." It landed. `RecordError(code, message, hint, retryable)` validates `code` against a closed `CODES` tuple and every refusal leaves through one wire site. ⚑ **Bounded, and the bound NARROWED at 0.2.0 ([E21](docs/experiments/E21-cli-contract-report.md)):** both published console scripts now emit `message` / `cause` / `hint` on an unexpected exception and on a fired gate — so the CLI surface carries the shape's readable half, though not `code`-as-a-closed-enum or `retryable`. **The 34 unpublished research scripts are unchanged** and keep the `ANDON:` convention — a halt carrying the measurement that fired it — which is *not* this shape. That is deliberate: retrofitting an error registry across the instruments that produced four accepted assets would be a large change to accepted-asset tooling bought for a checkbox. The contract is met on the MCP product surface, met in readable form on the two installed commands, and disclosed in SECURITY.md for the rest
- [x] `[cli]` Exit codes: 0 ok · 1 user error · 2 runtime error · 3 partial success (2026-08-08, **closed at 0.2.0 by [E21](docs/experiments/E21-cli-contract-report.md)**, measured through a subprocess before and after — T29, 30 tests) — the pre-change surface was **inverted at both ends, not one**: user error exited **2** (argparse) *and* runtime error exited **1** (CPython's uncaught-exception default, with a raw traceback). This line's earlier text named only the argparse half; the second inversion was found by running the matrix rather than reading the code. Now `0` / `1` / `2` as written, asserted per outcome class with a can-fail leg for each. **`3` is declared and unused**, because no verb of either command has a partial-completion path — `verify` reporting three passing legs and one failing one has *completed* and reports a measured outcome. ⚑ **The bound that stood here is CLOSED by [E22](docs/experiments/E22-gates-report.md).** Two classes kept their pre-E21 codes on purpose — a **failing `verify` leg** and a **fired ANDON** — because what they deserved was [E21](docs/experiments/E21-cli-contract-report.md)'s open questions 1 and 2 and belonged to a ruling, not to an executor. [E21 Ruling 4](docs/experiments/E21-ruling.md) ruled them, and E22 carried it: **both now exit `4 = REFUSED`** — *the tool ran correctly and is telling you not to proceed* — which is one code and not two, because no caller has been shown to need the distinction and the message already carries it. `0`/`1`/`2` are the standard's, `3` stays reserved and unused, and `4` is domain space the standard leaves open. Pinned in T30 with a can-fail leg, and the certificate field and the test fixture now read the tool's own constant instead of a hardcoded integer
- [x] `[cli]` No raw stack traces without `--debug` (2026-08-08, **closed at 0.2.0 by [E21](docs/experiments/E21-cli-contract-report.md)**) — an unexpected exception now leaves as a structured failure (`message` / `cause` / `hint`) naming the next step, and a **fired gate** leaves as `GATE_FIRED` carrying its own ANDON text instead of an `AssertionError` traceback. `--debug` restores the traceback and is **proven** presentation-only rather than promised: same exit code with and without, and a `build` run under each writes a byte-identical artifact. E08 Amendment 32's no-skip-flag ruling is enforced against the new flag by an AST walk pinning that `debug` is read only where a failure is *printed*, plus a live test that a fired gate still refuses with `--debug` set. T21's closed flag allowlist widened by **exactly one**, in writing, with that condition attached
- [x] `[mcp]` Tool errors return structured results — server never crashes on bad input (2026-08-08, **fired live**, not attested) — `limit=999` → `BAD_ARGUMENT` with the valid range; `table="not_a_table"` → `BAD_ARGUMENT` naming all eight valid tables. **The server stayed up** — `record_health` answered normally in the same exchange
- [x] `[mcp]` State/config corruption degrades gracefully (stale data over crash) (2026-08-08) — `health()`'s contract is *"never raises — it returns the refusal instead"*, and the surface carries a literal `SERVING_STALE` state that serves the older record behind a banner naming the fix. E18's dogfood fired this on a hand-corrupted DB: every read tool refused with its code, health kept answering, one `record_build` recovered

And the objection is now mechanical, not philosophical: `record_mcp` calls `facet_index.verify()` in-process and **parses its stdout** to build the schema-versioned certificate, so a quiet `verify` breaks the certificate. `record_mcp`'s own 4 prints are all in `--print-tools`; **the serving path prints nothing**, because a stdio server that writes to stdout corrupts its own JSON-RPC stream — so a quiet mode for `facet-mcp` would govern an empty set. `build` is the one verb with a real progress line, and it already carries a `quiet=` keyword that `record_build` uses. Nothing is redacted because nothing sensitive is printed (see A3). **Blocked on the advisor's boundary ruling, not on work**

スタイルは、テクスチャ空間内のアセットに適用されます。ビューごとにペイントして後でつなぎ合わせることはありません。形状を強調した粘土のコンセプトをパイプラインに入力すると、そのメッシュのスタイライズされた参照から色を取得したテクスチャ付きメッシュが出力され、参照では見ることができなかった部分は、マスク処理されたインペインティングブラシとサーフェスを認識する拡大を使用して塗りつぶされます。

この問題の両方の側面を表す名前です：ポリゴンと、それらが保持する必要がある面。

## インストール

パイプライン自体は、入力したパスに対して実行する一連のローカルスクリプトです。リポジトリをクローンし、[Getting Started](https://mcp-tool-shop-org.github.io/facet/handbook/getting-started/) を参照してください。

**2つのサーバーがパッケージとして提供されます**。1つはレコードインデックスで、アシスタントが証拠の追跡を読み込む代わりにクエリを実行できるようにします。もう1つは、**v0.4.0 以降では測定サーバー**です。これにより、数か月離れて測定された2つのアセットは、同じコードパスを経由します。

```bash
npx @mcptoolshop/facet               # the record index; zero-prerequisite, no Python needed
pip install facet-mcp[measure-full]  # + the measurement tools and their instruments
```

`facet-mcp` は、レコード上の stdio MCP サーバーであり（6つのツールがあり、そのうちの1つが拒否的な健全性サーフェスとして機能する4脚検証）、`facet-index` はインデックス自体です（`build` / `verify` / `q` / `claims`）。どちらもチェックアウト内から実行します。`--db` は別のインデックスの名前です。

### 測定サーバー - v0.4.0 で新機能

`facet-measure` は、比較の**数値的な側面**を処理し、出力が良好かどうかは判断しません。すべてのペイロードには、サーバーバージョン、インストルメント自体のファイルハッシュ、および構成ハッシュが含まれており、`measure_report` は不一致がある場合に比較することを**拒否します**。これは、このシステム全体が存在する理由です。

**verb**（動詞）を実行することで検証され、`--help` を実行するのとは異なります。コントロールメッシュは、チェックアウトされていないマシン上で786,432個の面と完全なアイデンティティエンベロープを返します。

**結果は1つの要素に依存し、それはPythonのバージョンです。**

| あなたの Python | `[measure-full]` はあなたに提供します |
|---|---|
| **3.11 / 3.12** | **8つのツールすべて** - `open3d` は PyPI からインストールされます |
| **3.13** | 4つのツール。`mesh_stats`、`mesh_topology`、`measure_report`、`anchor_check` |

`open3d` 0.19.0 が最新の*リリース*であり、cp38〜cp312 ホイールを **sdist なし** で公開します。そのため、Python 3.13 では PyPI にインストールできるものはありません。追加機能は、それを `python_version < "3.13"` の背後に配置するため、そこでインストールが**成功**し、4つのジオメトリツールが
必要なものを名前で示して **`4` REFUSED** で終了します。これは、インストールの全体が失敗するのではなく、特定のツールの実行に問題があることを意味します。

**Python 3.13 で8つすべてを取得するには**、Open3D は現在の cp313 ホイールをローリング開発チャンネルで公開しています。コマンドラインでは直接 URL を使用できます。ただし、これは公開されたパッケージメタデータ内でのみ禁止されています。

```bash
# Linux — stable filename, no build hash
pip install https://github.com/isl-org/Open3D/releases/download/main-devel/open3d-0.19.0-cp313-cp313-manylinux_2_35_x86_64.whl
```

⚠ **Windows および macOS では、開発ホイールのファイル拡張子は `+<sha>` で終わります**（執筆時点では `open3d-0.19.0+63e30be-cp313-cp313-win_amd64.whl`）、名前は `main` が変更されるにつれて変更されます。 [ `main-devel` リリース](https://github.com/isl-org/Open3D/releases/tag/main-devel) にあるアセットをリストし、現在のものを選択します。 **このパイプライン自体の Open3D に依存する数値が測定されたのは、このビルドに対してです**。これは、比較可能性の境界線であり、アイデンティティエンベロープはインストルメントのハッシュを記録し、その依存関係ではありません。[E31](docs/experiments/E31-ruling.md)。

*v0.3.1 までのホイールには2つの `.py` ファイルが含まれており、測定ツールは含まれていません。そのため、インストールされた測定サーバーを実行しても何も実行できませんでした。これは4回のリリースにわたって誰にも気づかれませんでしたが、このリポジトリ自体がチェックアウトであるためです。ツールは、ビルドされた場所で機能し、他の場所に存在したことはありませんでした。*

⚠ **`pip install facet-mcp` は v0.3.0 までのすべてのリリースバージョンで壊れており、v0.3.1 で修正されています**。ホイールは `facet_index` をトップレベルモジュールとしてインストールするため、v0.3.0 およびそれ以前のバージョンでは、レコードの位置を `<venv>/Lib` に対して解決していました（これは、コーパスもインデックスも含まない）。また、`build`、`claims`、および `q` は `--db` なしで失敗しました。
**v0.3.0 以降を使用する場合は、上記の `npx` バイナリを使用してください。**

v0.3.1 以降では、ルートはそれを仮定するのではなく、**レコードの存在をテストすることによって解決されます**。どちらかのコマンドをチェックアウト内から実行すると、見つかります。他の場所から実行すると、**`4` REFUSED** で終了し、試した両方のディレクトリと検索した両方のマーカーの名前が表示されます。
`$FACET_INDEX_DB` は現在、両方のコマンドによって読み取られ、どの*インデックス*を使用するかを選択します（*コーパス*は選択しません）。 `main` からビルドされ、クリーンな仮想環境にインストールされたホイールで測定されました。[E24](docs/experiments/E24-ruling.md)。

*このブロックは2回修正されました。最初に `pipx install facet-mcp # または Python パッケージを直接`, until v0.3.0's read-back ran a **verb** instead of `--help` と記述されていました。次に、ホイールは「 `q` および `claims` でのみ機能する」と記述されていましたが、**`claims` も機能しませんでした**。これは E24 が実行して確認したものです。両方の修正は [known-defects.md](docs/known-defects.md) に測定値とともに記載されています。*

**4つの承認されたアセット、4つの被験クラスにわたって、クレジットはゼロです**。それぞれがディレクターによって独自のズームで評価されました（GLB 上またはフルサイズのシート上）。メトリックがしきい値を超えてクリアされることはありませんでした。

|---|---|---|---|
| **Character (W3)** | ヒューマノイド | [2026-08-04](docs/experiments/E08-ruling-gate0.md) | 68.8 / 4.2 / 27.0 |
| **Galleon** | 車両、薄いリギング | [2026-08-05](docs/experiments/E04-ruling.md) | 36.89 / 6.87 / 56.24 |

| **Longsword** | 小道具、ほぼ2D、グレーのグラデーション | [2026-08-08](docs/experiments/E14-ruling.md) | 45.25 / 2.07 / 52.68 |

共有されるのは有効なテクセルであり、**それらは被験者間で比較できません**。船はほとんど自身を目の高さから隠し、動物はその半分を隠します。それぞれを独自の事前に登録された範囲の上限と比較して評価すると、**86〜93％** になります。行間の違いはジオメトリであり、回帰ではありません。[完全な数値と分母](docs/handbook/subjects.md)。

**これはパイプラインであり、1つのキャラクターを生成するものではありません**。8つの名前付き要素で仕様に矛盾させると、プロンプトが **8/8** で勝利します。中央値の ΔE は 46.3 であり、5つの保持されたコントロールでは 6.2 です。ただし、図は同じ人物です。構造はメッシュと制御によって保持され、名前付き属性はプロンプトに依存します。

**プロジェクターに関する質問は2026年8月16日に終了しました**（[E45](docs/experiments/E45-warp-and-aov-kickoff.md)–[E49](docs/experiments/E49-finish-and-cap-kickoff.md））。
8つのプレートは、以下の要素で構成されます。各ビューのバンドルから再構築され、境界×向き×可視性による重み付けが行われ、アトラスがレンダリングされ、このルートで初めてディレクターの承認基準を満たしました。2回、2つのアークにわたって、また、プレートの色を劣化させる原因となっていた別のルートのアトラスと比較されました。これを行ったチェーンは`tools/`にあります（`emit_view_aovs`、`s3_composite`、`flow_estimate`、`s3_run`、`s3_sheet`、`atlas_from_aovs`、`twin_mesh_warp`）。これは主に外部レビューチャンネルを通じてビルドされ、指定されたキャリブレーションの主張は「20回中20回」成功し、そのすべてがここで検証されました。それは、ビルドを信頼する前に実行することで確認されます。

**カノンはデータであり、支出を制御します（2026年8月17日）。** アイデンティティ仕様には17個の要素が含まれていました。ツインを生成したワークフローには16個の要素が含まれていました。プロファイルデフォルトで新しい実行に使用されるのは6つでした。これらは互いに関連していません。したがって、4つのアークが、ソースで間違っていたペイントの下流での構成を修正しました。カノンは現在、**サーフェス**をキーとするデータベースです。要素リストでは、何が欠けているかを示すことはできません。また、null許容の占有物は、行に穴を開けます。そして、`canon_gate`は、出力ディレクトリが存在する前に、生成を作成するツールの**内部**で実行されます。カノンに準拠していないプロンプトを持つ生成は拒否され、何も書き込まれません。

**これはルーターであり、フェイルクローズです。** これは、対象をそのカノンファイルに関連付け、プロンプトを**両方向**でカバーし、スコープを持ちます。**支出を作成するツールであり、カノンが与えられていない場合、静かに処理を進めません。拒否します。** 実際にカノンを持たない対象に対する回避策は、統計データに基づいており、カノンを持つ対象によって使用することはできません。`--no-canon --subject GALLEON`は実行され、自身を通知します。`--no-canon --subject W3`は**拒否されます**。なぜなら、W3にはサーフェスがあるからです。これにより、チェックボックスが構成によって閉じられ、慣例ではなくなります。これは重要です。なぜなら、以前の形状（`if args.canon:`）では、出荷されたPowerShellドライバーがゲートを静かに通過できたからです。

**2番目の方向は、実際の欠陥を発見するものです。** プロンプトにカノンが含まれているかどうかを確認すると、プロンプトが薄いことがわかります。プロンプト内のすべての要素がカノンであるかどうかを確認すると、キャラクターが持っていないものを指すフレーズが見つかります。そして、ライブデフォルトには1つありました。それは**`gold necklace`**であり、このリポジトリはすでにそれを、ゴールドベルトのメダリオンを誤って命名していると評価していました。「*そして、その要素は偶然生き残ります。*」そのフレーズが追加されたカバージングプロンプトは、現在`missing: 0`を返し、それでも拒否され、句を指します。

```
canon_gate 1.0.0  census  (occupancy is not ratification)
subject      named   occupancy   ratified   prof_hit surfaces
W3              19       24/24      24/24       5/19 canon/w3.surfaces.json
GALLEON         13           -          -      11/13 NONE
DRAGON          11           -          -      10/11 NONE
LONGSWORD        5         5/5        5/5        4/5 canon/longsword.surfaces.json
E10-LAYER        1           -          -          - NONE
LOGO             0           -          -          - NONE
```

`prof_hit 5/19`は、**意図的に壊れたままのサンプルです**。これは、実行で使用されるライブデフォルトであるため、最初の`--profile character.json`は停止するように設定されています。文字列を修正すると、証拠が削除されます。

**そして、ワークシートがあります。なぜなら、カノンを持たない4つの対象は、自分で処理を進めることはないからです。** これは、対象の*種類*が示すすべてのサーフェスを出力します。したがって、穴は誰かが名前を付ける前に行になります。IDENTITY.mdをインベントリに変換し、ジョイントをペアとして扱い、確認し、各ビューのスコープスロットを予約します。これは**構造的に占有物を埋めることができません**。そして、それがテストされる特性です。サーフェスがすでに割り当てられている状態で、毒性のあるフレーズが到着した場合、それは書き込まれません。カノンの生成は、人間が参照を歩くことです。ワークシートは、単にその作業を安価かつ完全にします。

**ゲートの境界は、発見されるのを待つのではなく、明示的に述べられています。** これは、両方の方向で、スコープ内で、承認されたカノンのフレーズを確認します。これは、言い換えや同義語を確認しません。セマンティックマッチングはモデルをゲートの内側に配置することになり、このリポジトリはその原則に基づいて拒否します。また、ビューのスコープが宣言されるまで、各ビューのステムも確認されず、名前付きのマテリアルが*正しい*サーフェスに配置されたかどうかを確認しません。スコープスロットが存在し、そのサーフェスのリストは空です。それらを埋めるのは人間の作業であり、占有物を埋めるのと同じです。4つの対象にはIDENTITY.mdとサーフェスJSONがなく、参照を歩いて生成せずに放置されています。

**プロンプトが保持できる要素の数は測定され、カノンに到達することはありません。** 文献では、追加された各プロンプト要素は、要素が存在するかどうかという点においてコストがかかり、その範囲は当社よりもはるかに小さいです。したがって、Opusシートは、すでに支払われたプレートでそれを解決できるかどうかを尋ねました。**それはできません。そして、その理由は構造的です。** コーパス内のどの要素も、周囲のカウントが変化し、かつ存在しない可能性がある間に、フレーズを一貫して保持することはありません。それらが提供するのは、1つのカメラで5つのプロンプトがあり、バイト単位で同一の制御、マスク、およびシードがある場合の片側境界です。**10 → 17**にわたる要素ラダーでは、カウントが削除されても、10で存在していたものは何も削除されず、*ゼロ*でのアイデンティティの変更は、完全なキャリブレーション間隔を移動させました。**W3のカノンは19を要求し、コーパスは決してそれに到達しません**（[E55](docs/experiments/E55-density-vs-identity-report.md））。スタジオは、24のプロンプトサーフェス、25の必要なチェック、19の一意の要素という3つの数値を出力します。したがって、カバレッジカウントは、要素数測定に対して引用されることはありません。

## 何がそれを機能させるのか

6つの発見があり、それぞれ実験にコストがかかり、また、それらを生成した対象を超えて一般化される。［詳細な説明と測定値については、こちらを参照］（docs/findings.md）。

- **まず形状を決定し、次にスタイルを適用する。** 再構築ツールは、表面のノイズをジオメトリとして解釈する。意図的に誇張された面を持つ、滑らかで彫刻のような粘土を使用すると、より洗練されたスプライトよりも優れたトポロジーが得られる。また、スタイライズされたもう一方のモデルが同時に生成され、カラー参照として使用される。
- **顔をフレームに収め、顔を作成する。** バストショットでは、頭部に3.1〜4.5倍多くのポリゴンが配置され、その違いは構造的なものである。具体的には、まぶたの分離、眉間のしわ、鼻腔のモデリングなどであり、単なるぼかしの強さではない。
- **ツインはキャラクターではなく、メッシュに属する。** ツインを複数のメッシュで再利用すると、カバレッジが62%から22.7%に低下する。これは、腕がモデルの横にある空中に投影されるためである。テクスチャを適用しようとしているメッシュからツインを生成し、毎回使用する。
- **アイデンティティはプロンプトに依存する。** プロンプトで指定されていない正典要素が偶然出現し、同じ方法で消えることがある。これは、金色の膝当てが壊れたControlNetのノイズによってのみ画像に表示されるようになったときに測定された。
- **閾値ではなく、ジオメトリを尋ねる。** キー付きマスクを正確なレイキャストシルエットに置き換えると、有効なテクセルにおける参照カバレッジが28.4%から39.1%に増加する。これは厳密に追加であり、拡散やGPUは使用しない。コーナー中央値キーイングはここで3回失敗しており、廃止された。
- **カメラで確認できないものをアトラスから削除し、メッシュからは決して削除しない。** アトラスのテクセル全体の49%が外部からは見えないため、これらの面を除外すると補間が68%削減される。削除するのではなく除外することで、単に検出可能であるだけでなく、失敗を不可能にする。

## 未解決の問題

名前と測定値は、脚注ではなく、最初のページに記載されている。[すべてコード内に配置](docs/known-defects.md)。

- **一部の可視表面マップは、ベイク処理で書き込まれないアトラス空間にマッピングされ**、画像が変更されていないデフォルトの黒としてレンダリングされます。Blender のベーカーはテクセル中心サンプリングを使用するため、どのテクセル中心にも重なっていない三角形は空のままになります。開発者たちはこの仕組みに名前を付け、ビルドから 2 週間後に、ここで測定されたすべての数値に対して修正をマージしました。これは、特定のオブジェクトではなく、ルート全体の特性です。1 つのアセットで測定し、**他の 4 つでは測定していません**。
- **ブレードバンドは、8 台のカメラすべてでステージ 1 の参照の 0.00% を占めます**。灰色の背景に配置された金属が、キーの色合いの閾値に正確に一致します。この組み合わせにより、55.72% が補正されます。
- **ストロークの継ぎ目は滑らかではありません**。プロベナンス境界は、通常のテクスチャの変化よりも **5.5 倍** 大きく変化します。ディレクターが指定した領域は、**9.5 倍** の変化を示します。
- **拡散によって、関連性のないアトラスアイランド間で色が混ざります**。拡散されたテクセルの 74.9% は、高さ 1.0 の図で平均 0.177 だけ離れた別の島から色を取得します。⚠ **この割合はアトラスのテクセルに関するものであり、カメラが見ているものについては言及していません**: 拡散は、書き込まれたアトラス全体の 26.95% であり、**レンダリングされた図のピクセルの 4.95%** です。その比率は 0.18 倍です。ペイントは大きなチャートに存在し、穴は小さなものに存在するため、拡散されたテクセルは画面空間では安価です。
- **⚑ 合格を決定する欠陥は、フィルではなくペイントによって引き起こされます**。別のマテリアルの色を持つ領域で、どのスペクル統計もそれを検出できません。3 つの方法で 3 つのセッションで 3 つの空間で測定: **91.05% `reference` が 0.99 倍のエンリッチメントで表示され**、ベースレートとほぼ一致します。同じクラスの布地の緑色では **68.46% `reference`** であり、薄いブレード上では表面自体のペイントされたテクセルが **18.77%** で汚染されており、拡散フィルの **5.55%** と比較されます。フィルは、最も近いペイントされた隣接要素から正しくソースを取得します。そして、その隣接要素はすでに間違っています。ブレンド自体は、ドキュメント化されていない 2 つのバンド分割 (`M + gaussian_blur_σ16(B − M)`) であり、同じポイントで **4 つの代替案のうち最悪のもの** を測定します。
- **各ビューは独立していないため、すべてのブレンディング修正に制限があります**。欠陥のある領域ごとに、**2 つ以上のカメラが寄与している面の 100% は、すべて 90° の範囲内にあります** (中央値は 45°)。欠陥のある面の 21% は、1 つのカメラでのみ確認されます。ほぼ同一の制御下にある隣接するビューが同時に失敗するため、フォトグラメトリで公開されているマルチビューの利点は、そのまま転用できません。
- **このルート上のすべての再構築は、中空の二重壁シェルであり**、壁は約 2 ボクセルです。1 つのボクセルに対して有効な体積述語はありません。
- **プレートは名前のないマテリアル境界で異なり、その規範が重要なポイントです** (2026-08-16)。内側のメッシュへのワープは、すべての 8 つのビューでシルエットの中央値である 1.2〜3.0 に対して、**3.5〜11.1 ピクセルの中央値** で測定されました。ディレクターが円で囲んだすべての残余領域 (袖口、手、ブーツの上部) は、生成プロンプトでは名前が指定されていないマテリアル接点です。⚠ **2026-08-17 に修正され、その修正により結果がより明確になりました**。以前は「記録されたプロンプトには 6 つの要素が含まれています」と記述されていましたが、測定したところ、2 つ異なるファイルを結合していることがわかりました。ツインを生成したワークフローでは、グリップを除いて **17 のうち 16 個** が名前が指定されており、*ブラシプロファイルデフォルト* では 6 個の名前が指定されています。どちらも真実であり、文にはそれらのうち 1 つの誤った主張が含まれています。重要なのは、グリップ、ガントレット、グリーブ、手が **16 フレーズのプロンプトに 0 回** 登場することです。なぜなら、**それらに対する要素が規範にまったく存在しないからです**。完全なプロンプトでも、指定されていない手について名前を付けることはできません。✅ **2026-08-17 に終了**。表面リストは確認され、入力され、**24/24 が承認されました**。ゲートは現在、それを網羅していないプロンプトを拒否します。
- **有効なテクセルの 4.65〜5.57% は、フラットリングカメラでは見ることができない表面です**。すべてのビューで深度ゲートに失敗し、どの投影ルートでもペイントすることはできず、出荷されたパイプラインは、暗いマークを作成した島を意識しないフラッドでそれを覆いました。修正ではなく、ポリシー (中立的なマテリアル、ブラシ、または受け入れ) が必要です ([E49 レポート](docs/experiments/E49-finish-and-cap-report.md))。
- **承認されたグレードのシート上の平坦な色のポリゴン** は、ディレクターが指定した唯一のオープンクラスです。⚠ **フィルパス仮説は誤りであることが証明されました (2026-08-17)**。孤立したフィルは、欠陥で自身のベースレートよりも低い値を示し、パッチは通常のペイントされたテクセルの 90〜99% に存在し、同じ欠陥が、その原因とされている修正前のアトラスからレンダリングされたものにも存在します。代わりに、そのソースにトレースすると、レンダリングビュー自体のツインはその部分でクリーンであり、**別の** ビューが 115 個の欠陥ピクセルのうち 97 個を占め、0.68 の対比率に対して 0.60 です。角度のあるパッチは **散乱アーティファクト** であり、色はすでに名前が付けられている表面での実際のクロスビューの不一致です。したがって、「欠陥はツインにある」という理由でツインの再生成を行うことは正当化されません。
⚠ **そして、このページで提案された修正も誤りであることが証明されました (2026-08-17)**。「ターゲットビューを優先するコンポジターが、範囲内の修正であり、コストはかかりません」と記述されていました。コンポジターはすでに存在し、デフォルトになっていました。記録された 1 つの実行からの静止画でフラット分類器と比較すると、ターゲットファーストは、名前付きのターゲット (38 → 40) でカウントを増加させ、他の 2 つ (23 → 64, 36 → 110) でも大幅に増加させ、より接続性が高まります。そのメカニズム: **形状が所有権であり、色はそうではありません**。オリーブはビュー 6 の表面のペイントであり、ビュー 6 はそれを正しくペイントしています。したがって、ターゲット 6 (ターゲットファーストとは *ビュー 6 を優先する* こと) では、ポリシーはまさに欠陥を構成するペイントを最大化します。**所有権ポリシーは、正しく属性が付けられた表面でのクロスビューの色の不一致を修正することはできず**、それによってファミリー全体ではなく、その一部だけが廃止されます ([E52](docs/experiments/E52-target-first-flats-ruling.md))。残っているのはペイントに関する問題であり、1 回の生成で解決できます。*修正ルールに従って保持された、置き換えられたテキスト: 「単一の三角形サイズの孤立した島は、侵食されていないシルエットを使用して境界に隣接するツインサンプルからフラットフィルされます」*

## このリポジトリはどのように実行されますか？

この分野は、パイプラインと同様に、その結果を生み出すものであり、それには理由がある。以前の段階では、10回のセッションを実施し、各セッションでそれぞれの成果を評価し、次のセッションでその結論が確立された事実として読まれるようにした。しかし、この一連の流れの中で検証可能なものは何もなかった。

- **作業前に仕様を定め、作業後に報告を行い、最後に決定を下す** — そして、実験を設計するセッションは、決して自身の結果を評価しない。56件の実験が[記録](docs/experiments/)に保存されている。
- **修正は、それを覆した測定値の隣に配置され、静かに削除されることはない。** 最初の段階だけで、6つの既存の主張が虚偽であることが証明され、そのすべてが現在でも、それらに取って代わるものと一緒に閲覧できる。
- **失敗は、その理由とともにリポジトリに残る。** [`tools/superseded/`](docs/tools.md) はアーカイブではない。誰でもこれらのツールを実行し、同じように失敗する様子を観察することができる。
- **否定的な結果は完全な成功であり、数値に近づけるのではなく、報告され、完了として扱われる。**
- **テストは、コードに触れるコミットと連動する** — 2つの環境で1338件の合格、1284件の隔離された環境でパス制限付きCIが実行される。
- **記録は検索可能である。** 全体を通してSQLite + FTS5インデックスを使用し、4つの側面で検証されている。これにより、文章に誤りがあった3つの箇所について、記録自体を数えることで、決定の回数を特定することができた。

## ライセンスの位置

すべての段階でローカルに実行され、商用利用においても問題がない：SDXL (OpenRAIL++)、MV-Adapter (オープン)、open3d (Apache-2.0)、spandrel (MIT)、RealESRGAN anime6B (BSD-3)、Blender、numpy、scipy、trimesh。

意図的に除外され、その理由も明記されている：**nvdiffrast**（非商用 — ここでは構造的なトリップワイヤーによって強制されており、認証によるものではない）、**Hunyuan3D-Paint**（EU、英国、および韓国でのライセンスが無効）、**MVPaint**および**TEXGen**（ライセンスが全くない）、および**UltraSharp / SUPIR / StableSR**（非商用のアップスケーラー）。

**主張の境界は明示されており、発見されるのを待つことはない。** これは[記録されたルート]を記述するものであり、上記の図にある段階から画像から3Dへの変換へと進む。それよりも前の候補となる粘土準備ホップは、現在、このリポジトリがまだ検証していない利用規約を持つクローズドクラウドAPIで実行されているため、ここにあるライセンスの主張は、その粘土から作成されたアセットには適用されない。これは未解決の問題であり、それを解決するための明確な方法がある：ライセンスに準拠したローカルモデルは**Qwen-Image-Edit (Apache-2.0)**であり、**FLUX.1-Kontext [dev] は、nvdiffrastと同じ理由で除外されている** — 非商用の重み。どちらもスタジオのモデルカタログと比較して検証されており、その理由は[コンセプト準備](docs/concept-prep.md)に記載されている。

## 信頼と脅威モデル

facetは完全に自分のマシン上で実行される — すべてのツールは、コマンドラインで指定するパスに対して起動するスクリプトであり、したがって重要な質問は、「このアプリは何の権限を要求するか」ではなく、「これらのスクリプトがあなたのマシンに何をするか」である。測定によって回答され、すべてのスイープは再実行可能であり、完全なポリシーは[SECURITY.md](SECURITY.md)にある：

- **アクセスされるデータ:** ローカルディスク上のメッシュ、テクスチャ、画像、およびJSONファイル。コマンドラインで指定するパスに保存されている。さらに`docs/index/facet.db`も含まれるが、これは*派生したもの*であり、このリポジトリのファイルとしてすでに存在していたものではなく、`facet_index.py build`によって最初から再生成される。
- **アクセスされないデータ:** 認証情報は一切使用しない。ここではトークン、キー、またはパスワードを読み込んだり、保存したり、送信したりするものはなく、それらはツリーに存在しない — プロバイダーのプレフィックスが付いたキー、GitHub PAT、Slackトークン、AWSキーID、秘密鍵ブロック、ベアラートークン、およびインラインの`api_key`/`password`割り当てについてスキャンされ、**一致するものはない**。認証情報のようなファイルも追跡されていない。
- **テレメトリーは行われない。** 収集も送信もしない。オプトアウトする必要がないのは、オプトアウトするものが何もないからである。
- **ネットワークからのデータ送信:** 2つのツールがソケットを開く — `restylize_views.py`と`texpass_brush.py` — そしてどちらもComfyUI HTTP APIの`--host`に接続し、**デフォルトは`127.0.0.1:8188`**である。それ以外のものは、`tools/`の中に含まれていても、ネットワーク呼び出しを行わない。
- **権限:** 通常ユーザー。昇格、サービスインストール、システム設定またはレジストリへの書き込みは行われない。

３つの鋭い点が明らかになる一方で、単に安心感だけを列挙したセキュリティに関する注意書きは脅威モデルではないため、それらは主張されることはありません。**ファイル操作はサンドボックス化されていません**（ツールは、その引数で指定された場所に書き込みます）。**多くのツールやドキュメントには絶対パスが組み込まれています**—26個のファイルに114件の記述があります。これは秘密情報ではなく、単一のマシンの構成を明らかにするものであり、ほとんどのツールが変更なしで他の場所で実行されない理由でもあります。そして、**予期しないエラーは、未公開の研究スクリプト内でPythonのトレースバックとして表面化します**。ゲートはありません（`--debug`）。意図的な停止は、それをトリガーした測定値を伝達するメッセージです（`ANDON:`）。これが研究用具の契約であり、[SHIP_GATE.md](SHIP_GATE.md)には、それが十分でなくなる正確な時期が記録されています。これは、２つのコマンドに関して、インストール時に0.2.0で発生しました。`facet-index`と`facet-mcp`はそれぞれ、`0`（正常）/ `1`（ユーザーエラー）/ `2`（実行時エラー）を返します。そして、[E22](docs/experiments/E22-ruling.md)以降、トリガーされたゲートまたは失敗したステップ（`verify`）に対しては、**`4`（拒否）**となり、これはツールが動作し、実行時エラーではなく、続行しないように指示していることを意味します。これらすべては、トレースバックの代わりに、次のステップを示す構造化されたエラーメッセージで拒否されます（[E21](docs/experiments/E21-cli-contract-report.md)）。

**And the gates in those two commands are no longer deletable.** Every ANDON in what
facet installs `raise`s; a bare `assert` is a statement `python -O` removes silently,
and 87 of this repo's gates were removable by an environment variable until E22
converted them. Measured before and after on the same gate, in four interpreter modes.
**And since [E23](docs/experiments/E23-route-gates-report.md), neither are the gates on
the route that produced the four accepted assets** — its **57 sites across twelve
tools**, converted as a pure move on files no test had ever executed, each one now
refusing under `-O` and `PYTHONOPTIMIZE=1` as well as under a normal interpreter.
**And since [E25](docs/experiments/E25-ruling.md) the class is closed.** Its **133 sites
across 43 files** — the measurement instruments that produced the evidence for the four
accepted assets above — convert the same way, bringing the total that `raise` to **278**.
Exactly **one** bare ANDON `assert` remains anywhere under `tools/`:
`superseded/texpass_thin_mask.py`, which is **never** converted, because those tools are
kept so anyone can run them and watch them fail the same way. That remainder is pinned
**by name** in the test suite, so a future sweep cannot tidy it away without editing the
test on purpose.

**サポート状況：** このリポジトリはオープンな環境で開発され、１つのハードウェア構成で、１人のディレクターと、交代するアドバイザーと実行者のセッションによって行われます。`main`のみがサポートされている状態です。リリースチャンネルはなく、バックポートポリシーもSLAもありません。代わりに存在するものは記録であり、すべての主張はそれを生成するコードの隣に配置され、[docs/experiments](docs/experiments/)には、それぞれの仕様、レポート、および判断が含まれています。

## 要件

Blender 5.x、Python 3.11+（`numpy`、`scipy`、`trimesh`、`open3d`、`Pillow`、`spandrel`、`torch`）。インペイントブラシを使用するには、ローカルのComfyUIインストールが必要です。RTX 5090で開発されました。生の速度よりもVRAMの余裕が重要です。

CIは、スイートの隔離されたサブセットを**ubuntu-latest / Python 3.12**で実行し、固定されたインストール（`.github/workflows/ci.yml`）を行います。アーティファクト層には、記録されたツリーが必要です（`E:\AI\training`）。これらはgitには含まれていないため、CIは設計上、それらを非選択にします。ローカルでは、`python -m pytest`がすべての**1338**個のテストを実行し、`python -m pytest -m "not artifacts"`がCIで再現される**1284**個のテストを実行します。

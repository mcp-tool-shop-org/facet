スタイルは、テクスチャ空間内のアセットに適用されます。ビューごとにペイントして後でつなぎ合わせることはありません。形状を強調した粘土のコンセプトをパイプラインに入力すると、そのメッシュのスタイライズされた参照から色を取得したテクスチャ付きメッシュが出力され、参照では見ることができなかった部分は、マスク処理されたインペインティングブラシとサーフェスを認識する膨張によって補完されます。

この問題の両方の側面を表す名前です：ポリゴンと、それらが保持する必要がある面。

## インストール

パイプライン自体は、入力したパスに対して実行する一連のローカルスクリプトです。リポジトリをクローンし、[Getting Started](https://mcp-tool-shop-org.github.io/facet/handbook/getting-started/) を参照してください。

**2つのサーバーがパッケージとして提供されます**。1つはレコードインデックスで、アシスタントが証拠の追跡を読み込む代わりにクエリを実行できるようにします。もう1つは、**v0.4.0 以降では測定サーバーです**。数か月かけて測定された2つのアセットは、単一のコードパスを経由します。

```bash
npx @mcptoolshop/facet               # the record index; zero-prerequisite, no Python needed
pip install facet-mcp[measure-full]  # + the measurement tools and their instruments
```

`facet-mcp` は、レコード上の stdio MCP サーバーであり（6つのツールがあり、そのうちの1つが拒否的な健全性サーフェスとして機能する4脚検証）、`facet-index` はインデックス自体です（`build` / `verify` / `q` / `claims`）。どちらもチェックアウト内から実行します。`--db` は別のインデックスの名前です。

### 測定サーバー - v0.4.0 で新機能

`facet-measure` は、比較の**数値的な側面**を処理し、出力が良好かどうかは判断しません。すべてのペイロードには、サーバーバージョン、インストルメント自体のファイルハッシュ、および構成ハッシュが含まれており、`measure_report` は不一致がある場合の比較を**拒否します**。これは、このシステム全体の存在意義です。

**動詞**を実行することで検証され、`--help` を実行するのとは異なります。制御メッシュは、チェックアウトされていないマシン上で786,432個の面と完全なアイデンティティエンベロープを返します。

**結果は1つの要素に依存し、それはPythonのバージョンです:**

| お使いの Python | `[measure-full]` を使用すると |
|---|---|
| **3.11 / 3.12** | **8つのツールすべて**が利用可能になります。`open3d` は PyPI からインストールされます。 |
| **3.13** | 4つのツール：`mesh_stats`、`mesh_topology`、`measure_report`、`anchor_check` |

`open3d` 0.19.0 が最新の*リリース*であり、cp38〜cp312 ホイールを **sdist なし** で公開します。そのため、Python 3.13 では PyPI にインストールできるものがありません。追加機能は、それを `python_version < "3.13"` の背後に配置するため、そこでインストールが**成功**し、4つのジオメトリツールが、必要なものを名前で示す **`4` REFUSED** を出力するようになります。完全なインストールの失敗とは異なります。

**Python 3.13 で8つすべてを取得するには**、Open3D は現在の cp313 ホイールをローリング開発チャンネルに公開します。コマンドラインで直接 URL を使用しても問題ありません。ただし、これは公開されたパッケージメタデータ内でのみ禁止されています。

```bash
# Linux — stable filename, no build hash
pip install https://github.com/isl-org/Open3D/releases/download/main-devel/open3d-0.19.0-cp313-cp313-manylinux_2_35_x86_64.whl
```

⚠ **Windows および macOS では、開発ホイールのファイル名には `+<sha>` が付加されます**（執筆時点では `open3d-0.19.0+63e30be-cp313-cp313-win_amd64.whl`）。また、名前は `main` の変更に合わせて変更されます。したがって、[the `main-devel` release](https://github.com/isl-org/Open3D/releases/tag/main-devel) でアセットをリストし、現在のものを選択します。**このパイプライン自体の Open3D に依存する数値が測定されたのは、このビルドに対してです**。これは、比較可能性の境界線であり、アイデンティティエンベロープはインストルメントのハッシュを記録し、その依存関係ではありません。[E31](docs/experiments/E31-ruling.md)。

*v0.3.1 までのホイールには2つの `.py` ファイルが含まれており、測定ツールは含まれていません。そのため、インストールされた測定サーバーは実行するものがありませんでした。これは4回のリリースにわたって誰にも気づかれませんでしたが、このリポジトリ自体がチェックアウトであるためです。ツールはビルドされた場所で機能し、他の場所に存在したことはありませんでした。*

⚠ **`pip install facet-mcp` は v0.3.0 までのすべてのリリースバージョンで破損しており、v0.3.1 で修正されています**。ホイールは `facet_index` をトップレベルモジュールとしてインストールするため、v0.3.0 およびそれ以前のバージョンでは、レコードの位置を `<venv>/Lib` に対して解決していました（これは、コーパスもインデックスも含まれていません）。また、`build`、`claims`、および `q` は `--db` なしで失敗しました。**v0.3.0 またはそれ以前のバージョンを使用する場合は、上記の `npx` バイナリを使用してください。**

v0.3.1 以降では、ルートはそれを前提とするのではなく、**レコードが存在するかどうかをテストすることによって解決されます**。どちらかのコマンドをチェックアウト内から実行すると、見つかります。他の場所から実行すると、**`4` REFUSED** を出力し、試した両方のディレクトリと検索した両方のマーカーの名前を表示します。`$FACET_INDEX_DB` は現在、両方のコマンドによって読み取られ、どの*インデックス*を使用するかを選択しますが、どの*コーパス*を使用するかは選択しません。`main` からビルドされ、クリーンな venv にインストールされたホイールで測定されました。[E24](docs/experiments/E24-ruling.md)。

*このブロックは2回修正されました。最初に `pipx install facet-mcp # または Python パッケージを直接`, until v0.3.0's read-back ran a **verb** instead of `--help` と記述されていました。次に、ホイールは「 `q` および `claims` に対してのみ機能する」と記述されていましたが、**`claims` も機能しませんでした**。これは E24 が実行して確認したものです。両方の修正は [known-defects.md](docs/known-defects.md) に測定結果とともに記載されています。*

**4つの承認されたアセット、4つの被験者クラスにわたって、クレジットはゼロです**。それぞれが、ディレクターによって独自のズームで評価されました（GLB 上またはフルサイズのシート上）。メトリックがしきい値を超えたわけではありません。

| 被験者 | クラス | 承認済み | 参照 / ブラシ / 膨張 |
|---|---|---|---|
| **Character (W3)** | ヒューマノイド | [2026-08-04](docs/experiments/E08-ruling-gate0.md) | 68.8 / 4.2 / 27.0 |
| **Galleon** | 車両、細いリギング | [2026-08-05](docs/experiments/E04-ruling.md) | 36.89 / 6.87 / 56.24 |

| **Longsword** | 小道具、ほぼ2D、グレーのグラデーション | [2026-08-08](docs/experiments/E14-ruling.md) | 45.25 / 2.07 / 52.68 |

共有されるのは有効なテクセルであり、**それらは被験者間で比較できません**。船はほとんど自身を目の高さから隠し、動物は半分を隠します。それぞれを独自の事前に登録された範囲の上限と比較して評価すると、**86〜93%** になります。行間の違いはジオメトリであり、回帰ではありません。[完全な数値と分母](docs/handbook/subjects.md)。

**これはパイプラインであり、1つのキャラクターを生成するものではありません**。8つの名前付き要素で仕様に矛盾させると、プロンプトが **8/8** で勝利します。中央値 ΔE は 46.3 であり、5つの保持されたコントロールでは 6.2 です。ただし、図は同じ人物です。構造はメッシュと制御によって保持され、名前付き属性はプロンプトに依存します。

**プロジェクターに関する議論は2026年8月16日に終了しました**（[E45](docs/experiments/E45-warp-and-aov-kickoff.md)–[E49](docs/experiments/E49-finish-and-cap-kickoff.md））。
8つのプレートは、以下の要素で構成されます。境界×向き×可視性重みを使用して、各ビューのバンドルから再構築され、アトラスがレンダリングされます。これにより、このルートで初めてディレクターの承認基準を満たし、さらに2つの弧にわたって2回満たされました。これは、プレートの色を損なっていたルートを持つ既存のアトラスとは対照的です。この処理を実行したチェーンは`tools/`にあります（`emit_view_aovs`、`s3_composite`、`flow_estimate`、`s3_run`、`s3_sheet`、`atlas_from_aovs`、`twin_mesh_warp`）。主に外部レビューチャンネルを通じてビルドされ、指定されたキャリブレーションの主張は「17回中17回」成功し、そのすべてがここで検証されました。これは、信頼できるビルドを実行する前に実行されます。

**カノンはデータであり、支出を制御します（2026年8月17日）。** 17個の要素を持つアイデンティティ仕様、16個の要素を持つツインを生成するワークフロー、および新しい実行で使用されるデフォルトプロファイルには6個の要素が含まれます。これらは互いに関連付けられていないため、4つの弧で構成された後続の処理において、ソースで誤っていたペイントが修正されました。カノンは現在、「表面」をキーとするデータベースであり、要素リストでは欠落しているものを表示できません。また、null許容の占有領域によって、行に穴が開く可能性があります。そして、`canon_gate`は`restylize_views`と`texpass_brush`の中で実行され、出力ディレクトリが存在する前に処理されます。承認されたカノンを網羅していないプロンプトを持つ生成は拒否され、何も書き込まれません。

```
canon_gate 1.0.0  census  (occupancy is not ratification)
subject      named   occupancy   ratified   prof_hit surfaces
W3              19       24/24      24/24       5/19 canon/w3.surfaces.json
GALLEON         13           -          -      11/13 NONE
DRAGON          11           -          -      10/11 NONE
LONGSWORD        5         5/5        5/5        4/5 canon/longsword.surfaces.json
E10-LAYER        1           -          -          - NONE
LOGO             0           -          -          - NONE
```

`prof_hit 5/19`は、**意図的に破損したままのサンプル**です。これは、実際に使用されるライブデフォルトであり、最初の`--profile character.json`は停止するように設計されています。文字列を修正すると、証拠が削除されます。

**ゲートの境界は、発見に任せるのではなく、明示的に定義されています。** これは、対象プロンプトに承認されたカノンのフレーズが含まれているかどうかを確認します。言い換え、各ビューのステム、未承認のドラフト、表面ファイルを持たないサブジェクト、または名前付きのマテリアルが正しい表面に着陸したかどうかは確認しません。4つのサブジェクトにはIDENTITY.mdがありますが、表面JSONはありません。これは、参照をウォークせずに生成されたのではなく、未完成のままになっているためです。

## ルート

```
  styled 2D concept ╌╌► clay prep ╌╌╮   ← CANDIDATE hop, walked once. Not a route
                                    ╎     stage. Everything below it is the route.
                                    ▼
form-exaggerated clay concept ──► image-to-3D ──► weld ──► density allocation
                                                             │
                    cull what no camera can see ◄────────────┘
                                 │
                                 ▼
       twins, generated from THIS mesh ──► project ──► brush the holes ──► fill
```

段階ごとに、その理由とともに：**[ハンドブック](docs/handbook/index.md)**。

**破線で描かれたホップは新しく、意図的に実線ではありません。** ルートの最初のボックスには常に「粘土コンセプト」と表示されており、これまでここにはそれを作成するものはありませんでした。すべての粘土は手作業で到着し、その過程でハッシュ化されていました。現在、コンセプトから粘土へのツールが存在し、最初のペアがフルサイズでウォークされました。ポーズ、リストラップ、ベルトのメダリオン、および破れた裾がすべて再現されています。たてがみは再現されませんでした。カラーリークは、フレーム全体で**C\* p99.9 = 13.15**と測定され、シームレスな非彩色の背景が使用されました。**このペアでは、メッシュがより良く改善されるかどうかを示すことはできません。** これは、それを促進する唯一の質問であり、そのため、証拠を記録したまま候補として残ります：**[コンセプト準備](docs/concept-prep.md)**。

## それがどのように機能するか

6つの発見があり、それぞれが実験の対象となり、また、それを生成したサブジェクトを超えて一般化されます。[詳細な説明と測定値は](docs/findings.md)にあります。

- **まず形状を、次にスタイルを。** 再構築ツールは、表面ノイズをジオメトリとして解釈します。意図的に誇張された平面を持つ、クリーンで彫刻のような粘土は、様式化されたスプライトよりも優れたトポロジーで再現されます。様式化されたツインは並行して生成され、カラー参照になります。
- **顔をフレームに収め、顔を取得します。** バストクロップを行うと、頭部のポリゴン数が**3.1〜4.5倍**増加し、その違いは構造的です。分離されたまぶた、眉の溝、モデル化された鼻腔などであり、単なるぼかしではありません。
- **ツインはキャラクターではなく、メッシュに属します。** ツインを複数のメッシュで使用すると、カバレッジが**62%から22.7%**に低下するため、腕がモデルの横にある空中に投影されます。テクスチャを適用する予定のメッシュから、毎回ツインを生成してください。
- **アイデンティティはプロンプトに属します。** プロンプトで名前が指定されていないカノンの要素は、偶然に現れ、同じように消えます。これは、金色の膝プレートが、破損したControlNetのノイズを通じてのみ画像に表示されるようになったときに測定されました。
- **閾値ではなく、ジオメトリを要求します。** キー付きマスクを正確なレイキャストシルエットに置き換えると、有効なテクセルにおける参照カバレッジが**28.4%から39.1%**に増加しました。これは厳密に追加であり、拡散やGPUは使用しません。コーナー中央のキーイングはここで3回失敗し、廃止されました。
- **カメラで見ることができないものをアトラスとメッシュから削除します（ただし、メッシュからは決して削除しないでください）。** アトラステクセルの49%が外部からは見えません。これらの面を除外すると、補間が68%削減されます。除外するのではなく削除することで、単に検出可能であるだけでなく、失敗を不可能にします。

## 解決されていない問題

名前と測定値は、脚注ではなく、最初のページに記載されています。[すべてコード内にあります](docs/known-defects.md)。

- **一部の表示されるサーフェスマップは、ベイク処理で書き込まれないアトラス空間にマッピングされ**、画像にそのまま適用されたデフォルトの黒としてレンダリングされます。Blender のベーカーはテクセル中心サンプリングを使用するため、どのテクセル中心にも重なっていない三角形は空のままになります。開発者はこの仕組みに名前を付け、ビルドから 2 週間後に修正をマージしました (https://projects.blender.org/blender/blender/pulls/161752)。これは単一のオブジェクトではなく、ルート全体の特性です。あるアセットで測定し、**他の 4 つのアセットでは測定していません**。
- **ブレードバンドは、すべての 8 台のカメラでステージ 1 の参照の 0.00% を占めます**。グレーの背景に配置された金属が、キーの色と正確に一致します。この組み合わせにより、55.72% が補正されます。
- **ストロークの継ぎ目は滑らかではありません**。プロベナンス境界は、通常のテクスチャの変化よりも **5.5 倍** 大きく変化し、ディレクターが指定した領域は **9.5 倍** の変化を示します。
- **拡散によって、関連性のないアトラスアイランド間で色が混ざります**。拡散されたテクセルの 74.9% が、高さ 1.0 の図で平均 0.177 だけ離れた別の島から色を取得します。⚠ **この割合はアトラスのテクセルに関するものであり、カメラが見ているものについては言及していません**。拡散は、書き込まれたアトラス全体の 26.95% であり、レンダリングされた図のピクセルの **4.95%** です。その比率は 0.18 倍です。ペイントは大きなチャートに存在し、穴は小さなチャートに存在するため、拡散されたテクセルは画面空間では安価です。
- **⚑ 合格を決定する欠陥は、塗りつぶしではなく、ペイントによって引き起こされます**。別のマテリアルの色を持つ領域で、どのスプークル統計もそれを検出できません。3 つの異なる方法で、3 つのセッションで、3 つの異なる空間で測定しました。**91.05% `reference` が 0.99 倍のエンリッチメントで表示され**、ベースレートとほぼ一致します。同じクラスの布地の緑色は **68.46% `reference`** であり、薄いブレードでは、サーフェスのペイントされたテクセルが **18.77%** 、拡散塗りつぶしの **5.55%** に対して汚染されています。塗りつぶしは、最も近いペイントされた隣接要素から正しくソースを取得します。そして、その隣接要素はすでに間違っています。ブレンド自体は、ドキュメント化されていない 2 つのバンド分割 (`M + gaussian_blur_σ16(B − M)`) であり、同じポイントで **4 つの代替案のうち最悪のもの** を測定します。
- **各ビューは独立していないため、すべてのブレンディング修正に制限があります**。各欠陥領域について、**2 つ以上のカメラが寄与する面の 100% は、すべて 90° の範囲内にあります** (中央値は 45°)。欠陥のある面の 21% は、1 つのカメラでのみ表示されます。ほぼ同じ条件で制御された隣接ビューは同時に失敗するため、フォトグラメトリで公開されているマルチビューによる利点は、そのまま転用できません。
- **このルート上のすべての再構築は、中空の二重壁シェルであり**、壁は約 2 ボクセルです。単一のボクセルに対して有効なボリューム述語はありません。
- **プレートは、名前のないマテリアル境界で異なり、その中心となるのはカノンです** (2026-08-16)。内側のメッシュへのワープを測定した結果、すべての 8 つのビューで **3.5〜11.1 ピクセルの中央値** であり、シルエットの中央値は 1.2〜3.0 です。ディレクターが円で囲んだすべての残存領域 (袖口、手、ブーツの上部) は、生成プロンプトでは名前が指定されていないマテリアルの接合部です。⚠ **2026-08-17 に修正され、その修正により結果が明確になりました**。以前は「記録されたプロンプトには 6 つの要素が含まれています」と記述されていましたが、測定したところ、2 つの異なるファイルを結合していることがわかりました。ツインを生成したワークフローでは、グリップを除いて **17 のうち 16 個** が名前が指定されています。*ブラシプロファイルデフォルト* では、6 つの名前が指定されています。どちらも真実であり、文にはそれらのうち 1 つの誤った主張が含まれています。重要なのは、グリップ、ガントレット、グリーブ、手が、16 フレーズのプロンプトに **0 回** 表示されることです。なぜなら、**カノンにはそれらに関する要素がまったく存在しないからです**。完全なプロンプトでも、指定されていない手について名前を付けることはできません。✅ **2026-08-17 に終了**。サーフェスリストは確認され、入力され、**24/24 が承認されました**。ゲートは現在、それをカバーしていないプロンプトを拒否します。
- **有効なテクセルの 4.65〜5.57% は、フラットリングカメラでは表示されないサーフェスです**。すべてのビューで深度ゲートに失敗し、どの投影ルートでもペイントできず、出荷されたパイプラインは、暗いマークを作成した島を意識しないフラッドでそれを覆いました。修正ではなく、ポリシー (中立的なマテリアル、ブラシ、または受け入れ) が必要です ([E49 レポート](docs/experiments/E49-finish-and-cap-report.md))。
- **承認されたグレードのシート上の平坦な色のポリゴン**。これはディレクターが指定した唯一のオープンクラスです。⚠ **塗りつぶしパス仮説は誤りであることが証明されました (2026-08-17)**。孤立した塗りつぶしの測定値は、欠陥においてそれ自体のベースレートよりも *低い* 値を示し、パッチは通常のペイントされたテクセルの 90〜99% に存在し、同じ欠陥が、その原因とされている修正前のアトラスからレンダリングされたものにも存在します。代わりに、そのソースにトレースすると、レンダリングビュー自体のツインはそこでクリーンであり、**別の** ビューが、対向角度 0.68 に対して 0.60 で、115 個の欠陥ピクセルのうち 97 個を所有しています。角のあるパッチは **散乱アーティファクト** であり、色はすでに名前が付けられているサーフェスでの実際のクロスビューの不一致であるため、「欠陥がツインにある」という理由でツインの再生成を行うことは正当化されません。ターゲットビューを優先するコンポジターが、スコープされた修正であり、コストはかかりません。*修正ルールに従って保持される、置き換えられたテキスト:「単一の三角形のサイズの孤立した島で、境界に隣接するツインサンプルから平坦に塗りつぶされ、侵食されていないシルエットを使用します。」*

## このリポジトリはどのように運用されているか

この分野における知識や技術は、パイプラインと同様に、ある目的のために存在し、その過程で生み出されるものでもある。以前の段階では、10回のセッションを通じて各自が自分の成果を評価し、次のセッションでそれを事実として共有するというプロセスを踏んでいた。しかし、その一連の流れの中で検証可能な点は何もなかった。

- **作業前に仕様を定め、作業後に報告し、最後に結論を出す** — そして実験を設計するセッションは、決して自身の結果を評価することはありません。51件の実験が[記録](docs/experiments/)にあります。
- **修正は、それを覆した測定の横に配置されます**。静かな削除としてではなく。最初のセッションだけで6つの既存の主張が虚偽であることが判明し、そのすべては現在も、それらに取って代わるものと一緒に表示されています。
- **失敗は、その理由とともにリポジトリに残ります**。[`tools/superseded/`](docs/tools.md) はアーカイブではありません。誰でもこれらのツールを実行して、同じように失敗する様子を観察できます。
- **否定的な結果は完全な成功です**。数値に調整するのではなく、報告され、完了します。
- **テストは、コードに触れるコミットと連携します** — 2つの担当者によって1295件のテストが合格し、1241件の隔離されたテストに対してパスベースのCIが実行されます。
- **記録は検索可能です**。4つの要素で検証された、すべての履歴に対するSQLite + FTS5インデックスがあります。これにより、3つの場所で文章が間違っていた結論の数を、記録自体を数えることで特定しました。

## ライセンスの位置

すべての段階はローカルで実行され、商用利用も可能です：SDXL（OpenRAIL++）、MV-Adapter（オープン）、open3d（Apache-2.0）、spandrel（MIT）、RealESRGAN anime6B（BSD-3）、Blender、numpy、scipy、trimesh。

意図的に除外され、その理由も記載：**nvdiffrast**（非商用 — ここでは構造的なトリップワイヤーによって強制されており、認証によるものではありません）、**Hunyuan3D-Paint**（EU、英国、および韓国でのライセンスが無効）、**MVPaint**および**TEXGen**（ライセンスが全くない）、および**UltraSharp / SUPIR / StableSR**（非商用のアップスケーラー）。

**主張の境界は、発見されるのを待つのではなく、明示的に述べられています。** これは[記録されたルート]を記述します — 上記の図にある段階から、画像から3Dへの変換まで。その上流にある候補となる粘土準備ホップは、現在、このリポジトリがまだ検証していない条件を持つクローズドクラウドAPIで実行されているため、ここにあるライセンスの主張は、その粘土から作成されたアセットをカバーするものではありません。これは、それを解決するための明確なパスがある未解決の問題です：ライセンスに準拠したローカルモデルは**Qwen-Image-Edit（Apache-2.0）**であり、**FLUX.1-Kontext [dev] は、nvdiffrastと同じ理由で除外されています** — 非商用の重み。どちらもスタジオのモデルカタログに対してチェックされ、再利用されることはありません。その理由は[コンセプト準備](docs/concept-prep.md)にあります。

## 信頼と脅威モデル

facetは完全に自分のマシン上で実行されます — すべてのツールは、パスを入力して実行するスクリプトであり、したがって重要な質問は、「このアプリは何の権限を要求しますか？」ではなく、「これらのスクリプトはあなたのマシンに何をするのか？」です。測定によって回答され、すべてのスイープは再実行可能です。完全なポリシーは[SECURITY.md](SECURITY.md)にあります：

- **アクセスされるデータ:** ローカルディスク上のメッシュ、テクスチャ、画像、およびJSON。コマンドラインで渡すパスにあります。さらに`docs/index/facet.db`があり、これは*派生したもの*です — これは、このリポジトリ内のファイルではなかったものは含まれておらず、`facet_index.py build`はそれを最初から再生成します。
- **アクセスされないデータ:** 認証情報は一切ありません。ここでは、トークン、キー、またはパスワードを読み取ったり、保存したり、送信したりするものではなく、ツリーにも存在しません — プロバイダーのプレフィックスが付いたキー、GitHub PAT、Slackトークン、AWSキーID、秘密鍵ブロック、ベアラートークン、およびインラインの`api_key`/`password`割り当てに対してスキャンされました。**一致するものはありません**。認証情報のようなファイルも追跡されていません。
- **テレメトリーはありません**。収集も送信もしません。オプトアウトするものがないため、オプトアウトのオプションもありません。
- **ネットワークからのデータ送信:** 36個のツールのうち2つがソケットを開きます — `restylize_views.py`と`texpass_brush.py` — そしてどちらもComfyUI HTTP API（`--host`）に接続します。**デフォルトは`127.0.0.1:8188`です**。その他の`tools/`は、ネットワーク呼び出しを行いません。
- **権限:** 通常のユーザー。昇格、サービスインストール、システム設定またはレジストリへの書き込みはありません。

３つの鋭い点が明らかになる一方で、単に安心感だけを列挙したセキュリティに関する注意書きは脅威モデルではないため、それらは主張されることはありません。**ファイル操作はサンドボックス化されていません**（ツールは、その引数で指定された場所に書き込みます）。**多くのツールやドキュメントには絶対的なローカルパスが組み込まれています**—26個のファイルに114件の記述があります。これは秘密ではなく、単一のマシンのレイアウトを開示するものであり、ほとんどのツールを変更せずに他の場所で実行できない理由でもあります。そして、**予期しないエラーは、公開されていない36個の研究スクリプトにおいてPythonのトレースバックとして表面化します**。ゲートはありません（`--debug`）。意図的な停止は、それをトリガーした測定値を伝えるメッセージ（`ANDON:`）です。それが研究用具の契約であり、[SHIP_GATE.md](SHIP_GATE.md)には、それが十分に機能しなくなる正確な時期が記録されています。これは、２つのコマンドファセットで「インストール」された場合、バージョン0.2.0において、`facet-index`と`facet-mcp`がそれぞれ`0`（正常）、`1`（ユーザーエラー）、`2`（実行時エラー）を返します。そして、[E22](docs/experiments/E22-ruling.md)以降は、トリガーされたゲートまたは失敗した`verify`のいずれかに対して**`4`（拒否）**となり、これはツールが動作し、実行時エラーではなく、続行しないように指示するものです。これらすべては、トレースバックではなく、次のステップを示す構造化されたエラーメッセージで拒否します（[E21](docs/experiments/E21-cli-contract-report.md)）。

**そして、これらの２つのコマンドにあるゲートは、もはや削除できません。** 各ファセットのインストールでは、すべてのANDONが`raise`を保持します。単純な`assert`は、環境変数によって静かに削除されるステートメント`python -O`です。このリポジトリの87個のゲートは、E22で変換されるまで、環境変数によって削除可能でした。同じゲートに対して、４つのインタープリターモードで測定を事前と事後に行いました。
**そして、[E23](docs/experiments/E23-route-gates-report.md)以降、４つの承認されたアセットを生成したルートにあるゲートも同様です**—その**12個のツールにわたる57個のサイト**は、テストが一度も実行されなかったファイルに対して純粋な移動として変換され、それぞれが現在、`-O`と`PYTHONOPTIMIZE=1`だけでなく、通常のインタープリターでも拒否されます。
**そして、[E25](docs/experiments/E25-ruling.md)以降、クラスは閉じられています。** その**43個のファイルにわたる133個のサイト**—上記４つの承認されたアセットのエビデンスを生成した測定機器—は同様の方法で変換され、合計で`raise`となり、**278**になります。
正確には、**1つだけ**の単純なANDON `assert`が、どこかにある`tools/`の下に存在します。
それは**決して**変換されない`superseded/texpass_thin_mask.py`であり、なぜならこれらのツールは誰でも実行して、同じように失敗する様子を見ることができるように維持されているからです。この残りの部分は、テストスイートで**名前によって**固定されており、将来のスイープでは、意図的にテストを編集しない限り、それを削除することはできません。

**サポート状況：** このリポジトリはオープンな環境で開発され、１つのハードウェア構成で、１人のディレクターと、交代するアドバイザーと実行者のセッションによって行われます。`main`のみがサポートされている状態です。リリースチャネル、バックポートポリシー、SLAはありません。代わりに存在するものは記録であり、すべての主張はそれを生成するコードの隣に配置され、[docs/experiments](docs/experiments/)には各々の仕様、レポート、および判断が含まれています。

## 要件

Blender 5.x、Python 3.11+（`numpy`、`scipy`、`trimesh`、`open3d`、`Pillow`、`spandrel`、`torch`を含む）。インペイントブラシを使用するには、ローカルのComfyUIインストールが必要です。RTX 5090で開発されました。生の速度よりもVRAMの余裕が重要です。

CIは、スイートの隔離されたサブセットを**ubuntu-latest / Python 3.12**で実行し、固定されたインストール（`.github/workflows/ci.yml`）を行います。アーティファクト層には、記録されたツリー（`E:\AI\training`）が必要であり、これはgitには含まれていないため、CIはそれらを意図的に選択しません。ローカルでは、`python -m pytest`がすべての**1295個のテスト**を実行し、`python -m pytest -m "not artifacts"`が**1241個のCIで再現されるテスト**を実行します。

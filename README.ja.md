スタイルは**アセットに適用**され、テクスチャ空間内で処理されます。ビューごとに描画され、後でつなぎ合わせることはありません。形状を強調した粘土モデルをルートに与えると、そのメッシュのスタイル化された参照から色を取得したテクスチャ付きメッシュが返されます。参照では見えない部分は、マスクされたインペインティングブラシと、表面を認識した拡大処理によって補完されます。

この問題の2つの側面、つまりポリゴンと、それらが表現する必要がある面を表しています。

## インストール

ルート自体は、入力するパスに対して実行する一連のローカルスクリプトです。リポジトリをクローンし、[Getting Started](https://mcp-tool-shop-org.github.io/facet/handbook/getting-started/) を参照してください。

**2つのサーバーがパッケージとして提供されます**。1つはレコードインデックスで、アシスタントが証拠の追跡を読み込むのではなく、照会できるようにします。もう1つは、**v0.4.0で追加された測定サーバー**です。これにより、数か月かけて測定された2つのアセットは、1つのコードパスを通過します。

```bash
npx @mcptoolshop/facet               # the record index; zero-prerequisite, no Python needed
pip install facet-mcp[measure-full]  # + the measurement tools and their instruments
```

`facet-mcp` は、レコード上の stdio MCP サーバーです（6つのツールがあり、4つの脚を持つ検証ツールは、健全性を確認するためのものです）。`facet-index` は、インデックス自体です（`build` / `verify` / `q` / `claims`）。どちらもチェックアウト内から実行します。`--db` は、別のインデックスを指定します。

### 測定サーバー - v0.4.0で新規追加

`facet-measure` は、比較の**数値的な側面**を処理し、出力が良好かどうかは判断しません。すべてのペイロードには、サーバーのバージョン、インストルメント自身のファイルハッシュ、および構成ハッシュが含まれており、`measure_report` は、不一致がある場合の比較を**拒否**します。これは、このシステム全体の存在意義です。

**verb**（動詞）を実行することで検証され、`--help` を実行するのとは異なります。制御メッシュは、チェックアウトされていないマシン上で、完全なアイデンティティエンベロープを持つ786,432個の面を返します。

**結果は1つの要素に依存し、それはPythonのバージョンです。**

| Python | `[measure-full]` を使用すると |
|---|---|
| **3.11 / 3.12** | **8つのツールすべて**が利用可能になります。`open3d` は PyPI からインストールされます。 |
| **3.13** | 4つのツール：`mesh_stats`、`mesh_topology`、`measure_report`、`anchor_check` |

`open3d` 0.19.0 は最新の*リリース*であり、cp38〜cp312 のホイールを公開しますが、**sdist は含まれません**。そのため、3.13 では PyPI にインストールできるものはありません。追加のパッケージは、それを `python_version < "3.13"` の後ろに配置するため、インストールはそこで**成功**し、4つのジオメトリツールは、必要なものを名前で示して **`4` REFUSED** を出力します。完全なインストールが失敗するのではなく。

**Python 3.13 で8つすべてのツールを入手するには**、Open3D は現在の cp313 ホイールを、継続的に更新される開発チャンネルで公開しています。コマンドラインで直接 URL を使用しても問題ありません。ただし、公開されているパッケージのメタデータ内でのみ使用が禁止されています。

```bash
# Linux — stable filename, no build hash
pip install https://github.com/isl-org/Open3D/releases/download/main-devel/open3d-0.19.0-cp313-cp313-manylinux_2_35_x86_64.whl
```

⚠ **Windows および macOS では、開発ホイールのファイル名は `+<sha>` で終わります**（執筆時点では `open3d-0.19.0+63e30be-cp313-cp313-win_amd64.whl`）。ファイル名は、`main` が変更されると変更されます。したがって、[`main-devel` リリース](https://github.com/isl-org/Open3D/releases/tag/main-devel) でアセットをリストし、現在のものを選択してください。**このルートで使用されている Open3D に依存する数値は、このビルドに対して測定されたものです。** これは、比較の境界線です。アイデンティティエンベロープは、インストルメントの依存関係ではなく、ハッシュを記録します。[E31](docs/experiments/E31-ruling.md)。

*v0.3.1 までのホイールには、2つの `.py` ファイルが含まれていましたが、測定インストルメントは含まれていませんでした。そのため、インストールされた測定サーバーは、実行するものがありませんでした。誰も4つのリリースにわたって気づきませんでしたが、これは、このリポジトリがチェックアウト自体であるためです。ツールは、ビルドされた場所で機能し、他の場所に存在したことはありませんでした。*

⚠ **`pip install facet-mcp` was broken in every released version through v0.3.0, and is
fixed in v0.3.1.** The wheel installs `facet_index` as a top-level module, so up to and
including v0.3.0 it resolved the record's location against `<venv>/Lib` — which holds
neither corpus nor index — and `build`, `claims`, and `q` without `--db` all failed.
**On v0.3.0 or earlier, use the `npx` binary above.**

v0.3.1 以降、ルートは、それを仮定するのではなく、**レコードの存在をテストすることで解決されます**。どちらかのコマンドをチェックアウト内から実行すると、レコードが見つかります。他の場所から実行すると、**`4` REFUSED** を出力し、試した両方のディレクトリと、検索した両方のマーカーの名前を表示します。`$FACET_INDEX_DB` は、両方のコマンドによって読み込まれ、どの*インデックス*を使用するかを選択します。*コーパス*は選択しません。`main` からビルドされ、クリーンな仮想環境にインストールされたホイールで測定されました。[E24](docs/experiments/E24-ruling.md)。

*このブロックは2回修正されました。最初に `pipx install facet-mcp # または Python パッケージを直接 `, until v0.3.0's read-back ran a **verb** instead of `--help` と記述されていました。次に、ホイールは「`q` と `claims` でのみ機能する」と記述されていました。**`claims` も機能しませんでした**。これは、E24 が実行して確認したものです。両方の修正は、[known-defects.md](docs/known-defects.md) に、測定結果とともに記録されています。*

**方法論的な結果は、アセットよりも重要です。** その全体を通して、ControlNetの強度は一度も調整されませんでした。すべての修正は、ある要素に対して力を加えるのではなく、**原因を取り除きました。** 2つのエラーは、アドバイザー自身の仕様の欠陥であり、実行エンジンと外部レビューチャネルによって、クレジットが使用される前に検出され、両方とも記録に名前が記載され、それらを覆す測定値も記載されています。

**プロジェクターに関する問題は、2026年8月16日に終了しました**（[E45](docs/experiments/E45-warp-and-aov-kickoff.md)–[E49](docs/experiments/E49-finish-and-cap-kickoff.md））。8つのプレートは、**再構築され、各ビューのバンドルから、境界×向き×可視性の重みを使用して、アトラスがレンダリングされ、このルートで初めてディレクターの承認基準を満たしました。** これは2回、2つのアークにわたって行われました。その横には、ルートがペイントを破壊していたアトラスが配置されています。プレートは一致しています。それを実行したチェーンは`tools/`（`emit_view_aovs`、`s3_composite`、`flow_estimate`、`s3_run`、`s3_sheet`、`atlas_from_aovs`、`twin_mesh_warp`）にあります。これは主に、20/20の指名されたキャリブレーションの主張が検証され、そのすべてがここで実行され、ビルドが信頼される前に検証された、外部レビューチャネルを通じて構築されました。

**カノンはデータであり、支出を制御します（2026年8月17日）。** アイデンティティの仕様では17の要素が指定され、ツインを生成したワークフローでは16の要素が指定され、プロファイルデフォルトでは、新しい実行で使用する6つの要素が指定されました。これらは互いに関連していません。したがって、4つのアークで、ソースで間違っていたペイントの下流の構成が修正されました。カノンは現在、**サーフェス**をキーとするデータベースであり、要素リストでは何が欠けているかを示すことはできず、null許容の占有者は、空いている部分を行にします。そして、`canon_gate`は、出力ディレクトリが存在する前に、生成を生成するツールの**内部**で実行されます。カノンに準拠していないプロンプトを持つ生成は拒否され、何も書き込まれません。

**これはルーターであり、フェイルクローズです。** 被験体をカノンファイルに解決し、プロンプトを**両方向**に適用し、範囲を伝達します。**支出を生成し、カノンが与えられていないツールは、静かに進行しません。** 実際にカノンを持たない被験体に対する回避策は、人口調査に基づいており、カノンを持つ被験体によって使用することはできません。`--no-canon --subject GALLEON`は進行し、自身を宣言します。`--no-canon --subject W3`は、W3にサーフェスがあるため、**拒否されます。** これは、慣例ではなく、構造によってチェックボックスを閉じます。そして、それは重要です。なぜなら、前の形状（`if args.canon:`）では、出荷されたPowerShellドライバーがゲートを静かに通過することを許可していたからです。

**2番目の方向は、実際の欠陥を検出するものです。** プロンプトがカノンを*含んでいる*ことを確認すると、プロンプトが薄いことがわかります。プロンプトの*すべて*がカノンであることを確認すると、キャラクターが持っていないものを指すフレーズが見つかります。そして、それはライブデフォルトに1つありました。**`gold necklace`**。このリポジトリは、すでにそれが金のベルトのメダリオンを誤って名前付けていることを測定していました。**「そして、その要素は偶然生き残ります。」** そのフレーズが追加された包括的なプロンプトは、現在`missing: 0`を返し、それでも拒否され、その句が名前で示されます。

```
canon_gate 1.0.0  census  (occupancy is not ratification)
subject      named   occupancy   ratified   prof_hit surfaces
W3              19       24/24      24/24       5/19 canon/w3.surfaces.json
GALLEON         13           -          -      11/13 NONE
DRAGON          11           -          -      10/11 NONE
LONGSWORD        5         5/5        5/5        4/5 canon/longsword.surfaces.json
E10-LAYER        1           -          -          - NONE
LOGO             0           -          -          - NONE
A1              10       16/16      16/16      10/10 canon/a1.surfaces.json
```

`prof_hit 5/19`は、**意図的に壊されたままになっているサンプルです。** これは、実行が実際に使用するライブデフォルトであるため、最初の`--profile character.json`は停止するように設定されています。文字列を修正すると、証拠が削除されます。

**そして、カノンを持たない4つの被験体は、自分で歩き回ることはないため、ワークシートがあります。** ワークシートは、被験体の*種類*が示すすべてのサーフェスを出力します。したがって、空いている部分は、誰かが名前を付ける前に、行になります。IDENTITY.mdをインベントリに変換し、ジョイントをペアとして伝達して確認し、各ビューの範囲スロットを予約します。これは、**構造的に占有者を埋めることができず、** それがテストされているプロパティです。サーフェスがすでに割り当てられている状態で、毒性のあるフレーズが到着すると、書き込まれません。カノンの生成は、人間が参照を歩くことであり、ワークシートは、その歩みを安価かつ完全にします。

**ゲートの境界は、発見されるのを待つのではなく、明示的に定義されている。** これは、両方向で、特定の範囲内で、承認された標準的なフレーズをチェックする。言い換えや同義語はチェックしない。意味的な一致は、モデルをゲート内に配置することになり、このリポジトリはその原則に反するため、許可されない。また、ビューの範囲が宣言されるまでは、個々のビューの要素もチェックせず、名前付きのオブジェクトが正しいサーフェスに配置されているかどうかもチェックしない。スコープスロットが存在し、そのサーフェスリストは空である。それらを埋める作業は、オブジェクトを配置する作業と同様に、手動で行う必要がある。4つのオブジェクトには、IDENTITY.mdファイルがあり、サーフェスJSONファイルはない。これは、参照をたどって生成するのではなく、未完成のままになっている。

**プロンプトが保持できる要素の数は測定され、標準に達しない。** 既存の文献では、追加された各プロンプト要素に対して、要素が表示されるかどうかという点において、コストが設定されており、その範囲は我々のものよりもはるかに小さい。そのため、Opusの担当者は、すでに支払いが完了しているアセットでそれを解決できるかどうかを尋ねた。**しかし、それは不可能であり、その理由は構造的なものによる。** コーパス内のどの要素も、その周囲の要素数が変化し、かつ存在しない可能性がある状態で、フレーズを一定に保つことはできない。彼らが提供するのは、一方的な制限であり、1つのカメラで、バイト単位で完全に制御された5つのプロンプト、マスク、シードから始まる。要素の階層は**10 → 17**であり、10で存在していた要素はすべて削除され、*ゼロ*の要素数の変化でアイデンティティが変化すると、完全なキャリブレーション間隔が移動する。**W3の標準では19が必要であり、コーパスは決してそれに達しない**（[E55](docs/experiments/E55-density-vs-identity-report.md)）。スタジオは、3つの数値を出力し、それらは統合される。24のプロンプトサーフェス、25の必要なチェック、19のユニークな要素。したがって、要素数の測定値に対して、カバレッジ数は決して引用されない。

**6番目のオブジェクトは、別の質問に答えるために投入され、否定的な結果（2026-09-22）を返した。** `ai-rpg-stage`のハーバーガードは、ペイント*後*に何が起こるかをテストするために再構築された。ポーズとプロップが設定され、正常に再構築された後、**自動リギングに失敗する。** 4つの候補原因は、議論ではなく、測定によって排除された。テクスチャのない入力、コンポーネント数、メッシュのトポロジー、ポーズ。**識別子は特定されていない**。[`canon/BASE-FIGURE.md`](canon/BASE-FIGURE.md)には、試された内容の表が記載されており、原因を特定しない。なぜなら、このリポジトリが特定した唯一の原因である、腕と胴体の分離は、同じ時間内に、より広い分離で失敗した真のAポーズによって否定されたからである。

**その結果、サイズコントラクトと2つのゲートが作成された。** このルートで作成されたすべての再構築は、**最も長い軸で1.002**に正規化される。これは、関連性のない4つのアセットで、小数点以下3桁まで測定されたものである。したがって、プロップメッシュは実際のスケーリングを持たず、そのままロードされたヒーターシールドは、1.8mのドアである。プロップの実際のサイズは、現在、ミリメートル単位で一度だけ宣言され、ファイルと一緒に保存され、信頼するのではなくチェックされる（`tools/prop_scale.py`、シーンユニット**1.0 = 1.8 m**）。プロップが1つの頂点でオブジェクトに*接触*している場合、その接触は保持されない。したがって、接触ゲートは、最小距離**と接触面積**（`tools/verify/prop_contact.py`）を報告する。そのアセットがトリガーした接触は、624,510のうち97ポイントで0.00072であり、明らかにグリップされていなかった。また、自動リギングの結果は、推測するのではなく、読み取られる。`tools/verify/rig_report.py`は、ジョイントの名前を挙げ、メッシュを*セット*として比較し、スキニングが存在するかどうかを示す。

**6本の指を持つ手が、手が認識できない4つのゲートを通過し、許容可能な状態に達した。** 監督者は、それを見てそれを発見した。標準の第7条（1つの手につき5本の指）は、第2条が原因で存在し、現在は、メトリックが静かに無視していたものではなく、彼のズームでオブジェクトの許容項目となっている。

段階的に、各段階の理由とともに：**[ハンドブック](docs/handbook/index.md)**。

**点線のホップは新しく、意図的に実線ではない。** このルートの最初のボックスには、常に*粘土のコンセプト*と表示されており、これまで、ここにそれを作成するものは何もなかった。すべての粘土は手作業で作成され、投入時にハッシュ化されていた。現在、コンセプト→粘土ツールが存在し、最初のペアがフルサイズで実行された。ポーズ、手首のラップ、ベルトのメダリオン、破れた裾がすべて含まれている。髪の毛の塊は含まれていない。カラーリークは、フレーム全体で**C\* p99.9 = 13.15**と測定され、シームレスな非彩色の背景である。**このペアが示すことができないのは、メッシュがより良い状態になるかどうかである。** これは、それを促進する唯一の質問であるため、その証拠が記録された状態で、候補として残る：**[コンセプトの準備](docs/concept-prep.md)**。

## それが機能する理由

6つの発見があり、それぞれが実験の対象となり、それぞれがその対象から一般化される。[詳細な説明と測定値](docs/findings.md)。

- **まず形状を定義し、次にスタイルを適用する。** 再構築ツールは、表面のノイズをジオメトリとして解釈します。意図的に誇張された面を持つ、滑らかで彫刻のようなクレイモデルの方が、スタイライズされたスプライトよりも優れたトポロジーで再現されます。スタイライズされたモデルは、同時に生成され、カラー参照として使用されます。
- **顔の輪郭を明確にし、顔を表現する。** バストアップのクロップを行うと、頭部のポリゴン数が **3.1～4.5倍** 増加し、その違いは構造的なものになります。具体的には、まぶたの分離、眉間のしわ、鼻腔のモデリングなどです。これは、単にぼかしを強くするのとは異なります。
- **ツインはキャラクターではなく、メッシュに属する。** ツインを複数のメッシュで再利用すると、カバレッジが **62% → 22.7%** に低下します。これは、腕がモデルの横の空中に投影されるためです。テクスチャを適用する予定のメッシュから、毎回ツインを生成します。
- **アイデンティティはプロンプトに依存する。** プロンプトで指定されていないカノンの要素が、偶然生成され、同じように消えることがあります。例えば、金色のニープレートが、壊れたControlNetのノイズを通してのみ画像に現れる場合などです。
- **閾値ではなく、ジオメトリを考慮する。** キーフレームマスクを正確なレイキャストシルエットに置き換えると、有効なテクセルにおける参照カバレッジが **28.4% → 39.1%** に増加します。これは、単純な加算であり、拡散やGPUは使用しません。コーナーメディアンキーイングは、ここで **4回** 失敗しており、廃止されました。代わりに、ペイントされたグラデーション、グレーのクレイレンダリング、拡散モデルの照明付きスタジオ背景、および拡散参照を使用します。この拡散参照のコーナーは、L\* 48.1～81.1の範囲に広がります。⚠ この形状は、単一のコーナーをサンプリングする `tools/verify/gate_mesh.py` というコンシューマー製品に引き続き搭載されています。これは、静かに実装するのではなく、明示的に指定されています。
- **カメラで見えないものを、アトラスから削除し、メッシュからは削除しない。** アトラスのテクセルの49%は、外側からは見えません。これらの面を除外することで、補間の精度が **68%** 向上します。削除するのではなく、除外することで、単に検出可能にするだけでなく、失敗を不可能にします。

## 未解決の問題

名前を付けて測定し、脚注ではなく、ホームページに掲載します。[すべてはコードにあります](docs/known-defects.md)。

- **一部の表示されるサーフェスマップは、ベイク処理で書き込まれないアトラス空間にマッピングされ、**画像にそのままの黒色でレンダリングされます。Blenderのベーカーはテクセル中心サンプリングを使用するため、テクセル中心と重なっていない三角形は空のままになります。開発者はこの仕組みに名前を付け、ビルドから2週間後に修正をマージしました。これは、特定のオブジェクトではなく、ルートの特性です。あるアセットで測定し、**他の4つのアセットでは測定していません。**
- **ブレードバンドは、すべての8つのカメラでステージ1の参照の0.00%を占めます。** 灰色を基調とした背景に配置された金属は、キーの色と正確に一致します。この組み合わせにより、55.72%の改善が見られます。
- **ストロークの継ぎ目は滑らかではありません。** 表面の境界は、通常のテクスチャのバリエーションの**5.5倍**を示し、ディレクターが指定した領域は**9.5倍**です。
- **拡散は、関連性のないアトラスアイランド間で混ざり合います。** 拡散されたテクセルの74.9%は、高さ1.0の図で平均0.177離れた別のアイランドから色を取得します。⚠ **この割合はアトラスのテクセルに関するものであり、カメラが見ているものに関する主張ではありません。** 拡散は、書き込まれたアトラスの26.95%であり、**レンダリングされた図のピクセルの4.95%**であり、その比率は0.18です。ペイントは大きなチャートに存在し、穴は小さなチャートに存在するため、拡散されたテクセルは画面空間では安価です。
- **⚑ 合格を決定する欠陥は、ペイントによって引き起こされ、塗りつぶしによってではありません。** 他の素材の色を帯びている領域で、いかなる斑点統計もそれを検出できません。3つの方法で、3つのセッションで、3つの空間で測定しました。**91.05% `reference` が0.99倍のエンリッチメントで表示され、**ベースレートとほぼ同じです。同じ種類の布地の緑色では**68.46% `reference`**、薄いブレードでは、表面自体のペイントされたテクセルが**18.77%**、拡散されたテクセルの**5.55%**に対して汚染されています。塗りつぶしは、最も近いペイントされた隣接テクセルから正しくソースを取得します。そして、その隣接テクセルはすでに間違っています。ブレンド自体は、ドキュメント化されていない2つのバンドに分割されたものです（`M + gaussian_blur_σ16(B − M)`）。これは、同じポイントで**4つの代替案のうち最も悪いもの**を測定します。
- **⚑ ペイントされた面が帯状になり、それが合格したアセットに現れます。** A1のツイン面は、連続した色で塗られています。ベイク処理は、異なるピンク色の垂直ストライプに分割されています。`project_twins`は**勝者総取り**です。各テクセルは、面が正面から、および2つの45°の四分円から見えるため、各テクセルは、平均ではなく、面が向いている方向に基づいて、1つのカメラによって完全に決定されます。これらの視点では、**皮膚の値がR 13.0 / G 13.9 / B 18.3**異なり、合格したリング全体にわたって変化します。面の2つのUVチャートが異なるカメラによって所有されている場合、その違いは明確なステップとして現れるため、**帯はアイランドの境界であり、汚れではありません。** また、灰色の穴のクラスでもありません。**ブラシは構造的にそれを修正できません。** `commit`は、穴のテクセルにのみ書き込み、スタイル化されたテクセルは固定されています。2つの修正が提案されていますが、どちらも採用されていません。正面からの視点にヘッドバンド全体を割り当て、または、シームブレンドを許可して**スタイル化された皮膚を再描画**します。ただし、このルートのどの段階でも、現在それを実行することはできません。加重平均はすでにツールに蓄積されており、ブレンドされたアトラスはすでにディスクに存在します。誰もそれをディレクターの前に提示していません。**これは、ベイク処理が承認されたときにシートに記載されていたものであり、**承認には、アイデンティティと衣装セットが含まれていました。合格したアーティファクトに存在するオープンな欠陥は矛盾ではありませんが、記録には、誰も評価していないプロパティをカバーするものとして承認が記載されてはなりません。

## このリポジトリの実行方法

このプロジェクトにおける規律は、パイプラインと同様に重要な要素であり、それには理由があります。以前の段階では、10回のセッションが実施され、各セッションで独自の出力を評価し、次のセッションで確立された事実として扱われる結論をまとめました。そのループのどの部分も検証できませんでした。

- **作業前に仕様を定め、作業後に報告し、最後に結論を出す**。そして、実験を設計するセッションは、決して自身の結果を評価しません。72回の実験が[記録](docs/experiments/)にあります。
- **修正は、それを覆した測定の横に配置され、静かな削除として行われることはありません。** 最初のセッションだけで、6つの既存の主張が偽造され、そのすべては、それを置き換えたものと一緒に今でも読むことができます。
- **失敗は、その理由とともにリポジトリに残ります。** [`tools/superseded/`](docs/tools.md)はアーカイブではありません。誰でもこれらのツールを実行し、同じように失敗する様子を観察できます。
- **否定的な結果は、完全な成功であり、数値に調整するのではなく、報告され、完了します。**
- **テストは、コードに触れるコミットに紐付けられます**。2つの環境で1376件のテストがパスし、1319件の隔離されたテストに対してパスゲートされたCIが実行されます。
- **記録は検索可能です。** SQLite + FTS5インデックスが、すべての履歴に適用され、4つの環境で検証されています。その結果、記録自体を数えることで、3つの場所で文章が間違っていたことが判明しました。

## ライセンスの位置

すべての段階はローカルで実行され、商用利用も可能です：SDXL（OpenRAIL++）、MV-Adapter（オープン）、open3d（Apache-2.0）、spandrel（MIT）、RealESRGAN anime6B（BSD-3）、Blender、numpy、scipy、trimesh。

意図的に除外され、その理由も記載されています：**nvdiffrast**（非商用 - ここでは構造的なトリップワイヤーによって強制され、アテステーションによるものではありません）、**Hunyuan3D-Paint**（EU、英国、および韓国ではライセンスが無効）、**MVPaint**および**TEXGen**（ライセンスが全くない）、および**UltraSharp / SUPIR / StableSR**（非商用のアップスケーラー）。

**主張の境界は、発見されるのを待つのではなく、明示的に述べられています。** これは、上記の図の段階から3Dへの画像変換までの一連の段階である**記録されたルート**を記述します。その上流にある候補となる粘土の準備段階は、現在、このリポジトリが**検証していない**条件を持つクローズドクラウドAPIで実行されているため、その粘土から作成されたアセットは、ここでカバーされるライセンスの範囲に含まれません。これは、ライセンスを修正したローカルモデルである**Qwen-Image-Edit（Apache-2.0）**を使用して解決できるオープンな問題であり、**FLUX.1-Kontext [dev]は、nvdiffrastと同じ理由で除外されています**。つまり、非商用の重みです。どちらも、スタジオのモデルカタログに対して検証され、再利用されることはありません。その理由は、[コンセプトの準備](docs/concept-prep.md)に記載されています。

## 信頼と脅威モデル

facetは完全にローカルマシン上で実行されます。すべてのツールは、入力するパスに対して実行するスクリプトであるため、重要な質問は、*このアプリはどのような権限を要求するか*ではなく、*これらのスクリプトはマシンに対して何をするか*です。測定によって回答され、すべてのスイープは再実行可能です。完全なポリシーは、[SECURITY.md](SECURITY.md)に記載されています。

- **Data touched:** meshes, textures, images and JSON on local disk, at paths you
  pass on the command line. Plus `docs/index/facet.db`, which is *derived* — it holds
  nothing that was not already a file in this repo, and `facet_index.py build`
  regenerates it from scratch.
- **Data NOT touched:** no credentials, ever. Nothing here reads, stores or transmits
  a token, key or password, and none is present in the tree — swept for
  provider-prefixed keys, GitHub PATs, Slack tokens, AWS key ids, private-key blocks,
  bearer tokens and inline `api_key`/`password` assignments, **zero matches**, no
  credential-shaped file tracked.
- **No telemetry.** None collected, none sent. There is no opt-out because there is
  nothing to opt out of.
- **Network egress:** two tools open a socket — `restylize_views.py`
  and `texpass_brush.py` — and both call a ComfyUI HTTP API at `--host`, **default
  `127.0.0.1:8188`**. Nothing else in `tools/` makes a network call.
- **Permissions:** ordinary user. No elevation, no service install, no system-settings
  or registry writes.

セキュリティ上の懸念事項を主張するのではなく、3つの重要な点を開示します。なぜなら、単に安心できるというリストだけでは、脅威モデルとは言えないからです。**ファイル操作はサンドボックス化されていません**（ツールは、引数で指定された場所に書き込みます）。**絶対パスは、多くのツールやドキュメントに組み込まれています**。26個のファイルに114件の記述があります。これは秘密情報ではありませんが、1つのマシンの構成を明らかにするものであり、ほとんどのツールが変更なしに他の環境で実行できない理由です。また、**予期しないエラーは、未公開の研究スクリプトでPythonのトレースバックとして表示されます**。ゲートは`--debug`によって制御されていません。意図的な停止は、それをトリガーした測定値を伝達する`ANDON:`メッセージです。これが研究ツールの契約であり、[SHIP_GATE.md](SHIP_GATE.md)には、それが十分に機能しなくなる正確な時期が記録されています。2つのコマンドの側面でインストールする場合、0.2.0では、`facet-index`と`facet-mcp`がそれぞれ`0`（正常）/`1`（ユーザーエラー）/`2`（実行時エラー）を返します。また、[E22](docs/experiments/E22-ruling.md)以降、トリガーされたゲートまたは失敗した`verify`に対して、**`4`は拒否**されます。これは、ツールが正常に動作し、実行時エラーではなく、続行しないように指示していることを意味します。すべて、トレースバックではなく、次のステップを示す構造化されたエラーで拒否します（[E21](docs/experiments/E21-cli-contract-report.md））。

**And the gates in those two commands are no longer deletable.** Every ANDON in what
facet installs `raise`s; a bare `assert` is a statement `python -O` removes silently,
and 87 of this repo's gates were removable by an environment variable until E22
converted them. Measured before and after on the same gate, in four interpreter modes.
**And since [E23](docs/experiments/E23-route-gates-report.md), neither are the gates on
the route that produced the four accepted assets** — its **57 sites across twelve
tools**, converted as a pure move on files no test had ever executed, each one now
refusing under `-O` and `PYTHONOPTIMIZE=1` as well as under a normal interpreter.
**And since [E25](docs/experiments/E25-ruling.md) the class is closed.** Its **133 sites
across 43 files** — the measurement instruments that produced the evidence for the four
accepted assets above — convert the same way, bringing the total that `raise` to **278**.
Exactly **one** bare ANDON `assert` remains anywhere under `tools/`:
`superseded/texpass_thin_mask.py`, which is **never** converted, because those tools are
kept so anyone can run them and watch them fail the same way. That remainder is pinned
**by name** in the test suite, so a future sweep cannot tidy it away without editing the
test on purpose.

**サポート状況:** このリポジトリは、1つの環境で、1人のディレクターと、交代するアドバイザーと実行者のセッションによって、オープンに開発されています。`main`のみがサポートされている状態です。リリースチャネル、バックポートポリシー、SLAはありません。代わりに、すべての主張は、それを生成するコードの隣に配置され、[docs/experiments](docs/experiments/)には、各項目の仕様、レポート、および判断が記載されています。

## 要件

Blender 5.x、Python 3.11+、および`numpy`、`scipy`、`trimesh`、`open3d`、`Pillow`、`spandrel`、`torch`が必要です。インペインティングブラシを使用するには、ローカルのComfyUIインストールが必要です。RTX 5090で開発されました。生の速度よりも、VRAMの余裕が重要です。

**2つのインタープリターがあり、これは意図的なものです。** スイート、提供されるMCPツール、およびすべての測定は、CIピン（3.12）を含む環境で実行されます。再構築段階は、別のインタープリターで実行され、**3.10**にピン留めされています。これは、必要なTRELLISホイールがそれ用に構築されているためです。インポートに失敗するツールは、通常、別のインタープリターから要求されています。

CIは、**ubuntu-latest / Python 3.12**で、ピン留めされたインストール（`.github/workflows/ci.yml`）を使用して、スイートの隔離されたサブセットを実行します。アーティファクト層には、記録されたツリー（`E:\AI\training`）が必要ですが、これはgitには含まれていないため、CIはそれらを意図的に選択解除します。ローカルでは、`python -m pytest`は**1376**個すべてのテストを実行し、`python -m pytest -m "not artifacts"`はCIが再現する**1319**個のテストを実行します。

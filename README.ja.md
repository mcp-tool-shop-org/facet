スタイルは**アセットに適用**され、テクスチャ空間で処理されます。ビューごとに描画された後でそれらを結合するわけではありません。形状を強調した粘土モデルをルートに入力すると、そのメッシュのスタイライズされた参照から色を取得したテクスチャ付きメッシュが出力されます。参照では見ることができなかった部分は、マスクを使用したインペイントブラシとサーフェスを考慮した膨張処理によって補完されます。

この問題の2つの側面、つまりポリゴンと、それらが表現する必要がある面を表す名前が付けられています。

## インストール

ルート自体は、入力するパスに対して実行する一連のローカルスクリプトです。リポジトリをクローンし、[Getting Started](https://mcp-tool-shop-org.github.io/facet/handbook/getting-started/) を参照してください。

**2つのサーバーがパッケージとして提供されます**。1つはレコードインデックスで、これによりアシスタントは証拠の追跡を読み込む代わりに照会できます。もう1つは、**v0.4.0 以降では測定サーバー**です。これにより、数か月離れて測定された2つのアセットが、単一のコードパスを経由します。

```bash
npx @mcptoolshop/facet               # the record index; zero-prerequisite, no Python needed
pip install facet-mcp[measure-full]  # + the measurement tools and their instruments
```

`facet-mcp` は、レコード上の stdio MCP サーバーであり（6つのツールがあり、そのうちの1つは4本の脚を持つ検証ツールで、これは健全性を確認するためのものです）、`facet-index` はインデックス自体です（`build` / `verify` / `q` / `claims`）。どちらかをチェックアウト内から実行します。`--db` は別のインデックスの名前です。

### 測定サーバー - v0.4.0 で新機能

`facet-measure` は、比較の**数値的な側面**を処理し、出力が良好かどうかは判断しません。すべてのペイロードには、サーバーバージョン、インストルメント自体のファイルハッシュ、および構成ハッシュが含まれており、`measure_report` は不一致がある場合の比較を**拒否します**。これは、このシステム全体の存在意義です。

検証は、`--help` ではなく **動詞** を実行することで行われます。制御メッシュは、チェックアウトされていないマシン上で786,432個の面と完全なアイデンティティエンベロープを返します。

**結果は1つの要素に依存し、それはPythonのバージョンです:**

| お使いの Python | `[measure-full]` は以下を提供します |
|---|---|
| **3.11 / 3.12** | **すべての8つのツール** - `open3d` は PyPI からインストールされます。 |
| **3.13** | 4つのツール：`mesh_stats`、`mesh_topology`、`measure_report`、`anchor_check` |

`open3d` 0.19.0 が最新の*リリース*であり、cp38〜cp312 ホイールを **sdist なし** で公開します。そのため、Python 3.13 では PyPI にインストールできるものがありません。追加機能は、それを `python_version < "3.13"` の背後に配置するため、そこでインストールが**成功**し、4つのジオメトリツールが、必要なものを名前で示す **`4` REFUSED** を出力するようになります。全体的なインストールが失敗するのではなく。

**Python 3.13 ですべてを8つ入手するには**、Open3D は現在の cp313 ホイールをローリング開発チャンネルに公開します。コマンドラインで直接 URL を使用しても問題ありません。ただし、これは公開されたパッケージメタデータ内でのみ禁止されています。

```bash
# Linux — stable filename, no build hash
pip install https://github.com/isl-org/Open3D/releases/download/main-devel/open3d-0.19.0-cp313-cp313-manylinux_2_35_x86_64.whl
```

⚠ **Windows および macOS では、開発ホイールのファイル拡張子は `+<sha>` で終わります**（執筆時点では `open3d-0.19.0+63e30be-cp313-cp313-win_amd64.whl`）、そして名前は `main` が移動するにつれて変化します。 [the `main-devel` release](https://github.com/isl-org/Open3D/releases/tag/main-devel) にあるアセットをリストし、現在のものを選択してください。 **このルート自体の Open3D に依存する数値は、そのビルドに対して測定されました**。これは、比較可能性の境界です。アイデンティティエンベロープには、インストルメントのハッシュが記録され、その依存関係は記録されません。[E31](docs/experiments/E31-ruling.md)。

*v0.3.1 までのホイールには2つの `.py` ファイルが含まれており、測定インストルメントは含まれていません。そのため、インストールされた測定サーバーは実行するものがありませんでした。誰も4回のリリースにわたってそれに気づきませんでした。なぜなら、このリポジトリ自体がチェックアウトだからです。ツールは、ビルドされた場所で動作し、他の場所に存在したことは一度もなかったからです。*

⚠ **`pip install facet-mcp` は、v0.3.0 までのすべてのリリースバージョンで壊れており、v0.3.1 で修正されました**。ホイールは `facet_index` をトップレベルモジュールとしてインストールするため、v0.3.0 およびそれ以前のバージョンでは、レコードの位置を `<venv>/Lib` に対して解決していました。これは、コーパスもインデックスも含まないため、そして `build`、`claims`、および `q` は `--db` なしで失敗しました。 **v0.3.0 またはそれ以前のバージョンを使用する場合は、上記の `npx` バイナリを使用してください**。

v0.3.1 以降では、ルートはそれを仮定するのではなく、**レコードが存在するかどうかをテストすることで解決されます**。どちらかのコマンドをチェックアウト内から実行すると、見つかります。他の場所から実行すると、**`4` REFUSED** を出力し、試した両方のディレクトリと検索した両方のマーカーの名前を表示します。 `$FACET_INDEX_DB` は現在、両方のコマンドによって読み取られ、どの*インデックス*を使用するかを選択しますが、どの*コーパス*を使用するかは選択しません。 `main` からビルドされ、クリーンな仮想環境にインストールされたホイールで測定されました。[E24](docs/experiments/E24-ruling.md)。

*このブロックは2回修正されました。最初に `pipx install facet-mcp # または Python パッケージを直接`, until v0.3.0's read-back ran a **verb** instead of `--help` と記述されていました。次に、ホイールは「 `q` および `claims` の場合にのみ動作する」と記述されていましたが、**`claims` も動作しませんでした**。これは E24 が実行して確認したものです。両方の修正は [known-defects.md](docs/known-defects.md) に測定結果とともに記載されています。*

**次にブラシが開かれ、空いている部分に書き込みます。** 1回目のストロークは2026年8月19日にヨー角90で実行されました。不変ANDONは、472,318ピクセルにわたってテストされた中で、図の外側に**0.014 lv、最大のホットコンポーネントが0 px**と読み取られ、`commit`は**3,585テクセル**を書き込み、空いている部分を**2,044,423 → 2,040,838**に減らし、その後ソースアトラスがバイト単位で再検証されました。ディレクターのズームでは、ベストの襟から肩にかけての淡い三角形が紫色になり、縫い目は1つの衣装として表示されます。顔を作成したり、頭を回転させたり、2番目のベストを描いたりすることはありませんでした。

**方法論的な結果は、アセットよりも重要です。** その全体を通して、ControlNetの強度は一度も調整されませんでした。すべての修正は、特定の要素に対して力を加えるのではなく、原因を取り除きました。2つのエラーのうち、1つはアドバイザー自身の仕様上の欠陥であり、実行エンジンと外部レビューチャネルによって、クレジットが使用される前に検出され、両方とも記録に名前が記載されており、それらを覆す測定値も含まれています。

**これはパイプラインであり、1つのキャラクターを生成するものではありません。** 8つの名前付き要素で仕様と矛盾させると、プロンプトは**8/8**で勝利します。5つの固定コントロールと比較して、中央値ΔEは46.3に対して6.2です。一方、図は同じ人物のままです。構造はメッシュと制御によって保持され、名前付き属性はプロンプトに依存します。

**プロジェクターに関する問題は2026年8月16日に終了しました**（[E45](docs/experiments/E45-warp-and-aov-kickoff.md)–[E49](docs/experiments/E49-finish-and-cap-kickoff.md））。
8つのプレートは、境界×向き×可視性重みを使用して、各ビューのバンドルから再構築され、アトラスレンダリングがこのルートで初めてディレクターの承認基準をクリアしました。これは2回、2つの異なる段階で行われました。一方、出荷されたアトラスのルートは、プレートに描かれたペイントを破壊していました。それを実行したチェーンは`tools/`（`emit_view_aovs`、`s3_composite`、`flow_estimate`、`s3_run`、`s3_sheet`、
`atlas_from_aovs`、`twin_mesh_warp`）にあり、主に外部レビューチャネルを通じて構築され、その指定されたキャリブレーションの主張は**20回中20回成功し**、それぞれがここで検証されました。それは、ビルドを信頼する前に実行することで確認されます。

**カノンはデータであり、支出を制御します（2026年8月17日）。** アイデンティティ仕様では17の要素が指定され、ツインを生成したワークフローでは16の要素が指定され、プロファイルデフォルトで新しい実行で使用されるのは6つの要素でした。それらは互いに関連していませんでした。したがって、4つの段階を経て、ソースで間違っていたペイントの下流での構成が修正されました。カノンは現在、**サーフェス**をキーとするデータベースであり、要素リストでは何が欠けているかを示すことはできず、null許容の占有者は空いている部分を行にします。そして、`canon_gate`は、出力ディレクトリが存在する前に、生成を作成するツールの**内部**で実行されます。カノンに準拠していないプロンプトを持つ生成は拒否され、何も書き込まれません。

**これはルーターであり、フェイルクローズです。** 被験体をそのカノンファイルに関連付け、プロンプトを**両方向**でカバーし、範囲を持ちます。**支出を作成するツールであり、カノンが与えられない場合、静かに進行しません。拒否します。** 実際にカノンを持たない被験体に対する回避策は、統計データに基づいており、カノンを持つ被験体によって使用することはできません。`--no-canon --subject GALLEON`は実行され、自身を宣言します。`--no-canon --subject W3`は**拒否されます**。なぜなら、W3にはサーフェスがあるからです。これは、構成ではなく、設計によってチェックボックスを閉じます。そして、それは重要です。なぜなら、前の形状（`if args.canon:`）では、出荷されたPowerShellドライバーがゲートを静かに通過することを許可していたからです。

**2番目の方向は、実際の欠陥を検出するものです。** プロンプトにカノンが含まれているかどうかを確認すると、プロンプトが薄いことがわかります。プロンプトのすべての要素がカノンであるかどうかを確認すると、キャラクターが持っていないものを指すフレーズが見つかります。そして、ライブデフォルトには1つありました。それは**`gold necklace`**であり、このリポジトリはすでにそれが金のベルトメダリオンの名前を誤って記述していることを測定していました。*"そして、その要素は偶然生き残ります。"* そのフレーズが追加された包括的なプロンプトを使用すると、今度は`missing: 0`が返され、それでも拒否され、その句が名前で示されます。

```
canon_gate 1.0.0  census  (occupancy is not ratification)
subject      named   occupancy   ratified   prof_hit surfaces
W3              19       24/24      24/24       5/19 canon/w3.surfaces.json
GALLEON         13           -          -      11/13 NONE
DRAGON          11           -          -      10/11 NONE
LONGSWORD        5         5/5        5/5        4/5 canon/longsword.surfaces.json
E10-LAYER        1           -          -          - NONE
LOGO             0           -          -          - NONE
A1              10       16/16      16/16      10/10 canon/a1.surfaces.json
```

`prof_hit 5/19`は、**意図的に壊れたままになっているサンプルです**。それは、実行が実際に使用するライブデフォルトであるため、最初の`--profile character.json`は停止するように設定されています。文字列を修正すると、証拠が削除されます。

**そしてワークシートがあります。なぜなら、カノンを持たない4つの被験体は、自分で歩き回ることはないからです。** ワークシートは、被験体の*種類*が示すすべてのサーフェスを出力します。したがって、空いている部分は誰かが名前を付ける前に行になります。IDENTITY.mdをインベントリに変換し、ジョイントをペアとして扱い、確認し、各ビューの範囲スロットを予約します。それは**構造的に占有者を埋めることができず**、それがテストされる特性です。サーフェスがすでに割り当てられている状態で毒性のあるフレーズが到着すると、書き込まれません。カノンの生成は、人間が参照を歩き回ることであり、ワークシートはそのプロセスを安価かつ完全にします。

**ゲートの境界は、発見されるのを待つのではなく、明示的に定義されている。** これは、両方向で規定された主要なフレーズを特定の範囲内でチェックする。言い換えや同義語はチェックしない。意味的な一致によってモデルがゲート内に配置されると、このリポジトリはその原則に反するため拒否される。また、ビューの範囲が宣言されるまで、個々のビューの要素もチェックせず、名前付きのマテリアルが正しい表面に適用されたかどうかもチェックしない。スコープスロットが存在し、その表面リストは空である。それらを埋める作業は、オブジェクトを配置する作業と同様に、手動で行う必要がある。4つの被験体には、IDENTITY.mdと表面JSONがない。これは、参照データを実際に検証せずに生成することを避けるためである。

**プロンプトが扱える要素の数は測定され、主要な基準には達しない。** 既存の研究では、追加された各プロンプト要素に対してコストがかかり、要素が表示されるかどうかによって価格が決まる。その範囲は、現在のものよりも大幅に小さい。そのため、Opusの担当者は、すでに支払いが完了しているプレートで問題を解決できるかどうかを尋ねた。**しかし、それは不可能であり、その理由は構造的なものである。** コーパス内のどの要素も、周囲の数が変化しながら、常に同じフレーズを保持し、かつ存在しない状態になることはない。彼らが提供するのは、一方通行の制限である。例えば、1つのカメラでバイト単位で完全に制御された5つのプロンプトを使用し、マスクとシードを設定する。**10 → 17**という要素の段階を経て、10で存在していたものは何も削除されず、*ゼロ*カウントの変化におけるアイデンティティの変更によって、完全なキャリブレーション間隔が移動した。**W3の主要な基準は19であり、コーパスはその値に決して達しない** ([E55](docs/experiments/E55-density-vs-identity-report.md))。スタジオは、最終的に統合される3つの数値を表示する。すなわち、24個のプロンプト表面、25個の必要なチェック、19個の一意な要素である。したがって、要素数の測定値に対してカバレッジ数を引用することはない。

```
  styled 2D concept ╌╌► clay prep ╌╌╮   ← CANDIDATE hop, walked once. Not a route
                                    ╎     stage. Everything below it is the route.
                                    ▼
form-exaggerated clay concept ──► image-to-3D ──► weld ──► density allocation
                                                             │
                    cull what no camera can see ◄────────────┘
                                 │
                                 ▼
       twins, generated from THIS mesh ──► project ──► brush the holes ──► fill
```

段階ごとに、その理由とともに：**[ハンドブック](docs/handbook/index.md)**。

**点線のホップは新しく、意図的に完全に線で描かれていない。** 経路の最初のボックスには常に*粘土コンセプト*と表示されており、これまでここにそれを作成するものは何もなかった。すべての粘土は手作業で到着し、その過程でハッシュ化されていた。現在、コンセプトから粘土を生成するためのツールが存在し、最初のペアが完全なサイズで検証されている。ポーズ、リストバンド、ベルトのメダリオン、破れた裾などが再現された。たてがみは再現されなかった。カラーリークは、フレーム全体で**C\* p99.9 = 13.15**と測定され、シームレスな非彩色の背景が使用されている。**このペアでは、メッシュがより良く改善されるかどうかを示すことはできない。** これは、その価値を評価する唯一の基準であり、そのため、証拠とともに候補として残る：**[コンセプト準備](docs/concept-prep.md)**。

## それがどのように機能するか

6つの発見があり、それぞれが実験の対象となり、また、その実験で得られた結果は、その対象を超えて一般化される。[詳細な説明と測定値](docs/findings.md)。

- **まず形状を定義し、次にスタイルを適用する。** 再構築ツールは、表面のノイズをジオメトリとして解釈する。意図的に誇張された平面を持つ、滑らかな彫刻のような粘土を使用すると、スタイライズされたスプライトよりも優れたトポロジーが得られる。スタイライズされたモデルは並行して生成され、カラー参照となる。
- **顔のフレームを作成し、顔を得る。** バストクロップを行うと、頭部のポリゴン数が**3.1〜4.5倍**増加する。この違いは構造的なものであり、分離されたまぶた、眉間の溝、モデル化された鼻腔などがある。これは単にぼかしが軽減されるというだけではない。
- **ツインはキャラクターではなく、メッシュに属する。** ツインを複数のメッシュで使用すると、カバレッジが**62%から22.7%**に低下する。これは、腕がモデルの横にある空中に投影されるためである。テクスチャを適用する予定のメッシュから毎回ツインを生成する。
- **アイデンティティはプロンプトに属する。** プロンプトで名前が指定されていない主要な要素は、偶然に現れ、同じように消える。これは、金色の膝板が、壊れたControlNet内のノイズを通してのみ画像に表示されることが判明したときに測定された。
- **閾値ではなく、ジオメトリを尋ねる。** キー化されたマスクを正確なレイキャストシルエットで置き換えると、有効なテクセルにおける参照カバレッジが**28.4%から39.1%**に増加する。これは厳密に追加であり、拡散やGPUは使用されない。コーナーメディアンキーイングはここで3回失敗しており、廃止された。
- **カメラで見ることができないものを削除し、アトラスからではなく、常にメッシュから行う。** アトラスのテクセルの49%は外側からは見えない。これらの面を除外すると、補間が68%削減される。除外するのではなく、削除することで、単に検出できるだけでなく、失敗を不可能にする。

## 解決されていない問題

名前と測定値は、本文ではなく、脚注で示されている。[すべてコードに記載](docs/known-defects.md)。

- **一部の表示されるサーフェスマップは、ベイク処理で書き込まれないアトラス空間にマッピングされ**、画像が変更されていないデフォルトの黒としてレンダリングされます。Blender のベーカーはテクセル中心サンプリングを使用するため、どのテクセル中心にも重なっていない三角形は空のままになります。開発者はこの仕組みに名前を付け、ビルドから 2 週間後に修正をマージしました。これは単一のオブジェクトではなく、ルートの特性です。1 つのアセットで測定され、**他の 4 つでは測定されていません**。
- **ブレードバンドは、すべての 8 台のカメラでステージ 1 の参照の 0.00% を占めます**。グレーの背景に配置された金属が、キーの色域のしきい値に正確に一致します。この組み合わせにより、55.72% が改善されます。
- **ストロークの継ぎ目は滑らかではありません**。プロベナンス境界は、通常のテクスチャの変化よりも **5.5 倍** 大きく変化します。ディレクターが指定した領域は、**9.5 倍** の変化を示します。
- **拡散によって、関連性のないアトラスアイランド間で色が混ざります**。拡散されたテクセルの 74.9% が、高さ 1.0 の図で平均 0.177 だけ離れた別の島から色を取得します。⚠ **この割合はアトラスのテクセルに関するものであり、カメラが見ているものについては言及していません**: 拡散は書き込まれたアトラスの 26.95% を占め、**レンダリングされた図のピクセルの 4.95%** であり、その比率は 0.18 です。ペイントは大きなチャートに存在し、穴は小さなものに存在するため、拡散されたテクセルは画面空間では安価です。
- **⚑ 合格を決定する欠陥は、フィルではなくペイントによって引き起こされます**。別のマテリアルの色を持つ領域で、どのスペクル統計もそれを認識できません。3 つの方法で 3 つのセッションで 3 つの空間で測定されました: **91.05% `reference` が 0.99 倍に増加し**、ベースレートとほぼ同じです。布地の緑色の同じクラスでは **68.46% `reference`** であり、薄いブレード上ではサーフェスのペイントされたテクセルが **18.77%** で汚染され、拡散フィルの **5.55%** と比較されます。フィルは、最も近いペイントされた隣接テクセルから正しくソースを取得します。そして、その隣接テクセルはすでに間違っています。ブレンド自体は、ドキュメント化されていない 2 つのバンド分割です (`M + gaussian_blur_σ16(B − M)`)。これは、同じポイントで **4 つの代替案のうち最悪のもの** を測定します。
- **⚑ ペイントされた面が帯状になり、それが合格したアセットに現れます**。A1 のツイン面は 1 つの連続した色調です。ベイク処理では、異なるピーチ色の垂直ストリップに分割されています。`project_twins` は **勝者総取り** です。各テクセルに対して、カメラが向きに基づいて完全に決定し、平均化ではなく所有権を確立します。この面は正面図と 2 つの 45° の四分円で表示され、それらは受け入れられたリング全体で **R 13.0 / G 13.9 / B 18.3** と異なるスキンの値を示します。面の 2 つの UV チャートが異なるカメラによって所有されている場合、その違いは明確なステップとして現れるため、**帯状の部分は島境界であり、汚れではありません**。また、グレーの穴クラスでもありません。**ブラシでは構造的に修正できません**: `commit` は穴テクセルにのみ書き込み、スタイル化されたテクセルは固定されています。2 つの解決策が提案されましたが、どちらも採用されませんでした。正面図でヘッドバンド全体を所有させるか、または **スタイル化されたスキンを再描画できるシームブレンド** を許可します。ただし、このルートのどの段階でも現在実行できません。重み付け平均はすでにツールに蓄積されており、ブレンドされたアトラスはディスク上に存在します。誰もそれをディレクターに見せることはありませんでした。**これはベイク処理が承認されたときにシートに記載されていたものであり**、承認にはアイデンティティと衣装セットが含まれていました。合格したアーティファクトに存在するオープンな欠陥は矛盾ではありませんが、記録には、誰も評価していないプロパティをカバーするものとして承認が記載されていてはいけません。
- **各ビューは独立していません。これはすべてのブレンド修正の範囲を制限します**。各欠陥領域について、**2 つ以上のカメラで貢献している面の 100% はすべて、90° の範囲内にあります** (中央値は 45°)。欠陥のある面の 21% は、1 つのカメラでのみ表示されます。ほぼ同一の制御下にある隣接するビューが同時に失敗するため、フォトグラメトリで公開されているマルチビューの利点は、そのまま転送されません。
- **このルート上のすべての再構築は、中空の二重壁シェルです**。壁は約 2 ボクセルです。1 つのボクセルに対して有効なボリュームに関する述語はありません。
- **プレートは名前のないマテリアル境界で異なり、その規範が重要なポイントです (2026-08-16)**。内側のツインからメッシュへのワープは、すべての 8 つのビューでシルエットの中央値 1.2 ～ 3.0 に対して **3.5 ～ 11.1 ピクセル** の中央値で測定されました。ディレクターが円で囲んだ残りの領域 (袖口、手、ブーツの上部) はすべて、生成プロンプトで名前が指定されていないマテリアルの接合部です。⚠ **2026-08-17 に修正され、その修正により結果がより明確になりました**。以前は「記録されたプロンプトには 6 つの要素が含まれています」と記載されていましたが、測定したところ、これは 2 つの異なるファイルを結合しています。ツインを生成したワークフローでは、グリップを除いて **17 のうち 16 個** が名前が指定されています。*ブラシプロファイルデフォルト* では、6 つの名前が指定されています。どちらも真実であり、文はそれらから 1 つだけ誤った主張を行っています。重要なのは、グリップ、ガントレット、グリーブ、手が **16 要素のプロンプトに 0 回** 登場することです。なぜなら、**それらの要素は規範には存在しないからです**。完全なプロンプトでも、指定されていない手について名前を付けることはできません。✅ **2026-08-17 に終了しました**。サーフェスリストが確認され、入力され、**24/24 が承認されました**。ゲートは現在、それをカバーしていないプロンプトを拒否します。
- **有効なテクセルの 4.65 ～ 5.57% は、フラットリングカメラでは表示できないサーフェスです**。これらはすべてのビューで深度ゲートに失敗し、どの投影ルートでもペイントすることはできず、出荷されたパイプラインはそれらを島を意識しない塗りつぶしで覆い、暗いマークを作成しました。修正ではなく、ポリシー (中立的なマテリアル、ブラシ、または承認) が必要です ([E49 レポート](docs/experiments/E49-finish-and-cap-report.md))。
- **合格グレードのシートにあるフラットな色のポリゴン**。これはディレクターが指摘した唯一のオープンクラスです。⚠ **フィルパス仮説は誤りであることが証明されました (2026-08-17)**。孤立したフィルは、欠陥で自身のベースレートよりも *低い* 値を示し、パッチは通常のペイントされたテクセルの 90 ～ 99% に配置され、同じ欠陥が、その原因とされている修正前のアトラスからレンダリングされたものにも存在します。代わりに、そのソースにトレースされました: レンダビュー自身のツインはそこでクリーンであり、**異なる** ビューが、対面角度 0.68 に対して 115 個の欠陥ピクセルのうち 97 個を所有しています (元の値は 0.60)。角形のパッチは **散乱アーティファクト** であり、色はすでに名前が付けられているサーフェスの実際のクロスビューの違いです。したがって、「欠陥はツインにあります」という理由でツインの再生成を行うことは正当化されません。
⚠ **そして、このページで提案された修正も誤りであることが証明されました (2026-08-17)**。「ターゲットビューを優先するコンポジターが、範囲内の修正を行い、コストはかかりません」と記載されていました。コンポジターはすでに存在し、デフォルトでした。記録された 1 つの実行からの静止画でフラット分類器と比較すると、ターゲットファーストでは、名前付きのターゲット (38 → 40) でカウントが増加し、他の 2 つでも大幅に増加します (23 → 64, 36 → 110)。これにより、*より* 接続性が高まります。メカニズムは次のとおりです: **形状が所有権であり、色はそうではありません**。オリーブはビュー 6 のサーフェスのペイントであり、ビュー 6 はそれを正しくペイントしています。したがって、ターゲット 6 (つまり、ターゲットファーストで *ビュー 6 を優先する*) では、ポリシーはまさに欠陥を構成するペイントを最大化します。**所有権ポリシーでは、正しく属性が割り当てられたサーフェスのクロスビューカラーの不一致を修正することはできません**。これは、そのファミリー全体ではなく、1 つの部分をリタイアさせます ([E52](docs/experiments/E52-target-first-flats-ruling.md))。残っているのはペイントの問題であり、生成にコストがかかります。*以前のテキストは、修正ルールに従って保持されます: 「単一の三角形サイズの孤立した島で、侵食されていないシルエットを使用して境界に隣接するツインサンプルからフラットに塗りつぶされています」

## このリポジトリの実行方法

重要なのは、パイプラインと同じくらい、そのプロセスも重要であり、それには理由がある。以前の段階では、10回のセッションを実施し、各セッションでそれぞれの結果を評価し、次のセッションでそれを事実として扱う結論を書いた。この一連の流れの中で検証可能なものは何もなかった。

- **作業前に仕様を定め、作業後に報告し、最後に判断を下す** — そして実験を設計するセッションは、決して自身の結果を評価しない。72件の実験が[記録](docs/experiments/)にまとめられている。
- **修正は、それを覆した測定値の隣に配置され、静かに削除されることはない。** 最初のセッションだけで6つの既存の主張が否定され、そのすべてが現在でも、それらに取って代わるものと一緒に閲覧できる。
- **失敗は、その理由とともにリポジトリに残る。** [`tools/superseded/`](docs/tools.md) はアーカイブではない。誰でもこれらのツールを実行し、同じように失敗する様子を観察することができる。
- **否定的な結果は完全な成功であり、数値に近づけるのではなく、報告され、完了する。**
- **テストは、コードに触れるコミットと連動する** — 2つの環境で1346件の合格、1289件の隔離されたものに対してパスが制限されたCI。
- **記録は検索可能である。** 全体を通してSQLite + FTS5インデックスを使用し、4つの側面で検証されている。その結果、文章に誤りがあった3つの箇所を特定し、記録自体を参照して判断した。

## ライセンスの位置

すべての段階はローカルで実行され、商用利用においても問題がない：SDXL (OpenRAIL++)、MV-Adapter (オープン)、open3d (Apache-2.0)、spandrel (MIT)、RealESRGAN anime6B (BSD-3)、Blender、numpy、scipy、trimesh。

意図的に除外され、その理由は以下の通り：**nvdiffrast**（非商用 — ここでは構造的なトリップワイヤーによって強制されており、認証によるものではない）、**Hunyuan3D-Paint**（EU、英国、および韓国でのライセンスが無効）、**MVPaint**および**TEXGen**（ライセンスが全くない）、および**UltraSharp / SUPIR / StableSR**（非商用のアップスケーラー）。

**主張の境界は明示されており、発見されるのを待つことはない。** これは**記録されたルート**を記述するものであり、上記の図にある段階から画像から3Dへの変換へと進む。それよりも前の候補となる粘土準備ホップは、現在、このリポジトリが**検証していない**条件を持つクローズドクラウドAPIで実行されているため、ここにあるライセンスの主張は、そのいずれかの粘土から作成されたアセットをカバーするものではない。これは未解決の問題であり、それを解決するための明確な方法がある：ライセンスに準拠したローカルモデルは**Qwen-Image-Edit (Apache-2.0)**であり、**FLUX.1-Kontext [dev] は nvdiffrast と同じ理由で除外されている** — 非商用の重み。どちらもスタジオのモデルカタログに対して検証され、再利用されることはない。その理由は[コンセプト準備](docs/concept-prep.md)に記載されている。

## 信頼と脅威モデル

facetは完全に自分のマシン上で実行される — すべてのツールは、パスを入力して呼び出すスクリプトであり、したがって重要な質問は、「このアプリはどのような権限を要求するか」ではなく、「これらのスクリプトはどのようにあなたのマシンに影響を与えるか」である。測定によって回答され、すべてのスイープは再実行可能である。完全なポリシーは[SECURITY.md](SECURITY.md)にある：

- **アクセスされるデータ:** ローカルディスク上のメッシュ、テクスチャ、画像、およびJSON。コマンドラインで渡すパスに存在する。さらに`docs/index/facet.db`も含まれるが、これは*派生したもの*である — リポジトリ内のファイルとしてすでに存在していたものではなく、`facet_index.py build`によって最初から再生成される。
- **アクセスされないデータ:** 認証情報は一切使用しない。ここでは、トークン、キー、またはパスワードを読み取ったり、保存したり、送信したりするものはなく、ツリーにも存在しない — プロバイダーのプレフィックスが付いたキー、GitHub PAT、Slackトークン、AWSキーID、秘密鍵ブロック、ベアラートークン、およびインラインの`api_key`/`password`割り当てに対してスキャンされ、**一致するものはない**。認証情報のようなファイルも追跡されていない。
- **テレメトリーは行わない。** 収集も送信もしない。オプトアウトするものが何もないため、オプトアウトのオプションもない。
- **ネットワークからのデータ送信:** 2つのツールがソケットを開く — `restylize_views.py`と`texpass_brush.py` — そしてどちらもComfyUI HTTP API（`--host`）にアクセスし、**デフォルトは`127.0.0.1:8188`である。** `tools/`内の他のものは、ネットワーク呼び出しを行わない。
- **権限:** 通常のユーザー。昇格、サービスインストール、システム設定またはレジストリへの書き込みは行われない。

３つの鋭い点が明らかになる一方で、単に安心感だけを列挙したセキュリティに関する注意書きは脅威モデルではないため、それらは主張されることはありません。**ファイル操作はサンドボックス化されていません**（ツールは、その引数で指定された場所に書き込みます）。**多くのツールやドキュメントには絶対的なローカルパスが組み込まれています**—26個のファイルに114件の記述があります。これは秘密情報ではなく、単一のマシンの構成を明らかにするものであり、ほとんどのツールが変更なしで他の場所で実行されない理由でもあります。そして、**予期しないエラーは、未公開の研究スクリプト内でPythonのトレースバックとして表面化します**。ゲートはありません（`--debug`）。意図的な停止は、それをトリガーした測定値を伝達するメッセージです（`ANDON:`）。それが研究用具の契約であり、[SHIP_GATE.md](SHIP_GATE.md)には、それが十分に機能しなくなる正確な時点が記録されています。これは、２つのコマンドにおいて、インストール時に0.2.0で発生しました。`facet-index`と`facet-mcp`はそれぞれ、`0`（正常）、`1`（ユーザーエラー）、`2`（実行時エラー）を返します。そして、[E22](docs/experiments/E22-ruling.md)以降、トリガーされたゲートまたは失敗したステップ（`verify`）に対して、**`4`（拒否）**となります。これは、ツールが動作し、実行時エラーではなく、続行しないように指示していることを意味します。これらすべては、トレースバックの代わりに、次のステップを示す構造化されたエラーメッセージで拒否します（[E21](docs/experiments/E21-cli-contract-report.md)）。

**And the gates in those two commands are no longer deletable.** Every ANDON in what
facet installs `raise`s; a bare `assert` is a statement `python -O` removes silently,
and 87 of this repo's gates were removable by an environment variable until E22
converted them. Measured before and after on the same gate, in four interpreter modes.
**And since [E23](docs/experiments/E23-route-gates-report.md), neither are the gates on
the route that produced the four accepted assets** — its **57 sites across twelve
tools**, converted as a pure move on files no test had ever executed, each one now
refusing under `-O` and `PYTHONOPTIMIZE=1` as well as under a normal interpreter.
**And since [E25](docs/experiments/E25-ruling.md) the class is closed.** Its **133 sites
across 43 files** — the measurement instruments that produced the evidence for the four
accepted assets above — convert the same way, bringing the total that `raise` to **278**.
Exactly **one** bare ANDON `assert` remains anywhere under `tools/`:
`superseded/texpass_thin_mask.py`, which is **never** converted, because those tools are
kept so anyone can run them and watch them fail the same way. That remainder is pinned
**by name** in the test suite, so a future sweep cannot tidy it away without editing the
test on purpose.

**サポート状況：** このリポジトリはオープンな環境で開発され、１つのハードウェア構成で、１人のディレクターと、交代するアドバイザーと実行者のセッションによって行われます。`main`のみがサポートされている状態です。リリースチャンネル、バックポートポリシー、SLAはありません。代わりに、すべての主張は、それを生成するコードの隣に配置され、[docs/experiments](docs/experiments/)には、それぞれの仕様、レポート、および判断が含まれています。

## 要件

Blender 5.x、Python 3.11+（`numpy`、`scipy`、`trimesh`、`open3d`、`Pillow`、`spandrel`、`torch`）。インペイントブラシを使用するには、ローカルのComfyUIインストールが必要です。RTX 5090で開発されました。生の速度よりもVRAMの余裕が重要です。

CIは、スイートの隔離されたサブセットを**ubuntu-latest / Python 3.12**で実行し、固定されたインストール（`.github/workflows/ci.yml`）を行います。アーティファクト層には、記録されたツリーが必要です（`E:\AI\training`）。これらはgitには含まれていないため、CIは設計上、それらを非選択にします。ローカルでは、`python -m pytest`がすべての**1346**個のテストを実行し、`python -m pytest -m "not artifacts"`がCIで再現される**1289**個のテストを実行します。

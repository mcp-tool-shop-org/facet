スタイルは**アセットに適用され、テクスチャ空間内で行われます。** ビューごとにペイントして後でつなぎ合わせることはありません。形状を強調した粘土モデルをパイプラインに入力すると、スタイライズされた参照メッシュから色を取得したテクスチャ付きのメッシュが出力されます。参照では見えない部分は、マスク処理されたインペインティングブラシとサーフェスを認識する膨張処理によって補完されます。

この問題の2つの側面、つまりポリゴンと、それらが表現する必要がある面を表す名前が付けられています。

## インストール

パイプライン自体は、入力するパスに対して実行する一連のローカルスクリプトです。リポジトリをクローンし、[開始方法](https://mcp-tool-shop-org.github.io/facet/handbook/getting-started/)を参照してください。

**パッケージとして2つのサーバーが提供されます。** 1つはレコードインデックスで、アシスタントが証拠の追跡を読み込む代わりにクエリを実行できるようにします。もう1つは、**v0.4.0から測定サーバーです。** これにより、数か月かけて測定された2つのアセットは、同じコードパスを経由します。

```bash
npx @mcptoolshop/facet               # the record index; zero-prerequisite, no Python needed
pip install facet-mcp[measure-full]  # + the measurement tools and their instruments
```

`facet-mcp` は、レコード上の stdio MCP サーバーであり（6つのツールがあり、そのうちの1つが拒否型の健全性サーフェスとして機能する4脚検証）、`facet-index` はインデックス自体です（`build` / `verify` / `q` / `claims`）。どちらもチェックアウト内から実行します。`--db` は別のインデックスの名前です。

### 測定サーバー - v0.4.0で新機能

`facet-measure` は、比較の**数値的な側面**を処理し、出力が良好かどうかは判断しません。すべてのペイロードには、サーバーバージョン、インストルメント自体のファイルハッシュ、および構成ハッシュが含まれており、`measure_report` は不一致がある場合に比較することを**拒否します。** これは、このシステム全体の存在意義です。

**コマンド（verb）を実行することで検証されます。** `--help` を実行するのではなく、制御メッシュが786,432個の面と完全なアイデンティティエンベロープを返し、そのマシンにはチェックアウトが存在しません。

**結果は1つの要素に依存し、それはPythonのバージョンです。**

| お使いのPython | `[measure-full]` を使用すると |
|---|---|
| **3.11 / 3.12** | **8つのツールすべて**が利用可能になります。 `open3d` はPyPIからインストールされます。 |
| **3.13** | 4つのツール：`mesh_stats`、`mesh_topology`、`measure_report`、`anchor_check` |

`open3d` 0.19.0は最新の*リリース*であり、cp38〜cp312ホイールを**sdistなしで**公開します。そのため、Python 3.13ではPyPIにインストールできるものはありません。追加機能により、これは`python_version < "3.13"`の後ろに追加されるため、インストールがそこで**成功し**、4つのジオメトリツールが
必要なものを名前として出力する **`4` REFUSED** となります。完全なインストールの失敗とは異なります。

**Python 3.13で8つすべてを取得するには、** Open3Dは現在のcp313ホイールをローリング開発チャンネルに公開します。コマンドラインでは直接URLを使用できます。これは、公開されたパッケージメタデータ内でのみ禁止されています。

```bash
# Linux — stable filename, no build hash
pip install https://github.com/isl-org/Open3D/releases/download/main-devel/open3d-0.19.0-cp313-cp313-manylinux_2_35_x86_64.whl
```

⚠ **WindowsとmacOSでは、開発用ホイールのファイル名は `+<sha>` で終わります**（執筆時点では `open3d-0.19.0+63e30be-cp313-cp313-win_amd64.whl`）、名前は `main` の変更に合わせて変更されます。 [ `main-devel` リリース](https://github.com/isl-org/Open3D/releases/tag/main-devel)でアセットをリストし、現在のものを選択します。 **このパイプライン自体のOpen3Dに依存する数値は、このビルドに対して測定されました。** これは、比較の境界線です。アイデンティティエンベロープには、インストルメントのハッシュが記録され、その依存関係は記録されません。[E31](docs/experiments/E31-ruling.md)。

*v0.3.1までのホイールには2つの `.py` ファイルが含まれており、測定インストルメントは含まれていません。そのため、インストールされた測定サーバーは実行するものがありませんでした。これは4回のリリースにわたって誰にも気づかれませんでしたが、このリポジトリ自体がチェックアウトであるためです。ツールは、ビルドされた場所で機能し、他の場所に存在したことはありませんでした。*

⚠ **`pip install facet-mcp` は、v0.3.0までのすべてのリリースバージョンで壊れており、v0.3.1で修正されています。** ホイールは `facet_index` をトップレベルモジュールとしてインストールするため、v0.3.0までには、レコードの場所を `<venv>/Lib` に対して解決していました（これは、コーパスもインデックスも含まない）。また、`build`、`claims`、および `q` は `--db` なしで失敗しました。
**v0.3.0以前を使用する場合は、上記の `npx` バイナリを使用してください。**

v0.3.1以降では、ルートはそれを前提とするのではなく、**レコードの存在をテストすることで解決されます。** チェックアウト内からどちらかのコマンドを実行すると、見つかります。他の場所から実行すると、**`4` REFUSED** と出力され、試した両方のディレクトリと検索した両方のマーカーの名前が表示されます。 `$FACET_INDEX_DB` は現在、両方のコマンドによって読み取られ、どの*インデックス*を使用するかを選択します（*コーパス*は選択しません）。 `main` からビルドされ、クリーンなvenvにインストールされたホイールで測定されました。[E24](docs/experiments/E24-ruling.md)。

*このブロックは2回修正されました。最初に `pipx install facet-mcp # またはPythonパッケージを直接`, until v0.3.0's read-back ran a **verb** instead of `--help` と記述されていました。次に、ホイールは「 `q` および `claims` のみに機能する」と記述されていましたが、**`claims` も機能しませんでした。** これはE24によって実行された結果です。両方の修正は、[known-defects.md](docs/known-defects.md)に測定値とともに記載されています。*

## 現在の状況

**4つの承認済みアセットが、4つの被験者クラスに対して、クレジット0で提供されます。** それぞれは、ディレクターによって独自のズームレベルで評価されました（GLBまたはフルサイズのシート）。メトリックがしきい値を超えてクリアされたわけではありません。

| 被験者 | クラス | 承認済み | 参照/ブラシ/膨張 |
|---|---|---|---|
| **Character (W3)** | ヒューマノイド | [2026-08-04](docs/experiments/E08-ruling-gate0.md) | 68.8 / 4.2 / 27.0 |
| **Galleon** | 車両、シンプルなリギング | [2026-08-05](docs/experiments/E04-ruling.md) | 36.89 / 6.87 / 56.24 |
| **Dragon** | 獣、翼膜 | [2026-08-07](docs/experiments/E12-ruling.md) | 44.15 / 3.07 / 52.78 |
| **Longsword** | 小道具、ほぼ2D、グレーのグラデーション | [2026-08-08](docs/experiments/E14-ruling.md) | 45.25 / 2.07 / 52.68 |

共有されるのは有効なテクセルであり、**それらは被験者間で比較できません。** 船はほとんどを目の高さから隠し、動物はその半分を隠します。それぞれを独自の事前に登録された範囲の上限と比較して評価すると、**86〜93％** になります。行間の違いはジオメトリであり、回帰ではありません。[完全な数値と分母](docs/handbook/subjects.md)。

**これはパイプラインであり、1つのキャラクターを生成するものではありません。** 8つの名前付き要素で仕様に矛盾させると、プロンプトが **8回中8回勝利します。** 中央値ΔEは46.3となり、5つの制御対象では6.2でした。ただし、図は同じ人物です。構造はメッシュと制御によって保持され、名前付き属性はプロンプトに依存します。

## パイプライン

```
  styled 2D concept ╌╌► clay prep ╌╌╮   ← CANDIDATE hop, walked once. Not a route
                                    ╎     stage. Everything below it is the route.
                                    ▼
form-exaggerated clay concept ──► image-to-3D ──► weld ──► density allocation
                                                             │
                    cull what no camera can see ◄────────────┘
                                 │
                                 ▼
       twins, generated from THIS mesh ──► project ──► brush the holes ──► fill
```

段階ごとに、各段階の理由を説明します：**[ハンドブック](docs/handbook/index.md)**。

**破線で描かれたホップは新しく、意図的に実線ではありません。** ルートの最初のボックスには常に「粘土コンセプト」と表示されており、これまでここから何も生成されていませんでした。すべての粘土は手作業で運ばれ、その過程で加工されていました。現在では、「コンセプト→粘土」ツールが存在し、その最初のペアが実際のサイズで作成されました：ポーズ、リストバンド、ベルトのメダリオン、そして破れた裾がすべて再現されています。たてがみは再現されていません。色の滲みがフレーム全体で測定され、**C\* p99.9 = 13.15**となり、シームレスな無彩色背景となっています。**このペアでは、メッシュがより良く改善されるかどうかを示すことはできません。** これは、この技術を推進する唯一の要素であり、そのため、その証拠は記録され、引き続き候補として残ります：**[コンセプト準備](docs/concept-prep.md)**。

## どのように機能するか

それぞれ実験が必要で、かつ、それを生み出した対象を超えて一般化できる6つの発見。[詳細な説明と測定値は](docs/findings.md)にあります。

- **まず形状を決定し、次にスタイルを適用します。** 再構築ツールは、表面のノイズをジオメトリとして解釈します。意図的に誇張された平面を持つ、滑らかで彫刻のような粘土は、様式化されたスプライトよりも優れたトポロジーで再現されます。様式化されたもう一方のモデルは、同時に生成され、色の参照として使用されます。
- **顔をフレームに収め、顔を作成します。** バストクロップを使用すると、頭部のポリゴン数が**3.1〜4.5倍**増加し、その違いは構造的です。分離されたまぶた、眉間の溝、モデル化された鼻腔などであり、単なるぼかしの軽減ではありません。
- **ツインはキャラクターではなく、メッシュに属します。** ツインを複数のメッシュで使用すると、カバレッジが**62% → 22.7%**に低下します。これは、腕がモデルの横にある空中に投影されるためです。テクスチャを適用する予定のメッシュから、毎回ツインを生成します。
- **アイデンティティはプロンプトに属します。** プロンプトで指定されていないカノン要素が偶然生成され、同じ方法で消えます。これは、金色の膝当てが、壊れたControlNet内のノイズを通してのみ画像に表示される場合に測定されます。
- **しきい値ではなく、ジオメトリを尋ねます。** キー付きマスクを正確なレイキャストシルエットに置き換えると、有効なテクセルにおける参照カバレッジが**28.4% → 39.1%**に増加します。これは厳密に追加であり、拡散やGPUは使用しません。コーナー中央キーイングはここで3回失敗しており、廃止されました。
- **カメラで見ることができないものをアトラスから削除し、メッシュからは決して削除しないでください。** アトラスのテクセルの49%は見えません。これらの面を除外すると、補間が68%削減されます。削除するのではなく、除外することで、検出できるだけでなく、失敗を不可能にします。

## 解決されていない問題

名前と測定値は、本文ではなく、脚注に記載されています。[すべてはコード内にあります](docs/known-defects.md)。

- **一部の可視表面マップがアトラス空間にマッピングされますが、ベイク処理では書き込まれません。** そのため、画像には変更されていないデフォルトの黒としてレンダリングされます。Blenderのベーカーはテクセル中心サンプリングを使用するため、どのテクセル中心にも重なっていない三角形は空欄になります。開発者自身も[このメカニズムを特定し、修正をマージしました](https://projects.blender.org/blender/blender/pulls/161752)。これは、ここで測定されたすべての数値が使用されたビルドから2週間後に実行されました。これは、単一の対象ではなく、ルート自体の特性です。1つのアセットで測定され、**他の4つでは測定されていません。**
- **ブレードバンドは、8つのカメラすべてにおいて、ステージ1の参照の0.00%を占めます。** 鋼鉄が灰色の背景に配置されている場合、正確にしきい値上に位置します。ユニオンによって55.72%が救済されます。
- **ストロークの継ぎ目は均一ではありません。** プロベナンス境界は、通常のテクスチャバリエーションの**5.5倍**になります。ディレクターが指定した領域は、**9.5倍**になります。
- **拡散によって、関連性のないアトラスアイランド間で色が滲みます。** 拡散されたテクセルの74.9%は、高さ1.0の図で平均0.177離れた別の島から色を取得します。⚠ **この割合はアトラスのテクセルであり、カメラが見ているものに関する主張ではありません。** 拡散は、書き込まれたアトラスの26.95%であり、**レンダリングされた図のピクセルの4.95%**です。その比率は0.18倍です。ペイントは大きなチャートに存在し、穴は小さなものに存在するため、拡散されたテクセルは画面空間では安価です。
- **⚑ 合格を決定する欠陥は、塗りつぶしではなく、ペイントによって引き起こされます。** これは、スペクル統計では検出できない別のマテリアルの色を帯びている領域です。3つの方法で、3つのセッションで、3つの空間で測定されました：**91.05% `reference`が0.99倍のエンリッチメントで表示され、** 基本レートとほぼ同じです。同じクラスの布地の緑色は**68.46% `reference`**であり、薄いブレードでは、表面自体のペイントされたテクセルは**18.77%**が汚染されており、拡散塗りつぶしの**5.55%**と比較されます。塗りつぶしは、最も近いペイントされた隣接要素から正しくソースを取得します。そして、その隣接要素はすでに間違っています。ブレンド自体は、ドキュメント化されていない2バンド分割であり、（`M + gaussian_blur_σ16(B − M)`）同じポイントで4つの代替案のうちの**最悪のもの**を測定します。
- **ビューは決して独立していないため、すべてのブレンディング修正に制限が加わります。** 各欠陥ブロックについて、**2つ以上のカメラから貢献している面の100%において、それらのすべてが90°以内にあります**（中央値45°）、そして、欠陥のある面の21%は、1つのカメラでのみ表示されます。ほぼ同一の制御下にある隣接するビューが同時に失敗するため、フォトグラメトリで公開されているマルチビューの利点は、そのまま転送されません。
- **このルート上のすべての再構築は、中空の二重壁シェルであり、壁は約2ボクセルです。** ボリューメトリックな前提条件は、そのうちの1つに対して有効ではありません。

## このリポジトリがどのように実行されるか

この分野における規律は、パイプラインと同様に重要な成果であり、それには理由があります：以前の一連の実験では、10回のセッションが行われ、各セッションで独自の出力を評価し、次のセッションで確立された事実として読まれる結論を記述しました。そのループ内のものは何も検証できませんでした。

- **作業前に仕様を定め、作業後に報告し、最後に判断を下す** — そして実験を設計するセッションは、決して自身の結果を評価することはありません。40件の実験が[記録](docs/experiments/)にあります。
- **修正は、それを覆した測定の横に配置されます**。静かな削除としてではなく。最初のセッションだけで6つの既存の主張が虚偽であることが判明し、そのすべては現在も、それらに取って代わるものと一緒に閲覧できます。
- **失敗は、その理由とともにリポジトリに残ります**。[`tools/superseded/`](docs/tools.md) はアーカイブではありません。誰でもこれらのツールを実行して、同じように失敗する様子を観察できます。
- **否定的な結果は完全な成功です**。数値に調整するのではなく、報告され、完了します。
- **テストは、コードに触れるコミットと連携します** — 2つの担当者によって1166件が合格し、1121件の隔離されたものに対してパスベースのCIが実行されます。
- **記録は検索可能です**。4つの要素で検証された、すべての履歴に対するSQLite + FTS5インデックスがあります。これにより、3つの場所で文章が間違っていた判断回数を、記録自体を数えることで特定しました。

## ライセンスの位置

すべての段階はローカルで実行され、商用利用も可能です：SDXL（OpenRAIL++）、MV-Adapter（オープン）、open3d（Apache-2.0）、spandrel（MIT）、RealESRGAN anime6B（BSD-3）、Blender、numpy、scipy、trimesh。

意図的に除外され、その理由も記載：**nvdiffrast**（非商用 — ここでは構造的なトリップワイヤーによって強制されており、認証によるものではありません）、**Hunyuan3D-Paint**（EU、英国、および韓国でのライセンスが無効）、**MVPaint**と**TEXGen**（ライセンスが全くない）、および**UltraSharp / SUPIR / StableSR**（非商用のアップスケーラー）。

**主張の境界は明示されており、発見されるのを待つものではありません。** これは[記録されたルート]を記述します — 上記の図の段階から、画像から3Dへの変換まで。それよりも上流にある候補となる粘土準備ホップは、現在、このリポジトリがまだ検証していない条件を持つクローズドクラウドAPIで実行されているため、ここにあるライセンスの主張は、その粘土から作成されたアセットをカバーするものではありません。これは解決すべき問題であり、解決への明確なパスがあります：ライセンスに準拠したローカルモデルは**Qwen-Image-Edit（Apache-2.0）**です。また、**FLUX.1-Kontext [dev]も、nvdiffrastと同じ理由で除外されています** — 非商用の重み。どちらもスタジオのモデルカタログに対して検証されており、再利用されたものではありません。その理由は[コンセプト準備](docs/concept-prep.md)にあります。

## 信頼と脅威モデル

facetは完全に自分のマシン上で実行されます — すべてのツールは、パスを入力して実行するスクリプトであり、したがって重要な質問は、「このアプリは何の権限を要求しますか？」ではなく、「これらのスクリプトはあなたのマシンに何をするのか？」です。測定によって回答され、すべてのスイープは再実行可能です。完全なポリシーは[SECURITY.md](SECURITY.md)にあります：

- **アクセスされるデータ:** ローカルディスク上のメッシュ、テクスチャ、画像、およびJSON。コマンドラインで渡すパスにあります。さらに`docs/index/facet.db`があり、これは*派生したもの*です — これはすでにこのリポジトリにあるファイルではなく、また`facet_index.py build`はそれを最初から再生成します。
- **アクセスされないデータ:** 認証情報は一切ありません。ここではトークン、キー、またはパスワードを読み取ったり、保存したり、送信したりするものはなく、ツリーにも存在しません — プロバイダーのプレフィックスが付いたキー、GitHub PAT、Slackトークン、AWSキーID、秘密鍵ブロック、ベアラー・トークン、およびインラインの`api_key`/`password`割り当てに対してスキャンされました。**一致するものはありません**。認証情報のようなファイルも追跡されていません。
- **テレメトリはありません。** 収集も送信もしません。オプトアウトするものがないため、オプトアウトのオプションもありません。
- **ネットワークからのデータ送信:** 36個のうち2つのツールがソケットを開きます — `restylize_views.py`と`texpass_brush.py` — そしてどちらもComfyUI HTTP API（`--host`）に接続します。**デフォルトは`127.0.0.1:8188`です**。それ以外の`tools/`は、ネットワーク呼び出しを行いません。
- **権限:** 通常のユーザー。昇格、サービスインストール、システム設定またはレジストリへの書き込みはありません。

Three sharp edges are disclosed rather than claimed away, because a security note that
only lists reassurances is not a threat model: **file operations are not sandboxed**
(a tool writes wherever its arguments say); **absolute local paths are baked into many
tools and docs** — 114 occurrences across 26 files, not secrets but a disclosure of one
machine's layout, and the reason most tools will not run unmodified elsewhere; and
**unexpected failures surface as Python tracebacks in the 36 unpublished research
scripts**, with no `--debug` gate. Deliberate halts are `ANDON:` messages carrying the
measurement that fired them. That is the research-instrument contract, and
[SHIP_GATE.md](SHIP_GATE.md) records exactly when it stops being good enough — which for
the two commands facet *installs* it did, at 0.2.0: `facet-index` and `facet-mcp` return
`0` ok / `1` user error / `2` runtime error — and, since
[E22](docs/experiments/E22-ruling.md), **`4` REFUSED** for a fired gate or a failing
`verify` leg, which is the tool working and telling you not to proceed rather than a
runtime error. All of them refuse with a structured failure naming the next step rather
than a traceback ([E21](docs/experiments/E21-cli-contract-report.md)).

**そして、それらの２つのコマンドにあるゲートは、もはや削除できません。** どの側面でも、`raise`がインストールされます。単純な`assert`は、環境変数によって静かに削除されるステートメント`python -O`です。このリポジトリの87個のゲートは、E22で変更されるまで、環境変数によって削除できました。同じゲートに対して、４つのインタープリターモードで、変更前と変更後の測定が行われました。
**そして、[E23](docs/experiments/E23-route-gates-report.md)以降、４つの承認されたアセットを生成したルートにあるゲートも削除できません**—その**12個のツールにわたる57個のサイト**は、テストが一度も実行されていないファイルに対して純粋な移動として変換され、それぞれが`-O`と`PYTHONOPTIMIZE=1`だけでなく、通常のインタープリターでも拒否されるようになりました。
**そして、[E25](docs/experiments/E25-ruling.md)以降、クラスは閉じられました。** その**43個のファイルにわたる133個のサイト**—上記４つの承認されたアセットのエビデンスを生成した測定ツール—は同じように変換され、合計で`raise`が**278**になります。
正確には**１つ**だけ、どこかの`tools/`の下にある単純なANDON `assert`が残っています：
`superseded/texpass_thin_mask.py`であり、これは**決して**変換されません。なぜなら、これらのツールは誰でも実行して、同じように失敗する様子を見ることができるように維持されているからです。この残りの部分は、テストスイートで**名前**によって固定されており、将来のクリーンアップ操作で、意図的にテストを編集しない限り、削除することはできません。

**サポート状況：** このリポジトリはオープンな環境で開発され、１つのハードウェア構成で、１人のディレクターと、交代するアドバイザーと実行者のセッションによって行われます。`main`のみがサポートされている状態です。リリースチャンネルはなく、バックポートポリシーもSLAもありません。代わりに存在するものは記録であり、すべての主張はそれを生成するコードの隣に配置され、[docs/experiments](docs/experiments/)には、それぞれの仕様、レポート、および判断が含まれています。

## 要件

Blender 5.x、Python 3.11+と、`numpy`、`scipy`、`trimesh`、`open3d`、`Pillow`、`spandrel`、`torch`が必要です。インペイントブラシを使用するには、ローカルのComfyUIインストールが必要です。RTX 5090で開発されました。生の速度よりもVRAMの余裕が重要です。

CIは、**ubuntu-latest / Python 3.12**上で、固定されたインストール（`.github/workflows/ci.yml`）を使用して、スイートの隔離されたサブセットを実行します。アーティファクト層には、記録されたツリー（`E:\AI\training`）が必要ですが、これはgitには含まれていないため、CIはそれらを意図的に選択しません。ローカルでは、`python -m pytest`がすべての**1166個**のテストを実行し、`python -m pytest -m "not artifacts"`がCIで再現される**1121個**のテストを実行します。

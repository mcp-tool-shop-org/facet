スタイルは、テクスチャ空間内のアセットに適用されます。ビューごとにペイントして後でつなぎ合わせることはありません。形状を強調した粘土のコンセプトをパイプラインに入力すると、そのメッシュのスタイライズされた参照から色を取得したテクスチャ付きメッシュが出力され、参照では見ることができなかった部分は、マスク処理されたインペインティングブラシとサーフェスを認識する拡大によって補完されます。

この問題の2つの側面、つまりポリゴンと、それらが保持する必要がある面を表す名前が付けられています。

## インストール

パイプライン自体は、入力するパスに対して実行する一連のローカルスクリプトです。リポジトリをクローンし、[Getting Started](https://mcp-tool-shop-org.github.io/facet/handbook/getting-started/) を参照してください。

**2つのサーバーがパッケージとして提供されます。** 1つはレコードインデックスで、アシスタントが証拠の追跡を読み込むのではなくクエリできるようにします。もう1つは、**v0.4.0 以降では測定サーバーです。** これにより、数か月かけて測定された2つのアセットは、単一のコードパスを経由します。

```bash
npx @mcptoolshop/facet               # the record index; zero-prerequisite, no Python needed
pip install facet-mcp[measure-full]  # + the measurement tools and their instruments
```

`facet-mcp` は、レコード上の stdio MCP サーバーであり（6つのツールがあり、そのうちの4脚検証は、拒否する健全なサーフェスとして機能します）、`facet-index` はインデックス自体です（`build` / `verify` / `q` / `claims`）。どちらもチェックアウト内から実行してください。`--db` は別のインデックスの名前です。

### 測定サーバー — v0.4.0 で新機能

`facet-measure` は、比較の**数値的な側面**を処理し、出力が良好かどうかは決して示しません。すべてのペイロードには、サーバーバージョン、インストルメント自体のファイルハッシュ、および構成ハッシュが含まれており、`measure_report` は不一致がある場合の比較を**拒否します。** これは、このシステム全体の存在意義です。

**verb** を実行することで検証されます（`--help` ではなく）。コントロールメッシュは、チェックアウトされていないマシン上で786,432個の面と完全なアイデンティティエンベロープを返します。

**結果は1つの要素に依存し、それはPythonのバージョンです。**

| あなたの Python | `[measure-full]` はあなたに与えます |
|---|---|
| **3.11 / 3.12** | **8つのツールすべて** — `open3d` は PyPI からインストールされます |
| **3.13** | 4つのツール。`mesh_stats`、`mesh_topology`、`measure_report`、`anchor_check` |

`open3d` 0.19.0 が最新の*リリース*であり、cp38〜cp312 ホイールを **sdist なし** で公開します。そのため、3.13 では PyPI にインストールできるものがありません。追加機能は、それを `python_version < "3.13"` の背後に配置するため、そこでインストールが**成功** し、4つのジオメトリツールが
**`4` REFUSED** という名前で必要なものを出力します（インストールの全体が失敗するのではなく）。

**Python 3.13 で8つすべてを取得するには、** Open3D は現在の cp313 ホイールをローリング開発チャンネルに公開します。コマンドラインでは直接 URL を使用できます。ただし、これは公開されたパッケージメタデータ内でのみ禁止されています。

```bash
# Linux — stable filename, no build hash
pip install https://github.com/isl-org/Open3D/releases/download/main-devel/open3d-0.19.0-cp313-cp313-manylinux_2_35_x86_64.whl
```

⚠ **Windows および macOS では、開発ホイールのファイル拡張子は `+<sha>` です**（執筆時点では `open3d-0.19.0+63e30be-cp313-cp313-win_amd64.whl` であり）、名前は `main` が移動するにつれて移動します。 [`main-devel` リリース](https://github.com/isl-org/Open3D/releases/tag/main-devel) にあるアセットをリストし、現在のものを選択してください。 **このパイプライン自体の Open3D に依存する数値は、このビルドに対して測定されました。** これは、比較の境界線です。アイデンティティエンベロープには、インストルメントのハッシュが記録され、その依存関係は記録されません。[E31](docs/experiments/E31-ruling.md)。

*v0.3.1 までのホイールには2つの `.py` ファイルが含まれており、測定インストルメントは含まれていません。そのため、インストールされた測定サーバーは実行するものがありませんでした。誰も4回のリリースにわたってそれに気づきませんでした。これは、このリポジトリがチェックアウト自体であるためです。ツールは、ビルドされた場所で機能し、他の場所に存在したことはありません。*

⚠ **`pip install facet-mcp` は、v0.3.0 までのすべてのリリースバージョンで破損しており、v0.3.1 で修正されています。** ホイールは `facet_index` をトップレベルのモジュールとしてインストールするため、v0.3.0 およびそれ以前では、レコードの位置を `<venv>/Lib` に対して解決します（これにはコーパスもインデックスも含まれていません）。また、`build`、`claims`、および `q` は `--db` なしで失敗します。
**v0.3.0 またはそれ以前のバージョンを使用する場合は、上記の `npx` バイナリを使用してください。**

v0.3.1 以降では、ルートはそれを前提とするのではなく、**レコードをテストすることで解決されます。** チェックアウト内からどちらかのコマンドを実行すると、見つかります。他の場所から実行すると、**`4` REFUSED** と出力され、試した両方のディレクトリと検索した両方のマーカーの名前が表示されます。 `$FACET_INDEX_DB` は現在、両方のコマンドによって読み取られ、どの*インデックス*を使用するかを選択します（*コーパス*は選択しません）。 `main` からビルドされ、クリーンな venv にインストールされたホイールで測定されました。[E24](docs/experiments/E24-ruling.md)。

*このブロックは2回修正されました。最初に `pipx install facet-mcp # または Python パッケージを直接`, until v0.3.0's read-back ran a **verb** instead of `--help` と記述されていました。次に、ホイールは「 `q` および `claims` でのみ機能する」と記述されていましたが、**`claims` も機能しませんでした。** これは、E24 が実行して確認したものです。両方の修正は、[known-defects.md](docs/known-defects.md) に測定値とともに記載されています。*

## 現状

**4つの承認されたアセットを、4つの被験者クラスにわたって、クレジット0で提供します。** 各アセットは、ディレクターが独自のズームレベルで評価しました（GLB またはフルサイズのシート）。メトリックがしきい値を超えたわけではありません。

| 被験者 | クラス | 承認済み | 参照 / ブラシ / 拡大 |
|---|---|---|---|
| **Character (W3)** | ヒューマノイド | [2026-08-04](docs/experiments/E08-ruling-gate0.md) | 68.8 / 4.2 / 27.0 |
| **Galleon** | 車両、細いリギング | [2026-08-05](docs/experiments/E04-ruling.md) | 36.89 / 6.87 / 56.24 |
| **Dragon** | 獣、翼膜 | [2026-08-07](docs/experiments/E12-ruling.md) | 44.15 / 3.07 / 52.78 |
| **Longsword** | 小道具、ほぼ2D、グレーのグラデーション | [2026-08-08](docs/experiments/E14-ruling.md) | 45.25 / 2.07 / 52.68 |

共有されるのは有効なテクセルであり、**それらは被験者間で比較できません。** 船はほとんど自分自身を目の高さから隠し、動物は半分を隠します。各アセットを、事前に登録されたリーチ上限と比較して評価すると、**86〜93%** になります。行間の違いはジオメトリであり、回帰ではありません。[完全な数値と分母](docs/handbook/subjects.md)。

**これはパイプラインであり、1つのキャラクターを生成するものではありません。** 8つの名前付き要素で仕様に矛盾させると、プロンプトが **8/8** で勝利します。中央値 ΔE は 46.3 であり、5つの保持されたコントロールでは 6.2 です。ただし、図は同じ人物です。構造はメッシュと制御によって維持され、名前付き属性はプロンプトに依存します。

**プロジェクターに関する議論は2026年8月16日に終了しました**（[E45](docs/experiments/E45-warp-and-aov-kickoff.md)–[E49](docs/experiments/E49-finish-and-cap-kickoff.md））。
8つのプレートは、以下の方法で再構築されたものです。各視点からのバンドルを、境界×向き×可視性重みを使用して再構築し、アトラスを作成します。これにより、ディレクターが「正直言ってかなり良くなった」と評価し、「素晴らしい出来栄えだ」と判断しました。これは、以前のバージョンで問題があったアトラスと比較したものです。その原因となった一連の流れは、`tools/`（`emit_view_aovs`、`s3_composite`、`flow_estimate`、`s3_run`、`s3_sheet`、`atlas_from_aovs`、`twin_mesh_warp`）にあります。そのうちの7つのプレートは、外部チャンネルによって作成されました。このチャンネルが主張するキャリブレーションの精度は、「10回試して10回成功」しており、それぞれここで検証された後で信頼できるようになりました。残りの要素は以下に示されており、隠されていません。調査中のフィルパスポリゴンクラス、まだ見たことのないサーフェス（ポリシーを待機中）、そしてディレクターが最も重要だと述べた標準的なビルドです。

## ルート

```
  styled 2D concept ╌╌► clay prep ╌╌╮   ← CANDIDATE hop, walked once. Not a route
                                    ╎     stage. Everything below it is the route.
                                    ▼
form-exaggerated clay concept ──► image-to-3D ──► weld ──► density allocation
                                                             │
                    cull what no camera can see ◄────────────┘
                                 │
                                 ▼
       twins, generated from THIS mesh ──► project ──► brush the holes ──► fill
```

段階ごとに、その理由とともに説明します：**[ハンドブック](docs/handbook/index.md)**。

**点線で描かれた経路は新しく、意図的に実線ではありません。** ルートの最初のボックスには常に「粘土コンセプト」と表示されており、これまでここから何も生成されていませんでした。すべての粘土は手作業で作成され、その過程で加工されました。現在、コンセプト→粘土ツールが存在し、最初のペアがフルサイズでテストされています：ポーズ、リストラップ、ベルトメダリオン、破れた裾などが再現されています。髪の毛の表現は再現されていません。カラーリークは、フレーム全体で**C\* p99.9 = 13.15**と測定され、シームレスな非彩色の背景が使用されています。**このペアでは、メッシュがより良く再構築されるかどうかを示すことはできません。** これは、このツールを評価する唯一の基準であり、そのため、その証拠は記録されたまま、引き続き候補として残ります：**[コンセプト準備](docs/concept-prep.md)**。

## どのように機能するか

6つの発見事項があり、それぞれが実験によって検証され、また、それらを生成した対象を超えて一般化されます。[詳細な説明と測定値は](docs/findings.md)にあります。

- **まず形状を定義し、次にスタイルを適用します。** 再構築ツールは、サーフェスのノイズをジオメトリとして解釈します。意図的に誇張された平面を持つ、滑らかな彫刻のような粘土を使用すると、より優れたトポロジーで再構築されます。スタイライズされたスプライトよりも優れています。スタイライズされたバージョンは並行して生成され、カラーの参照として使用されます。
- **顔をフレームに収め、顔を作成します。** バストクロップを行うと、頭部のポリゴン数が**3.1〜4.5倍**増加し、その違いは構造的です。分離されたまぶた、眉間の皺、モデル化された鼻腔などがあります。これは単なるぼかしの改善ではありません。
- **ツインはキャラクターではなく、メッシュに属します。** ツインを複数のメッシュで使用すると、カバレッジが**62%から22.7%**に低下します。これは、腕がモデルの横にある空中に投影されるためです。テクスチャを適用する予定のメッシュから毎回ツインを生成してください。
- **アイデンティティはプロンプトに依存します。** プロンプトで指定されていない標準的な要素が偶然生成され、同じように消える可能性があります。これは、金色の膝当てが、壊れたControlNet内のノイズを通してのみ画像に表示されることが判明したときに測定されました。
- **閾値ではなく、ジオメトリを要求します。** キー化されたマスクを正確なレイキャストシルエットに置き換えると、有効なテクセルにおける参照カバレッジが**28.4%から39.1%**に増加しました。これは厳密に追加であり、拡散やGPUは使用していません。コーナーメディアンキーイングはここで3回失敗しており、廃止されました。
- **カメラで見ることができないものをアトラスとメッシュの両方から削除します。** アトラスのテクセルの49%が外部からは見えません。これらの面を除外すると、補間が68%削減されます。削除するのではなく、除外することで、単に検出できるだけでなく、失敗を不可能にします。

## 解決されていない問題

名前と測定値は、本文中に記載されています（脚注ではありません）。[すべてはコード内にあります](docs/known-defects.md)。

- **一部の表示されるサーフェスマップは、ベイク処理で書き込まれないアトラス空間にマッピングされ**、画像に影響を与えないデフォルトの黒としてレンダリングされます。Blender のベーカーはテクセル中心サンプリングを使用するため、どのテクセル中心にも重なっていない三角形は空のままになります。開発者はこの仕組みに名前を付け、ビルドから 2 週間後に修正をマージしました (https://projects.blender.org/blender/blender/pulls/161752)。これは単一のオブジェクトではなく、ルートの特性です。あるアセットで測定された場合、**他の 4 つのアセットでは測定されません**。
- **ブレードバンドは、すべての 8 台のカメラでステージ 1 の参照の 0.00% を占めます**。グレーの背景に配置された金属が、キーの色域のしきい値と正確に一致します。この組み合わせにより、55.72% が補正されます。
- **ストロークの継ぎ目は滑らかではありません**。起源境界は、通常のテクスチャの変化よりも **5.5 倍** 大きく変化します。ディレクターが指定した領域は、**9.5 倍** の変化を示します。
- **拡散により、関連性のないアトラスアイランド間で色が混ざります**。拡散されたテクセルの 74.9% は、高さ 1.0 の図で平均 0.177 だけ離れた別の島から色を取得します。⚠ **この割合はアトラスのテクセルに関するものであり、カメラが見ているものについての主張ではありません**。拡散は、書き込まれたアトラス全体の 26.95% を占め、**レンダリングされた図のピクセルの 4.95%** であり、その比率は 0.18 です。ペイントは大きなチャートに存在し、穴は小さなものに存在するため、拡散されたテクセルは画面空間では安価です。
- **⚑ 合格を決定する欠陥は、塗りつぶしではなく、ペイントによって引き起こされます**。他のマテリアルの色を表示している領域で、どのスプークル統計もそれを検出できません。3 つのスペースで 3 回のセッションで 3 つの方法で測定されました。**91.05% `reference` が 0.99 倍のエンリッチメントで表示され**、基本レートとほぼ一致します。同じクラスの布地の緑色は **68.46% `reference`** であり、薄いブレードでは、サーフェスのペイントされたテクセルが **18.77%** で汚染されており、拡散塗りつぶしの **5.55%** と比較されます。塗りつぶしは、最も近いペイントされた隣接要素から正しくソースを取得します。そして、その隣接要素はすでに間違っています。ブレンド自体は、ドキュメント化されていない 2 つのバンドに分割された処理です (`M + gaussian_blur_σ16(B − M)`)。これは、同じポイントで **4 つの代替案のうち最悪のもの** を測定します。
- **各ビューは独立していないため、すべてのブレンディング修正が制限されます**。各欠陥の塊について、**2 つ以上のカメラから寄与している面の 100% は、すべて 90° の範囲内にあります** (中央値は 45°)。欠陥のある面の 21% は、1 つのカメラでのみ表示されます。ほぼ同一の制御下にある隣接するビューが同時に失敗するため、フォトグラメトリで公開されているマルチビューによる利点は、そのまま転送されません。
- **このルート上のすべての再構築は、中空の二重壁シェルであり、壁は約 2 ボクセルです**。単一のボクセルに対して有効な体積述語はありません。
- **プレートは、名前のないマテリアル境界で異なり、その中心となるのはカノンです (2026-08-16)**。内側のメッシュへのワープは、すべての 8 つのビューでシルエットの中央値が 1.2〜3.0 であるのに対し、**3.5〜11.1 ピクセルの中央値** で測定されました。ディレクターが円で囲んだすべての残存領域 (袖口、手、ブーツの上部) は、生成プロンプトに名前が記載されていないマテリアル接合部です (記録されたプロンプトには 6 つの要素が含まれており、グリップ、ガントレット、グリーブ、および手が **0 回** 表示されます)。彼の診断は記録に残っています。「私たちはカノンを適切に構築しませんでした」。W3 カノンのビルドアウトとカノンに基づいたツイン再生成は、段階的な修正です ([E49 のディスパッチレコード](docs/experiments/E49-finish-and-cap-kickoff.md))。
- **有効なテクセルの 4.65〜5.57% は、フラットリングカメラでは表示されないサーフェスです**。これらはすべてのビューで深度ゲートに失敗し、どの投影ルートでもペイントできず、出荷されたパイプラインは、暗いマークを作成した島を無視する塗りつぶし処理でこれらのテクセルを補正しました。修正ではなく、ポリシー (中立的なマテリアル、ブラシ、または受け入れ) が必要です ([E49 レポート](docs/experiments/E49-finish-and-cap-report.md))。
- **完全な候補の塗りつぶしパスは、平坦な色のポリゴンをレンダリングします**。これは、ディレクターが承認されたグレードシートで言及した唯一のオープンクラスです (*「素晴らしいですが、色付きの多角形の形状があります」*)。テスト中の仮説であり、起源マスクはすでにタグ付けされています。孤立した島は単一の三角形のサイズであり、境界に隣接するツインサンプルから平坦に塗りつぶされ、侵食されていないシルエットが使用されます。

## このリポジトリはどのように運用されているか

この分野における知識や技術は、パイプラインと同様に、ある目的のために存在し、その過程で生み出されるものでもある。以前の段階では、10回のセッションを通じて各自が自分の成果を評価し、次のセッションでそれを事実として共有するというプロセスが行われた。しかし、その一連の流れの中で検証可能な点は何もなかった。

- **作業前に仕様を決定し、作業後に報告を行い、最後に結論を出す** — そして、実験を設計するセッションは、決して自身の結果を評価することはありません。44件の実験が[記録](docs/experiments/)にあります。
- **修正は、それを覆した測定値の横に配置され、静かに削除されることはありません。** 最初のセッションだけで6つの既存の主張が誤りであることが判明し、そのすべては現在も、それらに取って代わるものと一緒に閲覧できます。
- **失敗は、その理由とともにリポジトリに残ります。** [`tools/superseded/`](docs/tools.md) はアーカイブではありません。誰でもこれらのツールを実行して、同じように失敗する様子を観察できます。
- **否定的な結果も完全な成功です。** 特定の数値に近づけるのではなく、報告され、完了として扱われます。
- **テストは、コードを変更したコミットと紐付けられます。** 2人の担当者によって1182件が合格し、そのうち1135件についてはパス制限付きのCIが適用されています。
- **記録は検索可能です。** 全ての履歴に対してSQLite + FTS5インデックスが作成され、4つの異なる場所で検証されました。これにより、文章に誤りがあった3つの場所で、記録自体を数えることで結論の数を特定することができました。

## ライセンスに関する状況

すべての段階はローカルで実行され、商用利用においても問題ありません：SDXL（OpenRAIL++）、MV-Adapter（オープンソース）、open3d（Apache-2.0）、spandrel（MIT）、RealESRGAN anime6B（BSD-3）、Blender、numpy、scipy、trimesh。

意図的に除外されており、その理由は次のとおりです：**nvdiffrast**（非商用 — ここでは構造的なトリップワイヤーによって強制され、アテステーションによるものではありません）、**Hunyuan3D-Paint**（EU、英国、および韓国ではライセンスが無効）、**MVPaint**および**TEXGen**（ライセンスが一切存在しない）、および**UltraSharp / SUPIR / StableSR**（非商用のアップスケーラー）。

**主張の範囲。発見されるのを待つのではなく、明示的に記述されています。** これは、上記の図における段階から画像から3Dへの変換へと続く、**記録された経路**を説明しています。その上流にある候補となるクレイ準備ステップは現在、このリポジトリが**検証していない**条件を持つクローズドクラウドAPIで実行されているため、ここでのライセンスに関する主張は、そのクレイから作成されたアセットには適用されません。これは未解決の問題であり、解決への明確な経路があります：ライセンスに準拠したローカルモデルは**Qwen-Image-Edit（Apache-2.0）**であり、**FLUX.1-Kontext [dev] は nvdiffrast と同様の理由で除外されています** — 非商用の重み。これらはすべて、スタジオのモデルカタログと比較して検証されており、その理由は[コンセプト準備](docs/concept-prep.md)に記載されています。

## 信頼と脅威モデル

facetは完全にローカルマシン上で実行されます — すべてのツールは、コマンドラインで入力するパスに対して呼び出すスクリプトです。したがって、重要な質問は、「このアプリがどのような権限を要求するか」ではなく、「これらのスクリプトがあなたのマシンに何をするか」ということです。測定によって回答され、すべてのスイープは再実行可能です。完全なポリシーは[SECURITY.md](SECURITY.md)に記載されています：

- **アクセスされるデータ:** ローカルディスク上のメッシュ、テクスチャ、画像、およびJSONファイル。コマンドラインで渡すパスにあります。さらに、`docs/index/facet.db`も含まれますが、これは*派生したもの*です — このリポジトリ内の既存のファイル以外のものは含まれておらず、`facet_index.py build`によって最初から再生成されます。
- **アクセスされないデータ:** 認証情報は一切使用されません。トークン、キー、またはパスワードを読み取ったり、保存したり、送信したりするものはなく、ツリー内にも存在しません — プロバイダーのプレフィックスが付いたキー、GitHub PAT、Slackトークン、AWSキーID、秘密鍵ブロック、ベアラー・トークン、およびインラインの`api_key`/`password`割り当てについてスキャンされましたが、**一致するものはありません**。認証情報のようなファイルも追跡されていません。
- **テレメトリーは行われません。** 収集も送信もしません。オプトアウトするものが何もないため、オプトアウト機能もありません。
- **ネットワークからのデータ送信:** 36個のツールのうち2つがソケットを開きます — `restylize_views.py`と`texpass_brush.py` — そしてどちらもComfyUI HTTP API（`--host`）を呼び出します。**デフォルトは`127.0.0.1:8188`です**。その他のツール（`tools/`）はネットワーク接続を行いません。
- **権限:** 通常のユーザー。昇格、サービスインストール、システム設定またはレジストリへの書き込みはありません。

Three sharp edges are disclosed rather than claimed away, because a security note that
only lists reassurances is not a threat model: **file operations are not sandboxed**
(a tool writes wherever its arguments say); **absolute local paths are baked into many
tools and docs** — 114 occurrences across 26 files, not secrets but a disclosure of one
machine's layout, and the reason most tools will not run unmodified elsewhere; and
**unexpected failures surface as Python tracebacks in the 36 unpublished research
scripts**, with no `--debug` gate. Deliberate halts are `ANDON:` messages carrying the
measurement that fired them. That is the research-instrument contract, and
[SHIP_GATE.md](SHIP_GATE.md) records exactly when it stops being good enough — which for
the two commands facet *installs* it did, at 0.2.0: `facet-index` and `facet-mcp` return
`0` ok / `1` user error / `2` runtime error — and, since
[E22](docs/experiments/E22-ruling.md), **`4` REFUSED** for a fired gate or a failing
`verify` leg, which is the tool working and telling you not to proceed rather than a
runtime error. All of them refuse with a structured failure naming the next step rather
than a traceback ([E21](docs/experiments/E21-cli-contract-report.md)).

**そして、これらの2つのコマンドにあるゲートはもはや削除できません。** facetがインストールするすべてのANDONは、`raise`に変換されます。単なる`assert`は、環境変数が静かに削除するステートメント`python -O`です。このリポジトリの87個のゲートは、E22によってそれらに変換されるまで、環境変数で削除できました。同じゲートについて、4つのインタープリターモードで、前と後の状態を測定しました。
**そして、[E23](docs/experiments/E23-route-gates-report.md)以降、受け入れられた4つのアセットを生成した経路にあるゲートも削除できません** — **12個のツールにわたる57個のサイト**が、テストが一度も実行されなかったファイルに対する純粋な移動として変換されました。それぞれは、現在、`-O`と`PYTHONOPTIMIZE=1`だけでなく、通常のインタープリターでも拒否されます。
**そして、[E25](docs/experiments/E25-ruling.md)以降、クラスは閉じられました。** **43個のファイルにわたる133個のサイト** — 上記の4つの受け入れられたアセットに対する証拠を生成した測定ツール — は同じように変換され、合計で`raise`に変換された数は**278**になります。
正確に**1つだけ**の単なるANDON `assert`が、どこかにある`tools/`の下に残っています：
`superseded/texpass_thin_mask.py`は、これらのツールは誰でも実行して、同じように失敗する様子を見ることができるようにするために、**決して変換されません**。この残りはテストスイートで**名前によって固定**されているため、将来のスイープでは、テストを意図的に編集しない限り、それを整理することはできません。

**サポート状況:** このリポジトリは、1つの環境で、1人の責任者と交代制の顧問および実行担当者によってオープンに開発されています。サポートされているのは、`main`の状態のみです。リリースチャンネル、バックポートポリシー、SLAはありません。代わりに、すべての主張がそれを生成するコードの隣に配置され、[docs/experiments](docs/experiments/) には、それぞれの仕様、レポート、および決定が含まれています。

## 要件

Blender 5.x、Python 3.11+ と共に、`numpy`、`scipy`、`trimesh`、`open3d`、`Pillow`、`spandrel`、`torch`が必要です。インペイントブラシを使用するには、ローカルに ComfyUI をインストールする必要があります。RTX 5090 で開発されており、生の速度よりも VRAM の余裕が重要です。

CI は、**ubuntu-latest / Python 3.12** 上で、固定バージョンでインストールされたスイートの密閉されたサブセットを実行します（`.github/workflows/ci.yml`）。成果物層には、`E:\AI\training`の下に記録されたツリーが必要ですが、これらは Git に含まれていないため、CI は意図的にそれらを除外します。ローカルでは、`python -m pytest` が **1182** 個すべてのテストを、そして `python -m pytest -m "not artifacts"` が CI で再現される **1135** 個のテストを実行します。
